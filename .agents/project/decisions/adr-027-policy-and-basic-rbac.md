# ADR-027：Policy 与基本角色权限

- 状态：Accepted（最小 contract 与 PostgreSQL 18 / MySQL 8.4 默认实现已验证；授权路由及 PAT ability 交集通过集成验收）
- 日期：2026-10-26

## 最小 Spec

- 在 `openrust-auth` 复用 `CurrentUser`、`Db`、Plugin 与现有认证表名 resolver，不新增独立授权 crate 或通用规则引擎。
- 提供数据库共享的 `Policy` 服务，用精确权限字符串判断用户授权；未知权限默认拒绝。
- 提供全局角色、权限、用户角色和角色权限关联；租户、资源所有权和业务数据范围仍由应用判断。
- JWT/Session 要求数据库角色授予权限；PAT 必须同时具有同名 token ability 与数据库角色权限。
- 权限检查读取权威数据库，不使用进程缓存；已提交的角色/权限变更从下一次检查起对所有节点生效。
- 通过追加 `AuthPolicyMigration` 建表，不修改既有认证迁移；生成项目 `--auth` 纳入迁移。
- 对 PostgreSQL 16+ 与 MySQL 8.4+ 覆盖 CRUD、默认拒绝、PAT 交集、撤销即时生效和表名映射。
- 不自动保护路由；handler/service 显式调用 `Policy::allows` 或 `Policy::authorize`，拒绝映射为统一 403。

## 背景与证据

ADR-012 已确定 `CurrentUser`、路由认证和 PAT abilities，但没有角色或权限数据模型；现有认证插件只负责确认身份，不能表达基本角色授权。v1 覆盖计划要求 Policy 和基本角色权限。既有 `Db`、插件注册、迁移 runner 与 `CurrentUser` 足以承载最小实现。

## 决策

- 权限名是应用可定义的稳定、不透明字符串，比较采用精确匹配，不支持通配符。
- `Policy` 暴露确保角色、给角色授予权限、为用户分配/撤销角色、检查权限及返回 `Forbidden` 的授权入口。权限检查不隐式创建数据。
- 授权为交集：数据库角色权限是必要条件；PAT 还需要其 token abilities 精确包含该权限。空 PAT abilities 不允许任何 Policy 权限。token ability 不能覆盖数据库撤权。
- 角色与权限写入后不需要缓存失效广播；每次检查查询共享数据库，节点切换不改变结果。数据库不可用时返回后端错误，不降级为允许或默认拒绝。
- 本 ADR 不定义内置管理员、权限命名目录、角色 UI、租户隔离、所有权表达式或策略 DSL。应用负责保护授权管理操作。

## 执行模型与边界

Policy 为显式注入服务，调用方传入 `CurrentUser` 和权限名。授权拒绝使用 `Error::Forbidden`，调用路径通过现有 HTTP 包装返回统一错误。角色分配/撤销及单关联删除为单语句操作；`grant_permission` 在一个数据库事务中确保 permission 并写入关联。重复确保/关联写入在两个后端均幂等。跨节点可见性以数据库事务提交为界。

## 验收

- 单元/双库测试覆盖未知用户/权限默认拒绝、授予与撤销、多个角色并集、PAT ability 交集、SQL 表名前缀映射及数据库故障传播。
- PostgreSQL 与 MySQL 完成真实隔离库验证；生成项目默认启用迁移并可编译/测试。
- 应用示例展示显式 `Policy` 注入与授权调用，不把身份认证本身视为授权。

## 取舍

此实现满足 v1 的通用基本 RBAC，同时保留业务自定义授权规则的空间。每次查询增加一次共享数据库读；当前优先保证跨节点撤权语义。若性能基线显示有必要，再单独设计可失效缓存及其传播契约。
