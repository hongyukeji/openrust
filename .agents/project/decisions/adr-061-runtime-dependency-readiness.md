# ADR-061：运行时依赖就绪探针

> 状态：Accepted
> 日期：2026-10-27

## 背景

`Readiness::is_ready()` 表示 listener 生命周期状态，供协议层控制接流量与优雅停机。它不能发现进程启动后数据库或缓存连接失效；启动时连接成功也不能证明运行期依赖仍健康。依赖错误详情不得出现在公共健康响应中，探测本身也必须有界且只读。

## 决策

- 保留 `Readiness::is_ready()` 的 listener 语义，新增公开异步 `register_probe` 与 `dependencies_ready`。探针名唯一、稳定且最多 64 个；名称限定为 1–96 个小写 ASCII 字母、数字、点、短横线或下划线。
- `/ready` 仅在 listener 可接流量且所有依赖探针成功时返回 200；探针失败、执行超过 2 秒或已有一轮探测时返回 503。没有探针时保持 listener-only 行为。并行探测轮全局最多一轮，每轮最多并发 16 个探针。
- `DatabasePlugin` 为每个具名数据库注册只读探针，检查主库及所有配置只读副本；`CachePlugin` 为每个配置 store 注册只读 `get` 探针。数据库、缓存驱动错误及超时只影响就绪状态，不返回错误细节；探针名受稳定名称规则约束。
- 自定义插件可注册异步探针，必须采用有界、只读检查。探针重复、名称无效或数量超限时，注册失败并阻止应用完成初始化。
- `/health` 继续只表示进程存活。gRPC health 的既有协议 listener 生命周期语义不在本 ADR 中改变；HTTP `/ready` 的依赖聚合不自动覆盖 WebSocket/SSE 连接、跨节点实时投递、任意外部调用或自定义原生 SQL 依赖。

## 影响

- `/ready` 的成功响应结构保持不变；依赖故障时状态码为 503，正文只包含通用 `not_ready` 状态。
- 每个 HTTP `/ready` 请求至多触发一轮并发探测，最多同时运行 16 个探针、整轮最多运行 2 秒；失败日志只记录探针名和稳定错误码。探针需要自行避免昂贵、写入或不可取消的操作。
- 配置数据库实例及缓存 store 都是必需依赖；其中任意一个失效会使 HTTP readiness 失败。应用可通过自定义插件注册其他必需依赖。
- 指标、探针耗时观测与 gRPC/实时协议的依赖健康传播仍属于可观测性与生产资源后续工作。
