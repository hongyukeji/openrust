# ADR-011 第一代短信与邮件通信能力

- 状态：Accepted（第一代需求范围；具体公共 API 与供应商选型待设计，不表示已实现）
- 日期：2026-10-25

## 背景

应用开发常需要邮件与短信，只有注册登录接口而缺少可使用、可测试、可替换供应商的通信能力，不能满足创建项目后直接进入业务开发的目标。短信纳入第一代；邮件保留既定第一代范围。

## 决策

- 在 M3 增加短信能力，与邮件采用独立的公共入口和供应商适配边界，遵循 [ADR-009](adr-009-extensible-capability-drivers.md)。框架内置常用实现，开发者可通过公开契约扩展自己的供应商，无需修改框架。
- 短信提供发送入口、模板标识与参数、供应商错误映射及超时配置；第一代至少有一个真实供应商适配，以及本地开发 log 与测试 fake 实现。供应商与依赖选型需比较实际 API、地区覆盖、维护成本后确定，不预先承诺全部厂商。
- 邮件保留 SMTP、log、fake、纯文本与邮件模板，以及本地 Mailpit 路径。M4 接入队列后，为邮件与短信补充异步发送及失败处理。
- 外部发送实现通过可选依赖或 feature 接入，配置缺失时给出可操作错误；本地开发默认不需要短信账户或产生发送费用。生产环境不得悄悄回退到 log/fake 并报告真实发送成功。
- 明确供应商接受请求与最终送达的区别，不把返回发送请求成功描述为用户已收到。若供应商支持回执，扩展契约需允许适配；第一代是否内置回执端点按具体供应商 contract 决定。
- 超时结果可能不确定；队列重试需说明重复发送风险，按供应商能力使用幂等标识，不承诺恰好一次发送。
- 密钥、验证码与完整消息内容不进入生产日志；收件号码/地址按需要脱敏。log/fake 驱动的内容捕获仅用于明确的本地或测试场景。
- 第一代通信验收包含真实供应商接入证据、本地不付费路径、公共契约测试、错误映射与队列重试边界。真实发送必须具有明确的目标号码/地址及费用授权；没有凭据或授权时记录未完成项，不以 fake 测试代替实发验收。
- “开箱即用”指本地无需购买账户即可运行和测试，生产填写有效凭据与模板配置即可接入；不表示框架能免除供应商账户、模板审核或发送费用。
- 本决策不引入统一通知中心、站内信或推送平台；这些仍在后续版本候选范围。是否需要更高层通知编排，应由实际多渠道需求驱动。

## 需要补充评估的完整使用路径

以下是设计检查项和建议，不视为已确认的新功能交付清单；先复用现有规划，发现缺口后再确定范围。

| 场景 | 需要核对的闭环 |
| --- | --- |
| 注册与账号找回 | 认证、邮件/短信发送、凭据验证、过期与撤销、失败响应是否能完整跑通 |
| 验证码 | 建议提供可复用机制；需设计用途/身份绑定、短有效期、一次消费、并发消费原子性、尝试次数和重发限制；与短信传输职责分离，不默认开启短信登录或修改账号模型 |
| 异步通信 | 模板渲染、队列投递、失败查询、重试和重复发送风险是否有明确行为 |
| 上传与下载 | 核对既有存储能力是否有大小/类型限制、访问授权和可测试示例，不等于新增媒体平台 |
| 外部服务调用 | 评估统一出站 HTTP 超时、错误处理和测试替身是否有必要；非幂等请求不自动重试 |
| 安全与运维 | 核对会话/CSRF、限流、密钥遮蔽、健康/就绪检查和诊断命令，区分已有规划与新增缺口 |
| 扩展开发 | 官方实现和独立第三方适配能否通过相同公开入口注册，并运行契约测试 |

## 影响与执行

- 第一代计划移除“短信不纳入”，M3 增加短信，M4 增加队列化短信；更新 [框架设计](../plans/framework-design.md) 与 [roadmap](../roadmap.md) 保持范围一致。
- 到 M3 前补充能力命名、配置、供应商选型与验收 contract，按 ADR-006 登记公共名称；未选型前不创建空壳 crate、不新增依赖。
- 当前 M2 工作保持独立闭环。代码、生成器、配置示例、测试与 crate 事实在能力实施时同步更新，设计决定不能替代实现证据。
