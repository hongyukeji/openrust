# ADR-035 审计记录与事务边界

- 状态：Accepted
- 日期：2026-10-26

## 背景

v1 要求应用能够记录账号与权限等安全相关变化，并允许应用替换持久化实现。审计记录与请求日志、追踪不同；默认收集完整请求或错误文本会持久化凭据及个人信息。关键业务变更还需要可选择与记录原子提交。

## 决策

- 公共模块为 `openrust::audit`，通过 `AuditPlugin::database()` 注册内置数据库 sink，或 `AuditPlugin::with_sink()` 注册第三方 `AuditSink`。应用显式调用 `Audit::prepare` / `Audit::record`，不自动拦截所有认证或授权方法，不增加平行 Hooks 或事件总线。
- `AuditEvent` 的主体、动作、对象、结果、时间、request ID、可信来源 IP 与显式 details 组成记录。`AuditRecord` 字段私有，只有通过 `AuditPolicy` 的白名单和长度校验后才能创建。密码、令牌、验证码、请求/响应、任意错误和 SQL 文本不得作为 details；敏感名称固定脱敏。
- `AuditSink::append` 的失败向调用者传播，不静默忽略、切换 fake 或自动重试。首版不承诺去重、恰好一次或远程 sink 的持久投递保证。
- 数据库审计迁移由应用 migrator 显式加入，遵循数据库表名解析。`DatabaseAuditSink::record_in_transaction` 只在调用者提供的同一数据库事务插入，不提交、不嵌套。关键业务写入和审计插入均成功后再由外层提交；审计失败使业务事务回滚。事务结束后的失败/拒绝记录另行写入，不能保证数据库不可用时仍持久化。
- 事务外 `Audit::record` 使用主库连接；自定义 sink 不具备数据库原子性。业务提交后记录失败不意味着业务已回滚。
- `purge_before` 只按调用者提供的 cutoff 删除有限批次；不自动清理、不承诺固定法定保留期。v1 不提供公共审计查询 HTTP API，也不宣称记录不可篡改或满足合规认证。

## 影响

- 应用负责选择安全的 details 值、鉴权审计查询/清理入口、配置保留期，并在需要原子审计的流程中共享业务事务。
- 账号/权限示例使用公开数据库事务边界；其他 AuthFlows 不因本 ADR 自动变为全覆盖审计。
- PostgreSQL 与 MySQL 都必须验证迁移、写入、回滚、表名映射和有界清理。
