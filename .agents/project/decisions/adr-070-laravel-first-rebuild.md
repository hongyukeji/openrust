# ADR-070 Laravel 与 laravel-modules 的 Rust 1:1 实现

- 状态：Accepted；1:1 目标与模块化范围已授权，实际实现/验收以源码、Git 与 todo 为准
- 日期：2026-10-28

## 背景

开发者明确要求“Laravel 版的 Rust，一切要原汁原味”，并要求以后“按照 Laravel 的框架功能更新和跟进同步，相当于用 Rust 实现 Laravel Rust 版”。本决策确立最新正式定位“Laravel + laravel-modules = OpenRust”，同时授权全面重构；Goravel 仅提供跨语言实现参考。

## 用户意图与验收原则

- **产品定位**：OpenRust 用 Rust 1:1 实现固定基线 Laravel 框架与 laravel-modules 模块化能力；两者来源分开，使用同一 Container/ServiceProvider 内核，目录或名称近似不足以验收。
- **1:1 定义**：逐项功能、可观察语义、默认值、错误/安全边界、服务容器、register→boot、扩展契约及开发/CLI/生成/测试/部署流程与固定上游对应；Laravel 开发者可直接依官方章节完成 Rust 等价操作，不是 PHP 运行环境或字节兼容。
- **开发体验**：具备 Rust 基础的 Laravel 开发者可以沿用原有框架知识，完成创建应用、业务开发、扩展、测试和部署；学习成本通过实际任务对照验收。
- **持续演进**：本轮重构完成后仍持续跟进 Laravel 的框架功能、行为修复、安全修复和开发体验更新，按版本维护对应关系与差异。
- **保留优秀设计**：遵循 Laravel 的同时，保留并融合 OpenRust 已有的优秀通用机制，例如统一返回格式。增强放在 Laravel 对应职责与公开扩展位置，复用同一内核；不能因上游没有完全相同的内置能力就删除，也不能另建一套平行框架。
- **必要适配**：保留 Rust 类型、所有权、trait、async 和工具能力。偏离 Laravel 必须说明具体约束、替代行为和验收证据；不能仅凭实现困难、个人偏好或笼统“Rust 惯用”降低目标；适用核心能力不能据此标不适用。必要适配记录原行为、确切限制、选定替代与测试，无法等价保持缺口。

## 决策

1. 固定基线 Laravel 的功能、可观察语义、默认行为、工作流与扩展契约是 1:1 验收标准；laravel-modules 的模块创建/注册/资源/依赖/启停/生成/管理能力纳入正式对应矩阵，不缩减为示例目录习惯；Goravel 是跨语言落地参照，其他框架按具体问题参考。允许重构或重写全部架构、目录、公共 API、默认值和实现，无旧接口、旧数据或历史布局兼容义务；具体实现遵守上述必要适配原则。
2. 已验证实现可复用、适配或替换；“已经完成”“Rust 原生命名”“不能重做迁移”不再阻止新设计。保留回归证据，替换后重新验收；不以删除测试减少交付范围。
3. 允许采用 ServiceProvider、Container、Facade、FormRequest、Resource、Model、Factory、Seeder、Mailable、Notification、Gate、Guard、disk 及 `make:model` 等熟悉概念。具体 Rust 签名按功能簇 contract 确定，不做 PHP 语法解释器或全局可变状态模拟。
4. 应用骨架与框架实现分开；默认面向一个业务应用，采用 Laravel 职责目录。根 `src/` 框架布局、`apps/<name>` 唯一生成位置、固定工具包名、响应强制包装、JWT-first 等原约束可被对应新 contract 替代。未迁移模块仍按实际代码说明，不把目标结构写成当前事实。
5. 依赖顺序与完成范围由 [全面重构计划](../plans/laravel-rebuild.md) 统筹；原 M0–M6/DX/F/G 计划作为能力资产与验收输入，不再决定开发顺序。V2 后台仍在新底座完整验收后推进；Vue、uni-app、PC 只规划及独立 AI 产品未启动的边界继续执行。
6. 无兼容义务不等于无保护：已有 WIP、他人进程和验收资料不得覆盖；外部凭据、真实发送目标和发布授权不得推断。工程验证、代码安全、许可证和真实证据要求继续有效。
7. 默认一个功能簇处于实现中。用户授权使用 `gpt-6.1-sol` 子智能体完成已定 contract 的局部实现、测试与文档；固定路径、输入、交付、验证和额度边界。编排方负责跨模块决策与协调；按开发者最新要求直接在 main 开发；同一功能簇可按明确、互不重叠文件范围并行实现，Cargo manifest/lock、迁移、共享文档和提交由一位集成负责人串行协调，并提前分配构建 target 与服务资源。不另建隔离分支/worktree、不递归派发。高风险改码由不同 Provider 或不同模型独立审查。
8. 一般设计取舍由执行 Agent 对照 Laravel、Goravel、Rust 自主决定并记录；外部条件缺失时继续独立工作。无法完成的验收保持明确缺口，不把“全部处理好”解释为可以伪造结果或取消门禁。
9. 每个交付版本固定 Laravel 上游基线，维护功能、行为与差异矩阵。后续变化按[长期上游跟进](../plans/laravel-rebuild.md#长期上游跟进)进入后继交付批次，安全修复优先处理；不使当前验收范围无限漂移，也不将版本对应或计划记录当作已完成同步。
10. 已有增强须在 R0 逐项归入对应 Laravel 职责，记录保留价值、接入方式、差异与回归证据；需要重写实现不等于取消能力。统一返回格式归 HTTP Response / API Resource 与异常渲染，由共同契约处理成功、分页、校验与错误，提供便捷接入和公开定制。具体默认值在 R3 contract 定稿；保留应用选择原生响应的能力，HTML、文件、流与无正文响应遵守自身协议，不强制改成 JSON 或 HTTP 200。其他增强按同样原则评估，避免重复抽象和无实际价值的功能堆积。
11. 禁止以改目录、改名、别名或包裹旧实现代替行为迁移。每簇核对生产调用链与能区分旧、新语义的证据；发现偏离即在所属功能簇纠正，未解决则不关闭受影响条目。过渡实现可按依赖分簇保留，但不得冒充目标已交付；执行闭环见[纠偏规则](../plans/laravel-rebuild.md#执行偏离的纠正)。

## 替代范围

本 ADR 替代以下**目标设计约束**；旧 ADR 中未被替代的行为和验收事实继续作为迁移输入。各功能簇落地时补充领域 ADR，逐项校准事实文档。

| 原 ADR | 被替代或重新开放的部分 |
| --- | --- |
| 001 | 参考顺序、已验证内核不可因体验重写、限制仅做薄整合；成熟组件复用原则仍适用 |
| 006、010、016 | Laravel 术语与冒号 CLI 禁令、Factory/Seeder 禁令、固定前缀与资源动作命名 |
| 007、021、039、062–065 | 固定根框架源码、宿主/生成位置、示例和工具布局、包名/分发形式；真实聚合验收责任保留 |
| 008 | 重开强制响应包装与默认 always_ok；保留统一返回格式作为 HTTP/Resource/异常渲染增强，具体接入与默认值在 R3 定稿，协议正确性保留 |
| 018 | 所有应用 JWT-first；新认证按 web、SPA、API、机器调用场景定义 guard |
| 023 | 原扩展命名、固定应用形态等与本目标冲突部分 |
| 030、068、069 | 配置、根路由和模板目录的固定形式；配置安全与公开/私有资源边界保留 |

其余 ADR 不因本次授权自动声明失效或已实现；执行 Agent 可以在对应功能簇主动替代，须写明新行为与证据。ADR 状态区分“目标被替代”和“代码已迁移”。

## 影响

- 新功能不再被旧术语或布局禁令阻挡；文档入口、技能和模板同时校准。
- 重构计划覆盖完整能力矩阵、Rust 适配、依赖顺序、真实双库/集群验收与生态能力归属。
- 本 ADR 不创建新框架实现、不运行服务、不修改外部环境、不发布。后续实施无需再次请求总体架构授权。

## 对应证据与用户约定

每个稳定矩阵 ID 追溯固定上游源码与测试，再给出 Rust API/配置、等价行为测试、modules/example 实际代码、文档及适用真实服务证据。未盘点、未实现、未实测均保持缺口；旧行为验证不自动成为新 contract 已通过。分类与验收细则以[总计划](../plans/laravel-rebuild.md#逐项对应与差异分类)为唯一维护入口。

用户主动选择的单仓 main、根 Laravel 结构、modules/<模块>、唯一 modules/example 与专属资源内聚、Vue/uni-app、Redis 默认/无静默回退、已撤销专项不恢复，属于用户约定，不能被字面 1:1 覆盖，也不伪称与上游无差异。统一响应等原授权增强继续保留，遵守上游协议与公开配置边界；可见差异透明披露。

Laravel 核心须全量落地，已纳入官方生态按对应可选模块逐项实现；托管商业服务、闭源运营、未经授权 AI 产品、真实付款与对外动作边界不因定位扩大。laravel-modules 来源仍是第三方包，其正式能力范围见独立固定矩阵，不另起模块内核或无限吸收其他产品。
