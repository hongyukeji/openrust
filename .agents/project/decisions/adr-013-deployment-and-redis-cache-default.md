# ADR-013 单机与集群部署、默认 Redis 缓存

- 状态：Accepted（部署与默认配置决策；缓存驱动仍按里程碑实施）
- 日期：2026-10-25
- 替代：ADR-003 中“缓存默认进程内、Redis 仅可选”的部分；队列与会话默认策略保持有效。

## 背景

一般应用先部署单机，业务并发或单机资源达到瓶颈后需要增加应用副本。框架同时支持单机和集群，并默认采用共享缓存，减少扩容时更换基础机制的成本。

## 决策

- 单机与集群均为 v1 正式支持拓扑。普通项目可用一个应用实例；集群仍是必须实现和验收的能力，不要求所有项目开始就部署多个节点。
- 标准生成应用与默认示例使用 Redis 缓存；框架 Cache 入口不变，memory/file 仍可显式选择，用于本地/测试或已明确接受其作用域的场景。
- 默认模板显式启用对应 Redis feature，并提供 Redis 开发依赖编排与配置示例；底层库保留按需编译，精简应用可不用 Redis。Redis 版本、超时和连接默认值实施前按实际驱动与集成测试决定，不在此虚构支持矩阵。
- Redis 不可达时不得静默切换进程内缓存并报告正常。配置与就绪检查明确失败；允许降级的特定业务需显式策略及对应保证说明。
- 队列继续默认数据库，Session 继续默认共享数据库，Redis 驱动按各自契约选择；本次默认缓存调整不自动改动队列、认证和会话后端。
- 数据库与 Redis 是应用集群的共享状态基础：业务数据在数据库，缓存及所选限流/验证码/锁/在线路由状态由对应契约选择共享后端。存在两个服务不等于业务已具备多副本正确性。
- 集群还需负载均衡、共享文件/对象存储（使用上传时）、一致的应用配置和密钥，以及任务去重、租约恢复、跨节点实时投递与滚动发布；按 [集群计划](../plans/v1-cluster-deployment.md) 验收。
- 一台数据库和一台 Redis 可支撑多个应用副本，但它们仍是单点。应用多副本不等于基础服务高可用，也不要求默认启用 Redis Cluster；数据库/Redis 的 HA、持久化和备份按部署侧需求配置。
- 在达到共享数据库/Redis 的容量边界后再评估基础服务扩容，不承诺增加应用节点即可无限扩展。

## 影响与验收

- 更新 ADR-009、总计划、技术栈、配置说明与默认模板设计；相关代码和真实 Redis 接入在 M5 功能簇实施，不因本决策视为已实现。
- 验证单应用加数据库/Redis 的开发路径，以及多应用共享同一逻辑数据库和 Redis 的路径。缓存跨节点可见、失效/故障行为与集群原子操作分别测试。
- 本次仅更新设计，不启动、安装或重配任何用户基础服务，不修改凭据，不执行远端部署。
