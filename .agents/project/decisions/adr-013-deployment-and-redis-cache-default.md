# ADR-013 单机与集群部署、共享状态要求（缓存默认值已被 ADR-014 修订）

- 状态：Partially Superseded（部署拓扑与共享状态要求仍有效；默认缓存后端由 ADR-014 改为 memory）
- 日期：2026-10-25
- 历史：本 ADR 初版曾建议 Redis 作为应用默认缓存；该默认值现由 ADR-014 修订。队列与会话默认策略保持有效。

## 背景

一般应用先部署单机，业务并发或单机资源达到瓶颈后需要增加应用副本。框架同时支持单机和集群；需要跨节点一致的状态时，应用必须按功能 contract 选择共享后端。

## 决策

- 单机与集群均为 v1 正式支持拓扑。普通项目可用一个应用实例；集群仍是必须实现和验收的能力，不要求所有项目开始就部署多个节点。
- 按 [ADR-014](adr-014-cache-driver-and-store-contract.md)，默认生成应用使用无需外部服务的进程内 memory cache；Redis/file 由应用显式选择。Redis 仍是集群共享缓存的官方可选 driver，按需编译并提供真实集成验证。
- Redis 不可达时不得静默切换进程内缓存并报告正常。配置与就绪检查明确失败；允许降级的特定业务需显式策略及对应保证说明。
- 队列继续默认数据库，Session 继续默认共享数据库，Redis 驱动按各自契约选择；本次默认缓存调整不自动改动队列、认证和会话后端。
- 数据库是默认共享状态基础；若应用选择 Redis，Redis 可提供缓存及相应契约支持的共享状态。缓存及所选限流/验证码/锁/在线路由状态由对应能力明确选择共享后端。存在两个服务不等于业务已具备多副本正确性。
- 集群还需负载均衡、共享文件/对象存储（使用上传时）、一致的应用配置和密钥，以及任务去重、租约恢复、跨节点实时投递与滚动发布；按 [集群计划](../plans/v1-cluster-deployment.md) 验收。
- 一台数据库及显式配置的一台 Redis 可支撑多个应用副本，但它们仍是单点。应用多副本不等于基础服务高可用，也不要求启用 Redis Cluster；数据库/Redis 的 HA、持久化和备份按部署侧需求配置。
- 在达到共享数据库/Redis 的容量边界后再评估基础服务扩容，不承诺增加应用节点即可无限扩展。

## 影响与验收

- ADR-014 修订默认缓存决定。缓存代码及真实 Redis 接入仍在 M5 实施，不因本决策视为已实现。
- 验证单应用仅依赖数据库的默认路径，以及显式 Redis 的多应用共享路径。缓存跨节点可见、失效/故障行为与集群原子操作分别测试。
- 本次仅更新设计，不启动、安装或重配任何用户基础服务，不修改凭据，不执行远端部署。
