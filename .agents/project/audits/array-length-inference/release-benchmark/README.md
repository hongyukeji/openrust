# Release 耗时与堆分配对照

2026-11-24。结论：**本轮测点未新增Rust堆分配；稳态注册、Application装配和Faker调用基本不变，方法列表生成更快；新进程首次构造Faker仍有约0.6微秒的实测变慢，保留为冷路径例外，不能概括为所有场景绝对零开销。** 不改变生产代码以消除测量噪声或掩盖例外。

## 对照设计

- 同一已提交基线 `a15c7b891dd8c121cbf936d1f8562638355cfa85`。A只反向恢复 `ce75e29be`、`2099a49a6` 的框架长度表达改动，B保留推导写法；其他实现、数据和顺序相同。新增Provider和模板仍保留：两组都是31个Provider、40个模板，A的手写数字据此调整，避免把新增功能差异当成性能差异。首次机械复原38个模板不能编译，不计入任何测量，修正为当前40项后才构建A。
- Apple M4 Max／Mac16,5，aarch64 macOS 27.2.1，Rust 1.94.0／LLVM 21.1.8。`cargo build --locked --release`，开启相同的 `CARGO_PROFILE_RELEASE_INCREMENTAL=true` 保留增量缓存；其余Release默认值，无额外RUSTFLAGS／LTO覆盖。结果不是对其他编译配置、平台或未来编译器的保证。
- 两组使用同一路径的独立源码，依次编译后保存二进制，避免源码路径长度影响分配计数。未在活跃工作树编译，未改生产源码、根清单或锁文件。
- 普通计时二进制使用默认分配器，**没有计数器**；另一个二进制以 `GlobalAlloc` 转发至System统计 `alloc`、`alloc_zeroed`、`realloc`、`dealloc`。计数器以64字节分配→128字节扩容→释放自检，确认次数、192字节累计请求、128字节峰值与0字节保留。
- 构造输入、命令行解析、JSON输出均在测量区间外。稳态工作预热后批量调用；冷工作每个样本启动新进程，只调用一次，不把已初始化的LazyLock当作首次初始化。
- 先做两轮探索采样，再做一轮严格控制采样；每轮稳态31对、冷路径151对，A/B顺序和用例顺序随机交错；对每对B/A的对数比取中位数，用10000次配对bootstrap得到95%区间。预先以5%作为实际关注阈值。CI只描述本机这套实验，不能证明所有负载或未来部署的上界。
- 为观察私有方法，仅在隔离副本加入同样的适配器：`Router::all_methods()`原样返回和`default_elements()`原样返回。适配器没有Vec、Box或动态分发；方法适配器的8项返回类型用于匹配固定测量基线的ABI，不是新增生产契约。

参考官方 [`black_box`](https://doc.rust-lang.org/std/hint/fn.black_box.html) 防止无用计算被直接消除；[`GlobalAlloc`](https://doc.rust-lang.org/std/alloc/trait.GlobalAlloc.html) 计数只说明该产物实际观察到的请求，分配本身也可能被编译器优化。官方当前文档用于方法论，实际构建使用1.94.0；版本化文档链接本轮工具未能访问，不声称已在线核对其页面。

## 耗时结果

下表取最后一轮严格控制采样：通过 `subprocess.run(..., executable=...)` 把A/B的 `argv[0]` 固定为相同的 `array-perf`。前两轮使用各自文件名作argv0，虽然解析在计时区间外，启动前分配／触页上下文仍不够一致，故仅作为探索数据保留在 [results.json](results.json)，不据此直接归因。所有原始数据都保留。注册测点包括创建、注册128条静态URI和销毁一个Router，不包括HTTP请求分发或网络吞吐。Application测点只做 `create()`，不包含Provider boot、HTTP监听、队列和调度运行。

| 测点 | 固定长度A中位数 | 推导B中位数 | 配对变化及95%区间 |
| --- | ---: | ---: | ---: |
| 128条GET注册 | 770.619 µs | 773.377 µs | +0.41% [-0.46%, +0.98%] |
| 128条any注册 | 906.304 µs | 908.760 µs | +0.89% [+0.12%, +1.42%] |
| 8项HTTP方法列表 | 23.736 ns | 21.022 ns | -11.39% [-12.05%, -11.04%] |
| Application::create | 14.516 µs | 14.596 µs | +0.82% [-0.27%, +1.06%] |
| Faker重复构造 | 198.853 ns | 198.980 ns | +0.05% [-0.73%, +1.00%] |
| Faker热randomElement | 74.676 ns | 73.513 ns | -1.56% [-2.30%, -0.20%] |
| 默认集合热读取 | 0.677 ns | 0.679 ns | -0.03% [-0.45%, +1.02%] |
| **新进程首次Faker构造** | **21.334 µs** | **21.958 µs** | **+3.43% [+1.51%, +5.14%]** |
| 已构造／seed后的首次randomElement | 9.084 µs | 8.291 µs | -9.13% [-10.00%, -7.69%] |
| 默认集合首次初始化 | 5.167 µs | 4.542 µs | -12.02% [-13.49%, -10.41%] |

“配对变化”是每对B/A的中位数，不是前两列总体中位数相除。方法列表三轮均快约11–12%，仅约2.7–2.8ns／次，**不代表HTTP吞吐提高11%**。注册及Faker稳态的置信区间都落在±5%内。

冷Faker构造探索轮配对变化分别为+3.78%和+5.33%，总体中位数相差约0.9–1.0µs。另做151对相同argv0的构造专测，变化缩至+1.32% [0.00%, +2.81%]；最后完整受控轮为+3.43% [+1.51%, +5.14%]，约0.62µs。因此冷结果对启动上下文敏感，既不能把探索轮5.33%说成确定的自动推导开销，也不能证明冷构造完全落在±5%等效区间。保留例外，不以稳态结果覆盖冷路径。补充检查发现：

- 构造函数本体两份反汇编都是70条指令，操作码序列一致；代码／数据地址不同。没有据此证明操作数、所有被调函数或整个调用链完全等价。
- 101组独立进程对照，用0次构造作控制组、1次构造作实验组，新增minor fault的配对中位数为23→24，major fault为0→0。该计数覆盖整个子进程，**不是函数局部计数**。
- 现象与二进制布局和首次触页差异相符，尚未证明唯一因果。没有将这约1µs差异包装成随机误差消失，也没有据此推断稳态每次调用会多耗1µs。

空工作冷对照出现0ns和约125ns等量化结果，因此只报告绝对控制值，不计算其相对比率。初次汇总因log(0)中断；完整原始样本保留，修正汇总后重新分析，真实测点没有零时长，也没有丢弃样本。

## Rust堆分配

每项A/B均独立执行5遍，所有重复结果一致。下表为每个操作；字节数是**累计请求字节，包含realloc的新请求尺寸**，不是RSS，也不含分配器大小分级、管理元数据和静态区。计数不会覆盖绕过Rust全局分配器的外部C／OS分配。

| 操作 | alloc次数 A=B | realloc次数 A=B | 请求字节 A=B | 区间峰值字节 A=B |
| --- | ---: | ---: | ---: | ---: |
| 注册128条GET | 13700 | 3471 | 2826604 | 988069 |
| 注册128条any | 14476 | 3501 | 2894420 | 1016899 |
| 生成8项HTTP方法 | 0 | 0 | 0 | 0 |
| Application::create | 71 | 9 | 15948 | 11957 |
| 构造Faker（冷／热相同） | 4 | 0 | 20 | 15 |
| 热randomElement | 3 | 0 | 38 | 25 |
| 已构造／seed后的首次randomElement | 6 | 0 | 41 | 28 |
| 默认集合首次初始化 | 3 | 0 | 3 | 3 |
| 默认集合热读取 | 0 | 0 | 0 | 0 |

默认集合首次的3次是原有a／b／c三个Json字符串，保留3字节请求供静态LazyLock长期使用；不是新增分配，也不表示整个Faker只占3字节。其他测点区间结束的观测保留字节均为0。注册原有的分配没有因推导改动增加，本轮没有对其做独立优化。

## 复现和证据

在仓库根执行（本复现器按macOS等POSIX环境编写，Python 3.12+，需要固定提交历史和Rust 1.94.0；Windows未验收）：

```sh
python3 -B .agents/project/audits/array-length-inference/release-benchmark/run.py
```

脚本默认使用本次固定基线，在新的 `target/tmp/array-release-repeat-*` 下归档、构造A/B并通过正式构建守卫运行。可用 `--output target/tmp/<未使用目录>` 指定目录；`--prepare-only` 只核对输入。不会修改生产工作区／索引，不提交或推送。新机器路径和平台可能改变绝对耗时与分配字节数；比较时以同一次运行的A/B为准。主机级采样未绑核、未锁频，其他开发任务未被关闭，故不宣称实验室级零干扰。

- 实测原始证据：`target/tmp/array-release/`，含三轮原始样本、5次计数、二进制、两组源SHA、构建日志、反汇编及进程级fault对照；前两轮在 `run-1/` 和 `run-2/`。
- `results.json` 保存三轮汇总、单独argv0控制、计数、硬件／工具链、源／二进制／测点源码SHA及冷路径例外。
- 复现准备器实际生成的两组框架源SHA均与实测构建输入一致；所交付Rust测点源码逐字来自已编译样本。独立计数／自检和汇总脚本再次运行，复现了计数与汇总；主测点后续统一argv0后重新执行，最终脚本也采用相同控制。
- 本轮只新增内部测量材料，没有修改生产实现或三语用法文档。没有全仓性能、其他扩展性能、跨平台或HTTP网络吞吐的扩大结论。
- 编译采用本批独占Release缓存，保留正常并发和增量；日志及A/B独立二进制保留。无容器、数据库、HTTP服务、系统设置或用户应用变更。本地提交，不推送。
