# 06-04 批次账本与数据库队列跨连接发布

固定 Laravel 由批次账本事务更新计数，再通过批次配置的队列连接批量派发。OpenRust 保留同一连接的原子写入。使用独立数据库连接时，沿用现有 Redis 发布的持久意图和恢复命令，在目标数据库同一事务写入回执与任务。复核旧版 `6d1a8192` 的队列存储及实际 Worker 用例，旧版未实现任务批次账本。 [Laravel Batch::add](https://github.com/laravel/framework/blob/1449bf241017087fbd38c118ecaabef3f6797fdc/src/Illuminate/Bus/Batch.php)

- 初始发布、追加和链式续接使用各自的发布标识。初始发布确认后才允许追加和续接。目标数据库提交后才确认账本。确认失败时，恢复命令凭目标回执跳过已提交的插入。两个数据库均需迁移，目标数据库的回执在账本确认后标记为可清理。
- 使用两个独立 MySQL 8.4.13 验收库。通过实际 HTTP 创建批次和追加任务，模拟目标队列表不可写和目标提交后的账本确认失败。两个 Artisan 恢复进程并发运行，最终仅入队三条。实际 `queue:work destination` 各处理一次，批次进度达到 100%。同一套件复验 Redis 8.10.3 发布恢复、批次与链，另覆盖 SQLite。
- macOS ARM64、Rust 1.94.0。锁定离线 `job_batches` 2 项通过，1 个 Artisan 夹具由测试启动。格式、专项严格 Clippy 和三语站点构建通过。
- 06-03 仍跟踪 Bus 派发 DSL、PHP 序列化边界及额外内置驱动。06-04 仍跟踪固定 Laravel 的其余任务中间件及发布矩阵。核心闭合计数保持 21/66。
