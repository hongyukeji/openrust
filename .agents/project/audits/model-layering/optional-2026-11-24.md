## 第一批：Scout 批量导入

- `Searchable::make_all_searchable` 的公开签名、模型覆写钩子和默认值不变；内部 `importer` 模块承接原批量导入函数，模型入口与 EngineManager 为 Artisan 注册的导入闭包均委托同一实现。
- 原分页／软删除查询、`make_all_searchable_using`、`should_be_searchable`、引擎同步、队列及计数顺序保留；没有增加平行导入机制或公开类型。三语 Scout 指南补充模型入口与命令的共同行为。
- 新增真实 TCP／HTTP 模型入口消费者：默认及显式 chunk、查询覆写排除、模型资格过滤、已删除模型及零 chunk 失败。仅新增既有 axum 的开发依赖和锁文件条目，无新运行期依赖。

### 验收

Rust 1.94.0，隔离快照由已提交基线加本批文件组成；工作区其他在途修改未纳入。Cargo 与临时文件均通过 `tests/build_guard.py` 放在项目 `target/tmp/model-layering-optional-20261124/`，保留正常增量和并发。

```sh
cargo test --locked -p openrust-scout --test integration
cargo fmt --all --check
cargo clippy --workspace --all-targets --locked -- -D warnings
```

- SQLite：integration 8项通过，包含真实 HTTP 模型导入、原生 HTTP Kernel、事务与 Observer、队列和 Artisan import／flush。
- MySQL 8.4.13、PostgreSQL 18（180007）：各精确运行真实 HTTP 模型导入和 `native_queue_reloads_latest_models_deletes_tombstones_and_import_commands_use_chunks`，各2项通过，合计12项实际驱动／入口执行通过。
- Artisan 覆盖 `--fresh`、分批 2／2／1、flush 不删业务数据、未知模型与零 chunk 错误。外部数据库两项用例分别由独立测试进程执行，避免旧夹具中固定表名在同一进程并行互删；没有用全局测试串行化掩盖冲突。测试服务使用项目的独占 MySQL／PostgreSQL 入口，不连接开发库。
- 全仓格式与 workspace／all-targets 严格 Clippy 通过；三语内容、命令入口、VitePress 构建和 `/`、`/docs/` 的三语桌面／移动端浏览器检查通过。
- 首次构建触及32 GB停线，守卫停止后持锁清理项目编译产物，释放63,671,336,960字节，清理后可用96,468,639,744字节；源码、未提交修改、日志、依赖缓存和数据卷保留，随后重新验收通过。

本批容器由隔离夹具回收；失效临时产物和文档构建在收尾清理，验收日志与下一批复用的独占缓存保留。不推送。
