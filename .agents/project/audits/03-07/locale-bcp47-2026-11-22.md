## A：盘点与契约

- 配置→现有 canonical_locale→App／Lang／LocaleUpdated／请求任务作用域→Translator 动态词条与缓存→FileLoader／DatabaseLoader。沿用精确语言资源加显式 fallback，不引入隐式 CLDR 地区归并；句子键 JSON 与分组回退差异保留。
- 应用策略：SetLocale 将浏览器中文文字／地区映射到三语资源；公开解析不做该映射。WelcomeController 分别选择页面文案与可用文档语言。
- 消费者：Validation、Blade、邮件 Markdown／PendingMail、通知／队列任务、Artisan／Worker、Number、Faker。Faker provider 和原始语料使用原生下划线键，只在私有 provider 边界适配；locale()／randomLocale() 公开输出使用 BCP 47。Number 复用 ICU 完整 Locale。
- 资源：根 lang 三语；框架 translation/stubs 的分组资源与 JSON；文档三语目录、VitePress 导航／搜索／landing／404、检查脚本；初始化与独立部署按已有目录复制。实际旧标识出现文件清单见临时 `old-label-inventory.json`，不是以关键词数量替代消费者验收。
- 持久化：translation-database 的 language_lines.text 为语言到文案的 JSON 对象，group／key 是翻译键，不能替换；表名可定制。settings 保存应用自定义 JSON，没有框架强制 locale 字段。邮件／通知序列化载荷含 locale，须部署前排空或显式迁移；不扫描或修改开发库。外部 WeChat lang、Faker／CLDR／portable-ascii 数据、许可和历史审计保留所属原生协议。
- 库决策：继续复用锁定 ICU4X Locale／LocaleCanonicalizer 2.4.0。完整 Locale 保留文字、地区、variant、Unicode／其他扩展及 en-x-demo；以固定 CLDR 别名数据 canonicalize（如 iw→he），不调用 maximize/minimize。拒绝下划线及非 ASCII 标签字符。Unicode Locale 不覆盖全部 BCP 47：独立 private-use x-demo、grandfathered i-klingon、extlang 等库拒绝形式显式 InvalidLocale，不静默丢弃。未在线校验每个 IANA 注册子标签，也不维护自有注册表；此支持边界须同步三语正文。
- 固定 Laravel 的 en_GB 示例与本次用户 BCP 47 标准冲突，仅目录／标签契约由用户决定覆盖；其余命名、装配、事件顺序和隔离保留。参考来源原文及摘要见 research/sources.json；旧 v0.x 的 translation.rs 使用自有 Locale／消息目录和不同 loader 体系，不能整套迁入；仅复用既有调用链盘点经验。

## B：核心及消费者

- `translation/locale.rs` 复用 ICU 完整 Locale 和扩展 CLDR canonicalizer，保留 script／region／variant／支持的扩展，不增加 maximize／minimize。公开旧下划线输入拒绝；额外拒绝 ICU 会去重的重复 Unicode attribute／key、transform key 和 variant，避免静默丢弃输入信息。`language_tag` 仅供复数内部提取 id，不改变公开标签或翻译资源路径。
- App 当前值、`isLocale`、fallback 和 LocaleUpdated 字段同一入口规范化；保留配置→译器→事件的顺序与错误传播，不新增全局可变状态。复核并保留既有深层 Config、首次解析默认值、Blade 翻译块等修复。
- Faker 的公开 locale 和私有 provider locale 分离，全部 formatter 分派使用私有键。Hans／Hant 的 provider 适配仅发生在该边界；公开标签保留地区和扩展。原始 255 个 provider 经 CLDR 弃用别名规范化得到 252 个不同标签，UniqueFaker 耗尽规则按真实规范结果验证；不改语料及来源许可。
- Number 采用同一规范化入口并保留 Unicode 扩展；邮件／PendingMail 和通知在记录 locale 或序列化前验证，排除旧载荷新入队；Markdown HTML 输出标准标签。Artisan fallback 按连字符分段，init 默认简体为 zh-Hans；Blade 缓存版本由 37 升到 38。
- 实际 Worker 消费者将 7 项 mail／notification 任务写入独立 SQLite，再通过真正 Artisan 子进程处理，核对载荷、简繁体 Blade 文案、通知 HTML lang、后续英文任务恢复、jobs／failed_jobs 及数据库通知结果。邮件 scope 覆盖 compose，通知 scope 覆盖 delivery，按既有职责验收，未借机扩大生命周期重构。

## C：资源、应用及文档

- 实际将 `lang/zh_CN`、`lang/zh_TW` 迁为 `lang/zh-Hans`、`lang/zh-Hant`；`docs` 对应目录同批迁移。默认环境模板三个语言键采用新标签，框架原英文默认保留 en／en-US；不编辑真实 `.env`。
- SetLocale 保留应用中文协商策略，显式 script 优先 region；未知 script 不按地区猜测。控制器区分应用当前语言、welcome 标题实际翻译语言和三语文档语言，关闭中间件的 fr 等标签不生成不存在的 docs/fr 链接，也不修改全局语言。
- VitePress 配置、landing／404、搜索、导航、语言切换、所有检查脚本、README、部署说明及项目有效链接同步新目录；三语 localization 解释解析支持、资源精确查找与升级步骤，configuration／deployment 引用同一升级章节。旧目录和旧 URL 不保留平行副本或默认重定向。

## D：持久化及升级

`vendor/openrust/translation-database/database/upgrade-bcp47/` 提供 PostgreSQL／MySQL／SQLite 各自只读 inventory 和事务脚本，只修改 language_lines.text 的语言键。默认映射 zh_CN→zh-Hans、zh_TW→zh-Hant、en_US→en-US、en_GB→en-GB；不改 group／key／文案，合法独立 zh-CN 保留。表名和其他应用专有映射须部署者审阅。

未映射的下划线键或任意旧新键同时存在时全局阻断，包括相同值、null，保证没有部分更新。默认末尾 ROLLBACK；明确核对后才改 COMMIT。验证失败时关闭专属会话；已提交后的恢复依赖备份，不能按新键名猜测来源并反向覆盖。

升级顺序：暂停新任务→排空旧 mail／notification 或保留待专用迁移→停旧进程并备份→旧版本清 config／view 缓存→同步配置、资源、代码及审阅后的持久化迁移→新版本重建缓存并重启。settings 任意 JSON 和加密队列没有安全的通用文本替换；不提供自动运行时兼容层。本轮仅只读核对真实 `.env` 的三个语言键仍为旧值，未访问开发数据库、缓存或数据卷；实际数据操作不在授权内。
