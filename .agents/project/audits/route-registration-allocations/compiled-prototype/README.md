# Symfony 式编译路由：隔离纯 Rust 原型

2026-11-24。用户授权先做原型对照，确认收益与兼容性后再决定是否替换。**本轮不修改正式 Router、Route、Application 或缓存代码，不启用正式后端或新增公开配置。** 原型放在 framework/tests/prototypes，prepare.py 只修改项目 target/tmp 下的 git archive 隔离副本。正式应用继续运行[既有实现](../followup/README.md)。

## 参考与实现范围

沿用项目 Laravel v13.40.0 固定基线与[上轮调研](../followup/README.md)。主要参考 Symfony Routing v7.4.0、提交 `4720254cb2644a0b876233d258a32bf017330db7` 的 [groupStaticRoutes／动态正则块](https://github.com/symfony/routing/blob/4720254cb2644a0b876233d258a32bf017330db7/Matcher/Dumper/CompiledUrlMatcherDumper.php)：会被先注册动态路径匹配的字面路由仍留在有序动态集合，无冲突的字面路径进入直接索引。没有复制 PHP 源码或引入 PHP／Go 运行时。

原型复用锁定依赖 regex 1.13.1 的 [RegexSet](https://docs.rs/regex/1.13.1/regex/struct.RegexSet.html)：集合只筛选保守字面前缀，按声明序号枚举候选，精确匹配、PCRE 约束、域名、参数提取、默认值、绑定、方法和中间件继续委托现有 Route／Router。没有移植 Symfony 的完整 PCRE 大联合表达式、MARK 或 host/path 拼接；它是编译候选架构原型，不是 Symfony 全部代码的 Rust 完成版。未新增依赖、缓存格式或全局状态。

- 每个方法按既有 by_method 顺序构建静态全路径表及有序动态候选；同 URI 覆盖已经由原注册代码完成，保留槽位顺序。动态遮蔽判定忽略域名作保守处理，宁可少进入静态表，也不让后注册静态路由提前胜出。
- 每256个动态候选使用一个前缀 RegexSet，依次筛选、精确匹配；不匹配的块只调用 is_match，匹配块才创建结果集合。参数约束没有合并、修改或推迟验证。
- 参数前的可选分隔符从前缀中保守移除。普通／回退路由选择保留原规则，回退候选按原 ordinal 比较，不能用新 route index 代替注册位置。
- 每块编译限制10MiB；若集合构建失败，整个原型标记回退到原 Router（包括既有缓存候选路径），不新增路由注册错误或取消原有正则资源限制。
- GET／HEAD 等方法只有在完整有序 route index 列表相同时共享 Arc<MethodMatcher>；不跨应用共享。新增注册清空实例内 OnceLock，避免陈旧索引。
- 隔离副本在应用路由装配和旧缓存加载后调用准备边界：基线是无分配 no-op，原型在启动阶段编译。直接 Router 测量也显式准备，避免把编译时间隐藏到首个请求。原型保留旧缓存对象及其验证逻辑，新的索引不写入缓存文件。

## 负载与测量边界

冻结基线、工具链、二进制和源码哈希见 results.json。两版共用相同 source 路径、Cargo.lock、Rust 1.94.0、默认 Release 配置及 incremental=true，仅隔离注入的原型不同。计时和分配是两个独立程序，argv0固定 compiled-route-perf，按同样的shape/count/iterations运行。原始日志与样本位于项目 `target/tmp/route-compiled-prototype/`。未绑定CPU／锁频或停止其他开发任务。

使用同一个 workload.rs 生成128、1000、10000条路由：

- static：`/bench/item00000` 等独立字面路径。
- dynamic：`/bench/item00000/{id}` 等独立参数路径。
- overlap：同一编号的一对动态／字面路径，交替采用动态先注册、静态先注册。查询必须分别保留两种赢家，不能无条件静态优先。

所有路径共用首段 bench，这是明确的同前缀负载；未据此推断首段分布很分散的应用或现有缓存的总体收益。六个查询依次为 first、middle、last、near_last、miss、reject；overlap 的 last 是靠后静态优先路径，near_last 是靠后动态优先路径，单独报告以免只挑快路径。reject 使用已有前缀但缺少必需参数或增加路径段。

每个分配阶段重复3次：完整创建／注册／准备／销毁（预热与首次分开）、仅索引构建、保留注册表、保留表并预热66次查询、已准备索引的首次首项／末项，以及预热后600次查询。分配器包装System，有alloc/realloc/free/请求字节/峰值/保留字节自检；不把分配计数器用于计时。常驻和预热后的保留字节均为Rust请求的存活堆字节，**不是RSS**；不含栈上Router对象、分配器内部开销及绕过Rust分配器的C／OS分配。

31轮随机交错配对计时，另做10000次配对bootstrap，保存全部原始样本、范围、IQR及95%区间。注册指标包含准备和销毁；编译cold是新注册表首次编译，warm是在同一注册表上重建索引（销毁在计时外）。首项和末项cold查找分别使用新注册表上的已准备索引；计时程序的首项在该表的cold编译、reset和warm重建之后查询，末项在另一张只准备一次的表上查询，二者都没有先发送请求；分配程序两者均只准备一次。编译本身可能已建立部分路径引擎缓存，cold不代表所有内部缓存为空；warm查找先验证并预热六个固定查询。没有计入处理器、解码、网络或数据库时间，不解释为HTTP吞吐。零耗时样本保留，对无法取对数的测点不计算百分比。

## 探索中的问题

- 单个万模式RegexSet试跑的动态查询约1.3ms，保留 exploratory/single-set.json 与诊断二进制；它不是最终31轮结果。之后改为上述有序分块，没有丢弃不利探索结果。
- 原型最初把 Rust trim_end_matches 的字符串模式误当字符集合，可选参数的 `/optional`、`/file` 漏匹配。原实现指针对照发现2项失败；修正为字符谓词并保留失败日志和反例。正式代码未受影响，未放宽断言。
- RegexSet 的匹配结果使用堆分配，预热后命中的动态块仍可能增加请求分配；首次查询还可能构建引擎内部缓存。这些成本纳入实测，不宣称所有查找零分配。

## 实际结果与裁决

**裁决：保留隔离原型，不替换正式 Router。** 大表靠后命中和未命中有明确收益，但早命中、首次引擎缓存、启动和请求分配均有退化；目前没有真实应用的命中分布，不能证明总收益。没有新增生产配置或改变公开契约。本次不是完整路由引擎替换验收。

## 契约验收与范围

在冻结基线与原型上分别实际执行：新增TCP HTTP矩阵1项、路由／请求／验证相关53项、SQLite真实HTTP模型绑定1项、根应用startup／console／resource_generator 37项；每版92项。原型另有3项与旧匹配器逐一比较路由指针的单元测试，总计187项Rust测试，0失败、0忽略（最终检查退出码见JSON）。矩阵每版实际144次HTTP请求、27次原生Application::handle_command Artisan调用，覆盖缓存生成两次字节稳定、加载及清除。不是外部shell的吞吐测试。

复用既有测试验证：注册顺序、重复覆盖、GET／HEAD、405和Allow顺序、组／前缀／中间件、Facade、多应用隔离、可选／默认参数、模型绑定、参数约束、域名大小写、Unicode和百分号解码，以及非法URI、参数上限、超长约束等旧错误边界。调试构建每次原型匹配均与原实现比较同一个Route指针，Release计时不执行对照。SQLite绑定确实执行；没有把未配置MySQL的早返回测试算入通过，本轮不修改数据库逻辑。

9组缓存原始字节在两版间一致，SHA保存在JSON；不同shape相同条数的缓存可以同哈希，因为既有v1保存首段bench及route index，模板仍由注册恢复。缓存错误和原资源限制仍走旧代码。本轮强制模拟缺失前缀集合测试保守扫描；没有真正触发10MiB编译耗尽或OS内存不足，不能把这些极限当成已实测。

首次严格Clippy指出负载两处取模应使用is_multiple_of，已作等价语法修改。测量二进制／样本没有替换或重采样；JSON保存实际测量负载源码及哈希、最终源码哈希，独立Rust对照确认三种负载33384条路径与54个查询完全相同。该修改不涉及原型匹配逻辑；失败日志亦保留。

没有修改用法及公开入口，故不往三语用户指南加入实验实现细节；本记录承载内部设计和验收。未验证真实业务流量分布、跨平台／CPU、并发吞吐、全量Laravel路由组合和分散前缀性能。不会把本轮通过扩大为已证明生产替换或性能最优。

## 复验

依次在项目根调用 prepare.py prototype／baseline，通过 `tests/build_guard.py --workflow route-compiled-prototype --target-dir target/tmp/array-release/cargo-target -- <命令>` 构建隔离副本。脚本会接入原型及诊断example，不能把隔离代码拷回正式src。

```sh
python3 -B .agents/project/audits/route-registration-allocations/compiled-prototype/prepare.py prototype --revision 176353051e38f379ee2ade811d15be14a7c2fcb4
# 隔离source中：
cargo fmt --all
cargo build --release --locked -p openrust-framework --example compiled_prototype_alloc --example compiled_prototype_time
cargo test --locked -p openrust-framework --lib routing::router::compiled_prototype::tests
cargo test --locked -p openrust-framework --test routing_compiled_matrix -- --nocapture
```

分别保存两版example为工作流bin/prototype_alloc、prototype_time、baseline_alloc、baseline_time；两版都设置 `CARGO_PROFILE_RELEASE_INCREMENTAL=true`。之后由同一守卫运行本目录measure.py，默认写入该工作流，另设ROUTE_PROTO_DIR仅允许项目target/tmp内目录。HTTP矩阵可通过ROUTE_PROTOTYPE_CACHE_OUTPUT保存缓存副本，路径必须位于隔离工作流内。

两版检查命令固定在verify.py，在build_guard中调用`python3 -B <本目录>/verify.py baseline`或`prototype`。最终源码通过格式及框架／根应用all-targets严格Clippy；原型隔离副本的workspace all-targets严格Clippy亦通过，完整命令见JSON。原始日志保留，临时隔离源码／辅助脚本在退出后清理，独立诊断二进制、样本、缓存字节与日志保留在工作流目录；Cargo缓存按磁盘守卫规则复用。再次运行prepare.py会从指定提交重建，不读取其他协作者的在途源码。
