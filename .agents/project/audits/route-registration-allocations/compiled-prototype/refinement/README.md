# 编译路由原型第二轮：借用前缀与顺序选择

2026-11-24。延续[第一轮](../README.md)的纯 Rust 隔离原型；正式 Router／Route／Application、公开 API、注册顺序、缓存 v1 均不修改。本轮只优化候选筛选与准备阶段，不接入生产后端。第一轮记录和数据保持原样。

## 调研与采用范围

- **Symfony Routing v7.4.0**，固定 `4720254cb2644a0b876233d258a32bf017330db7`：[StaticPrefixCollection](https://github.com/symfony/routing/blob/4720254cb2644a0b876233d258a32bf017330db7/Matcher/Dumper/StaticPrefixCollection.php) 保留顺序并按前缀组织候选，[CompiledUrlMatcherDumper](https://github.com/symfony/routing/blob/4720254cb2644a0b876233d258a32bf017330db7/Matcher/Dumper/CompiledUrlMatcherDumper.php) 区分静态与动态匹配。沿用候选编译与精确匹配分层；本次将重叠裁决留到请求阶段按原 ordinal 比较，取消原型注册时的逐对遮蔽检查。没有复制 PHP 实现，也没有移植整套前缀树／PCRE 联合正则。
- **Laravel v13.40.0**：[AbstractRouteCollection::matchAgainstRoutes](https://github.com/laravel/framework/blob/v13.40.0/src/Illuminate/Routing/AbstractRouteCollection.php) 取首个普通匹配，只有找不到普通匹配才使用 fallback。本原型的所有快路径都服从这一规则，并按本地既有 by_method 顺序选择，不另行重排域名或路由。沿用既有 Route 精确匹配、错误、参数、绑定及缓存装配。
- **matchit v0.8.4**，正是冻结 Cargo.lock 已有的 Axum 间接依赖：[源码](https://github.com/ibraheemdev/matchit/tree/v0.8.4)、[优先级说明](https://github.com/ibraheemdev/matchit/blob/v0.8.4/README.md)。其借用路径及前缀缩小搜索范围可借鉴；静态优先、冲突处理及动态后缀范围无法直接覆盖本项目的既有契约，所以没有将其整套 matcher 接入，也不重复实现其参数树。
- **Gin v1.10.1** 的[路由树](https://github.com/gin-gonic/gin/blob/v1.10.1/tree.go)作为零拷贝前缀搜索的旁证；不搬用节点优先级或 Go 运行时。旧版 openrust-v0.x 依赖 Axum 的匹配方式也有相同接入边界，不恢复旧行为。
- **regex 1.13.1** 的[源码](https://docs.rs/regex/1.13.1/src/regex/regexset/string.rs.html)：matches 建立 PatternSet，隐藏 matches_read_at 仍建立 PatternSet。复用这个隐藏入口不能消除分配；自行增加线程缓存、池锁或底层新依赖会增加状态与接入成本。本次用标准库 HashMap 的借用键查询和有序 Vec，未增加依赖、全局缓存、池或新路由引擎。

固定源码、仓库既有依赖与真实消费者测试作为选择依据，不引用 Star 数或其他项目的跑分来证明本项目收益。Symfony／Laravel／Gin 为 MIT，matchit 声明 MIT AND BSD-3-Clause；仅借鉴设计、复用已存在依赖，未复制第三方源码，不产生新的分发许可文件。

## 实现与顺序证明

1. 每方法编译 `prefixes: HashMap<Box<str>, Vec<Candidate>>` 及排序去重的前缀长度；静态路径用全路径，动态路径用首参数前的保守必需字面前缀。只在新前缀处分配键，同前缀候选按原 ordinal 追加；完全相同的方法序列继续共享应用实例内 Arc。
2. 请求直接以 `path.get(..length)` 借用字符串查询，不构造结果集合。遇到请求的不同 Unicode 边界跳过该长度，遇到超过请求字节长度的索引停止；空前缀、可选分隔符继续保守覆盖。
3. 先验证该方法的首个普通路由：命中即可返回，因为此前只可能有 fallback。后续候选按原 Route 精确匹配，跨桶始终取最小普通 ordinal，无普通结果才取最小 fallback ordinal。桶访问顺序、前缀长短、静态与动态类别均不能决定赢家；已有较早普通赢家时只剪掉更晚的候选。
4. 编译不再测试任意两条路由是否重叠，也不建立前缀 RegexSet；消除原型的平方级遮蔽扫描及该集合的编译失败路径。正式 Route 的正则限制、注册校验和缓存错误处理保留。隔离注入接口 requires_fallback 对新原型恒为 false；旧原型从固定提交装配时仍保留其集合失败回退分支。

前缀长度数记为 L、同前缀候选数记为 C：请求仍有 O(L+C) 的候选访问边界；高度异构前缀长度或全动态根前缀可能退化，未宣称普遍常数时间。编译的长度排序上界 O(n log n)，不再逐条执行其他路由的精确匹配。既有 Router 注册及重复覆盖处理本身仍随规模增长；本次消除的是原型新增的遮蔽成本，不修改正式注册算法。新增索引仅随本应用路由表增长，注册失效与多应用隔离继续由既有原型装配处理。

## 同基线实测方法

固定基线仍是 `176353051e38f379ee2ade811d15be14a7c2fcb4`。沿用同一 workload、128／1000／10000、static／dynamic／overlap、六个查询、分配8阶段、注册迭代数、预热次数、argv0、Rust 1.94.0 和默认 Release + incremental=true。baseline 和 previous 分别复用第一轮保留的独立基线／旧原型二进制，执行前核对原记录 SHA；prototype 用该基线隔离源码与当前原型构建。三版在同一轮交错运行，不以历史计时替代本轮复测。新源码路径为工作流内 source；旧二进制保持原构建产物，没有重链接。

计时与分配独立进程；分配每阶段3次，计时31轮随机交错、10000次配对 bootstrap，对 baseline→新原型和旧原型→新原型分别给出中位数、范围、IQR及95%区间。首次编译、重建及首次请求的具体边界沿用第一轮说明；不把查询计时当成 HTTP 吞吐，不把请求字节或存活堆字节当成 RSS。未锁频、绑核或停止其他开发任务。

新增 HTTP 反例覆盖：不同长度的重叠动态前缀、双向注册顺序、可选分隔符、Unicode边界／百分号解码、重复覆盖、域名大小写、fallback、HEAD、405／Allow及缓存前后；原型单元测试还以32种确定性排列逐一比较旧实现的路由指针。旧矩阵与路由／请求／绑定／应用测试仍实际执行，不使用同名搜索证明兼容性。

## 契约检查与中断处理

矩阵两版各2项测试，实际每版184次HTTP、33次原生Artisan调用。加上路由／请求／验证53、真实SQLite HTTP绑定1、根应用startup／console／resource_generator 37，每版93项；原型另6项直接指针对照，总计192项Rust测试。两版缓存v1的9份原始字节一致。原型调试匹配仍逐次比较旧实现指针；Release测量没有这些断言。

冻结副本的格式、相关包all-targets严格Clippy及原型workspace all-targets严格Clippy均实际通过，最终退出码见JSON。首次workspace检查被磁盘32GB守卫中断（75），不计通过；磁盘日志记录清理约82.75GB后复查107GiB，进一步清理遇到其他正在运行的rust-naming构建时安全拒绝。原始中断日志保留，独立二进制／源码／样本未删。恢复后补跑未完成检查，不把中断当成代码错误或成功。

额外实际核对prepare.py：错误基线被拒绝且不修改隔离源码、按98be650c2读取旧原型并装配其路径钩子、随后恢复当前原型及固定基线。工具不读入其他协作者的在途代码。

## 复验与证据
