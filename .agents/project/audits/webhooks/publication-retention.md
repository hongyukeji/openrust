# Webhook 共享发布正文回收

`DeliveryStore::prune_publication_bodies` 及 `webhook-server:prune --messages` 按范围、登记时间、页大小和消息 ID 游标扫描。预演返回扫描数和可清理数，实际回收只移除正文，保留摘要、消息 ID 与首次投递回执。重复发布仍执行原有幂等指纹比较。正文诊断添加 `body_pruned_at`，工作进程对已回收正文按缺失处理，保留期间的快照仍须通过正文摘要校验。

每个发布回执在原子扇出中固定最多 32 个首次投递 ID。清理先从写库确认这些 ID 的快照全部已清除，再检查已登记的重放快照。首次投递快照的清理与新重放登记有锁定边界。一旦观察到全部首次快照已清理，就无法再登记新的共享引用。随后检查已存在重放即可覆盖清理前注册成功的重放；缺失或仍在保留的投递阻止回收。更新以 `body_pruned_at IS NULL` 防止并发清理重复计数。

固定 Svix 消息实现提供独立消息与正文的存储边界，OpenRust 沿用本项目已固定的发布回执和重放关系作为回收依赖。新迁移拒绝在已出现正文墓碑时回滚。启用清理前，先升级所有可登记重放的进程。[Svix 固定消息源码](https://github.com/svix/svix-webhooks/blob/931467b95a1bbcc520c47bcb96f4e436782abcd2/server/svix-server/src/v1/endpoints/message.rs)

幂等墓碑期限、业务保留策略、普通 CONNECT 代理与跨主机部署尚待独立验收。

## 验收

SQLite、PostgreSQL 18.7 和 MySQL 8.4.13 均通过真实 HTTP、Artisan 与独立 Worker。覆盖无订阅消息、活跃首次投递保护、终态但仍可重放的旧快照保护、原始快照已清理但重放待发或仍可读取正文、原正文与 HMAC、范围隔离、预演和游标、并发回收与同键发布、同键异正文冲突、清理后拒绝重放和迁移回滚。测试用隔离 SQL 回拨保留期时钟；迁移也在存在原有发布和投递时回滚并重跑。SQLite 的原有扇出与诊断回归通过。Rust 1.94.0 格式检查、发送包九项合约、六组三语示例和受影响目标严格 Clippy 通过。
