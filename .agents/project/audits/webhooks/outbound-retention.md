# Webhook 出站快照与尝试留存

`DeliveryStore::prune` 和 `webhook-server:prune` 复用终态、范围和有界批次清理。快照保留期从投递截止时间起算，避免升级前的记录依赖不存在的完成时间。尝试记录单独按实际完成时间清理。只有已进入终态且无租约的投递可被选中，删除或更新时再次判断资格。预演不写库，命令每批 1 至 500 条。过期快照留下投递 ID、幂等摘要、状态和清理时间，清理后的同输入提交仍返回原 ID，异输入仍冲突。诊断显示 `payload_pruned_at`。[Laravel 固定 Prunable 源码](https://github.com/laravel/framework/blob/1449bf241017087fbd38c118ecaabef3f6797fdc/src/Illuminate/Database/Eloquent/Prunable.php) · [Spatie 固定接收包清理范围](https://github.com/spatie/laravel-webhook-client/blob/ff886d1bae33d35ad98b6c91403f280df158129d/src/Models/WebhookCall.php)

新重放事务写入候选后锁定原投递并复核原始状态和清理标记，与快照清理串行。清理先提交时，候选重放整次回滚，不产生孤儿投递或消耗重放预算。已登记重放持有独立快照；若其引用共享发布正文，当前批次仍保留该正文。尝试历史删除不重置投递计数。含快照墓碑时迁移拒绝回滚，防止把缺失正文重新视为可重放。启用清理前先运行迁移并升级所有登记重放的进程。备份仍按独立备份策略处理。

SQLite、PostgreSQL 18.7 和 MySQL 8.4.13 均通过迁移、配置与路由缓存、真实 HTTP 登记、Artisan 预演／清理／重放与独立 Worker。测试用隔离 SQL 回拨记录时间，覆盖待处理保护、跨范围查询零候选、重复清理、批次上限、原快照和尝试的独立周期、同键去重及异正文冲突。并发反例在重放策略读取原快照后暂停进程，实际清理再恢复，核对事务回滚。另一条路径先登记重放，清理原快照后再由 Worker 实投并校验原正文及 HMAC。共享发布后清理单条投递快照，仍可读取原发布正文和相同回执。三库均验收旧投递保留时按路径回滚及重跑迁移，产生墓碑后拒绝回滚。SQLite 的既有出站诊断、重放与扇出套件通过。Rust 1.94.0 隔离工作区格式检查、发送包九项合约、三语六组示例及受影响目标严格 Clippy 均通过。

共享发布正文的最终回收、幂等墓碑期限、应用保留策略和跨主机验收仍跟踪。普通 HTTP CONNECT 代理保持开放。
