# Webhook 有界订阅扇出

## 发布契约

`EventType` 以事件名称及非零 schema 版本精确匹配。同一范围内的受管端点可订阅或退订。发布最多匹配 32 个端点，JSON 信封（`type`、`schema_version`、`data`）最多 1 MiB。消息、发布幂等键、确定顺序的投递 ID 和全部投递记录写入同一个数据库事务。`publish_in_transaction` 支持复用业务事务，并用保存点撤销整次失败的发布。无匹配订阅也保存回执。同范围、同幂等键和相同输入重试时返回首次回执。输入不同则报告冲突。

原始正文只持久化一次，投递保存带范围和内容摘要校验的引用。发送、定时补派和重放沿用首次发布的正文及消息 ID，每个端点使用自己的签名凭据。缺失或摘要不符的正文不得发出请求。订阅变化影响后续新发布，已记录的目标仍须经过首次发送前的端点版本及许可检查。队列恢复在事务提交后运行。启用发布前，部署到同一数据库的实例和 Worker 均需支持新增迁移及正文引用。

Svix 固定版本将消息及正文的持久化与后续派发分开，请求幂等键和消息标识也有各自的用途。OpenRust 复用这一职责划分，并按 WD-05 的本地原子性要求在同一事务内固定有界投递集合。此批使用数据库正文，未引入外部消息中继或远程对象存储。 [Svix 固定源码](https://github.com/svix/svix-webhooks/blob/931467b95a1bbcc520c47bcb96f4e436782abcd2/server/svix-server/src/v1/endpoints/message.rs) · [Svix 幂等文档](https://docs.svix.com/idempotency)

## 验收

SQLite、PostgreSQL 18.7 和 MySQL 8.4.13 均通过迁移、Artisan 配置及路由缓存、真实 HTTP 发布和独立 Artisan Worker 投递。覆盖并发同键发布、冲突、空订阅回执、版本和租户隔离、退订与在途事务并发、外层业务回滚、无效端点导致整组回滚、端点和正文上限、独立 HMAC、单目标失败与重试、共享正文重放及损坏拒绝。

现有发送和共享限额回归通过。接收基线的 136 个真实 HTTP 请求及 83 个独立 Worker 验收通过。Webhook Server 合约测试、三语收发文档示例编译、隔离工作区格式检查及受影响包和真实消费者的严格 Clippy 均通过。

运维批量命令、保留期清理、TLS 扩展及真实跨主机部署仍按 WH-04 至 WH-07 验收。本轮多进程运行在同一主机。
