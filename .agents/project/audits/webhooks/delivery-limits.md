# Webhook 出站共享限额

## 计数与恢复

`register_delivery_limits` 支持范围发送、单个具名端点发送和范围人工重放登记三种限额。相同具名端点的版本切换共用发送桶。范围桶同时覆盖直接 URL、同步投递、Worker、自动重试及重放发送。应用在共享数据库的节点使用一致的配置；固定窗口以首次成功保留时的数据库时钟开始。桶数据只含哈希、类别、计数和恢复时间。

采用现有数据库事务和条件更新。范围桶与端点桶同事务先后扣减，任一达到限额则回滚两笔额度；手工重放的登记额度与新投递及审计记录同事务提交。Webhook 的同步和队列入口共用实际传输前的检查，限额延期持久化到投递记录，不占用原始 HTTP 尝试。准许后的传输错误或宕机保守保留已用额度。Laravel 的队列限流提供等待再执行的参考；现成队列 release 会计入队列尝试，因而这里把延期落在已有 Webhook 投递状态机。按应用与端点分别限流的职责参考 Svix。[固定 Laravel 队列基线](https://github.com/laravel/docs/blob/960eedf0911155ad16326ade49c0ea5d18eda0b8/queues.md#rate-limiting) · [Svix 端点限流](https://docs.svix.com/throttling)

## 实际验收

Rust 1.94.0 隔离源码叠加 Webhook 至 `5f3725583` 及本批文件。项目磁盘守卫清理停线产物后重新构建。SQLite、PostgreSQL 18.7、MySQL 8.4.13 使用真实 HTTP、Artisan 和独立 Worker 检查范围和端点组合扣减、两个使用独立本地目录与配置缓存的 Artisan 进程争额度、范围隔离、旧版本替换后继续共用桶、窗口恢复、自动重试历史、并发人工重放登记及重放发送重新计入范围。窗口边界用隔离数据库推进精确验证，限额延期夹住原截止时间。首轮争用在 SQLite 出现多记尝试、MySQL 返回存储失败。改为先取得计数桶写锁、再验证持有的租约，并将前一次尝试的写回收窄到唯一键。SQLite 重复实测仍偶发存储错误，随后让有端点绑定的完成事务在读取前取得写锁，以避免升级过时的读快照。最终三库矩阵通过，其中 SQLite 连续重复三次。出站、端点处置、定时恢复和接收回归通过，接收包含 136 个 HTTP 与 83 次独立 Worker。八个包测试、三语六组示例、全仓格式与双特性 workspace/all-targets 严格 Clippy 通过。原始日志位于 `target/tmp/webhooks-limits/`。

[订阅有界扇出](subscription-fanout.md)已接入。批量重放、限额状态和业务记录清理、正式跨主机拓扑及其他 WH-04 至 WH-07 门禁仍开放。
