# 接收状态与处理尝试查询

Webhook 计划的运维入口包括按接收 ID 查询和分页。复用出站诊断的范围绑定、光标和单行 Artisan JSON 契约。`DatabaseWebhookStore::inspect_receipt` 从主写连接读取接收摘要，`inspect_processing_attempts` 按处理代次读取最多 100 条。尝试查询使用已有接收范围和代次索引。租约有效性使用数据库时间。未启用租约的已处理记录仍可能是 `received`，`failed` 表示当前有异常记录并且没有完成、终止或延期状态。

两种查询仅选择诊断字段，不读出请求正文、URL、Header、异常详情、签名凭据或领取令牌。摘要返回 `has_exception` 布尔值。不存在或不属于范围的记录返回 `null`，对应尝试分页为空。公开 `webhook-client:inspect` 可指定已授权范围和数据库连接。应用通过自己的授权入口调用相同公开服务。

## 验收

SQLite、PostgreSQL 18.7、MySQL 8.4.13 在真实 HTTP 接收、独立 Artisan 和 Worker 中验证收到、处理中、延期、完成、停止、租约过期和重试失败等状态。带授权的测试 HTTP 入口返回与 Artisan 相同的摘要和尝试页。错误范围及无权限拒绝、未知记录、具名数据库、分页边界和超大游标通过。注入保存在数据库中的异常内容，确认查询只报告存在标志。失败回调、缓存、旧令牌、接管及跨后端恢复随原接收套件回归。接收包契约、应用和包的严格 Clippy、三语文档构建与浏览器检查均通过。
