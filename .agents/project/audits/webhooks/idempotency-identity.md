# Webhook 幂等键与持久投递 ID

请求键是有范围的去重入口，发布消息、投递、重放和队列任务继续使用各自的持久 ID。参考 Svix 区分请求幂等键与消息标识，并核对 Stripe 对过期请求键重新登记的行为。OpenRust 继续由投递快照或发布输入的指纹检查同键输入是否相同。 [Svix 幂等](https://docs.svix.com/idempotency) · [Stripe 幂等键期限](https://docs.stripe.com/api/idempotent_requests)

新写入通过 `webhook_idempotency_keys` 绑定键摘要与独立生成的记录 ID。表内保存摘要、范围、类型和目标 ID。直接登记和发布各自命名，范围仍隔离；新映射与初始记录及扇出在同一事务提交。直接登记在调用者事务中以保存点撤销失败的操作。首次重试旧版的确定性键时，映射绑定旧 ID 并返回原结果，已登记的 Worker 及正文引用仍按原 ID 工作。新投递 ID 继续使用 64 个十六进制字符，调用者使用返回的 ID。

这批铺好幂等期限的身份基础，当前映射仍保留。后续需实现到期释放、旧确定性键回退禁用及历史记录的独立保留。本批前先迁移并停止旧版本写入方，因为旧写入代码不会查询新映射。在还有映射时迁移拒绝回滚。

## 验收

SQLite、PostgreSQL 18.7 和 MySQL 8.4.13 先用升级前二进制运行迁移并通过真实 HTTP 生成直接投递和带订阅的消息，再保留数据库、切换新二进制、运行迁移与配置／路由缓存。三库覆盖并发旧键补登记、新键首写幂等、异输入冲突、事务取消时映射随记录回滚、稳定原回执、新 ID 独立和有映射时拒绝回滚。新 Artisan Worker 实投旧直接记录和旧发布快照。SQLite 既有发送、扇出、人工重放与出站留存回归通过。

Rust 1.94.0 隔离工作区格式检查、发送包九项测试、三语六组示例编译及受影响目标严格 Clippy 通过。工作区达到 32 GB 停线后，守卫记录持锁清理净释放 93,207,805,952 字节，随后复跑上述检查。
