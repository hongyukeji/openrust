# Webhook 接收处理租约

本批实现 WH-03 / WD-04 的接收 Worker 领取。固定 Spatie Client `ff886d1bae33d35ad98b6c91403f280df158129d` 的 ProcessWebhookJob 以接收记录为业务入口。固定 Laravel 队列文档 `960eedf0911155ad16326ade49c0ea5d18eda0b8` 说明重新释放会消耗尝试次数，且任务超时应短于队列保留时间。OpenRust 保持这些原生队列行为，通过可选注册方法增加持久领取。固定来源及复用判断见[实施计划](../../plans/webhooks.md#131-补充调研与采用理由)。

新增迁移保存领取 token、执行代次、租约到期时间和完成时间。存储以接收 ID 和范围为边界，在数据库时钟下条件更新未完成且可领取的记录。一笔写入分配 token、推进代次并清除旧异常。成功、显式释放和业务错误均按持有的 token 和有效期限回写。竞争时通过原生队列释放，完成后的重复投递直接确认。数据库收件读取使用写连接，避免独立 Worker 从滞后的副本查不到刚提交的行。业务处理不占用存储事务，任意业务错误只写入固定诊断。队列任务序列化字段和 HTTP 响应不变。启用租约时必须给任务设置比租约短至少两秒的正数超时，并由应用配置更长的队列保留／可见性。

隔离源码基线 `4f19d7c29`，Rust 1.94.0，构建与验收经项目 build_guard。SQLite、PostgreSQL 18.7、MySQL 8.4.13 各通过现有 136 个真实 HTTP 请求和 83 次独立 Artisan Worker 运行，另各通过本批 3 个签名 HTTP 请求和 8 次独立 Worker 运行。实测主动释放后再次领取、两个进程消费同一记录的两份队列任务、完成后重复任务确认、处理器内退出 79 后在队列及租约到期前后由不同进程消费。检查数据库中的 token、代次、完成时间及队列清空。三库均回滚本批和前一载荷迁移，再运行迁移并读取升级前记录。旧签名、接收 HTTP／Artisan 和许可检查一并复验。

同一主机的多进程和同一数据库竞争已验证。外部 broker、跨主机及混合版本部署、专门的旧 token 迟到竞态、实际超时压力、租约续期、逐尝试审计、持久 Deferred 和 Scheduler 补偿仍待对应门禁。完整 WD-04 和 WH-03 保持开放。HTTP 入站去重另依赖可信事件身份，并且业务外部效果仍需自行幂等。

全仓格式、启用两个 Webhook feature 的 workspace/all-targets 严格 Clippy、三语六个 Rust 示例、文档站构建和根／子路径浏览器检查通过。站点构建仍报告既有体积提示。验收日志保留在 `target/tmp/webhooks-lease`，清理隔离数据库、临时应用及站点输出。
