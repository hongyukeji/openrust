# Webhook 关联就绪后主动唤醒

本批补 WH-03 / WD-02 的同库主动唤醒。应用关联业务记录后调用 `QueuedWebhookJob::wake_deferred`，传递可信 scope 对应的存储、当前应用的 QueueManager 与接收 ID。沿用[固定 Laravel 队列的具名连接及队列契约](https://github.com/laravel/docs/blob/960eedf0911155ad16326ade49c0ea5d18eda0b8/queues.md)及现有同库事务派发。首次延期保存原处理器、连接、队列与任务选项，快照只保存队列元数据。应用无需再选择执行者或切换队列。

唤醒在同一事务条件推进就绪时间并写原生任务。条件要求记录仍在等待、期限内、没有租约并属于可信 scope。并发调用只有一次成立。入队失败回滚时间，原定延迟值保留。原定时任务和主动唤醒生成的任务共用领取和代次规则。领取后清除路由快照，已终结的原任务日后到达直接确认。此前已延期但尚无队列快照的旧记录继续按原定时机消费。

验收夹具通过真实 HTTP 接收通知并在独立 Worker 中持久延期。模拟关联就绪，从两个 Artisan 进程竞争唤醒。复验错误范围、缺队列表时回滚、提前执行、完成后重复唤醒，以及原定时任务迟到。测试用 Artisan 命令归应用夹具，包提供公开 Rust 入口。

隔离源码使用 `4f19d7c29` 加本任务已验变更至 `d987d7fa9` 及本批文件，Rust 1.94.0，构建与验收经项目 build_guard。磁盘守卫在其他构建安全停下后取得锁，执行项目编译产物清理，本批使用同一项目内目标目录冷编译。日志在 `target/tmp/webhooks-wake`。跨后端扫描和补偿、真实审核方关联、跨主机仍待独立验收。

SQLite、PostgreSQL 18.7、MySQL 8.4.13 每库通过 159 个真实 HTTP、110 次独立 Worker 和 5 次唤醒命令。相比前批新增 1 个 HTTP、3 次 Worker 及唤醒命令。首次迁移、回滚六个扩展迁移后重建及旧数据读取通过。现有签名、接收 HTTP／Artisan、许可回归、全仓格式、两个 Webhook feature 的 workspace/all-targets 严格 Clippy 通过。三语 Rust 示例、站点构建、根／子目录三语浏览器与导航通过。站点保留既有体积提示。本批隔离应用、数据库和站点输出已清理。
