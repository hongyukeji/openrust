# Webhook 过期附件与暂存补偿

本批补 WC-10、WC-12 的数据库与对象清理边界。接续[私有 Storage 附件引用](attachment-storage.md)及[接收记录保留期清理](retention.md)，沿用固定 Spatie Client `ff886d1bae33d35ad98b6c91403f280df158129d` 的终态保留策略。OpenRust 使用现有 Storage 接口回收 multipart 对象。

清理过期终态记录时，磁盘对象的解除引用与暂存登记在同一事务提交。候选选择和实际删除都核对范围、终态时间及处理令牌。登记插入失败时回滚接收记录删除。内联正文继续走有界批量删除。

新增 `webhook-client:prune --scope=<scope> --attachment-staging`。可与 `--database`、`--limit` 或 `--pretend` 一起使用。每批最多 500 条，先按数据库时钟领取已解除引用或暂存超过一小时的记录。一次领取持有 60 秒租约，单次 Storage 删除超时为 15 秒。领取令牌阻止晚到的接收事务提交该对象引用。删除失败保留登记并令 Artisan 以失败状态退出，租约到期后可重试。成功删除后只允许持有对应令牌的清理者移除暂存行。接收记录保留期设为 `null` 时，独立附件清理仍可运行。

## 验收结果

使用项目构建守卫，在隔离源码中以 `4f19d7c29` 和已验 Webhook 批次至 `eb324bfbb` 加本批变更验收。SQLite、PostgreSQL 18.7、MySQL 8.4.13 每库通过附件场景的 7 个真实 HTTP 和 3 次 Artisan Worker。实际执行迁移、查询、预演、记录清理及对象清理。覆盖提交前进程退出、近期暂存保护、其他范围隔离、真实文件删除失败与租约重试、两个独立清理进程竞争、登记冲突时事务回滚、终态附件回收、活跃记录保护、保留策略关闭和迁移回滚保护。三库分别通过 136 次公开路由 HTTP 与 83 次独立 Worker，另通过接收租约、去重、延期唤醒、验签审计和接收记录保留期回归。

全仓格式检查、Webhook 双特性的 workspace/all-targets 严格 Clippy、三语六段公开示例、三语文档站及桌面／移动浏览器检查通过。已有接收、签名和许可证检查通过。日志位于 `target/tmp/webhooks-attachment-cleanup`。

本批使用同机共享私有本地磁盘。仍需远端驱动和跨主机并发验收，包括远端写超时后服务端迟到完成的补偿、磁盘缺失对象的删除语义及磁盘别名的一致性。WH-02、WH-03、WH-06 和整体目标保持开放。
