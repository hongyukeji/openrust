# 正式版分批交付计划

固定上游文档使用 [Laravel 13.x 快照](https://github.com/laravel/docs/blob/960eedf0911155ad16326ade49c0ea5d18eda0b8/documentation.md)。下表以依赖排序，三语导航保持上游目录顺序。表里的 OpenRust 路径链接到英文正文，简体和繁体使用相同的相对路径。链接指向既有正文入口，功能状态以实际验收记录为准。

## 每批怎样闭合

1. 先核对该单元的固定上游章节、源码与测试，再检查 `openrust-v0.x` 的对应实现。记录 Rust 适配、公开契约及需要拆分的差异。
2. 完成代码与必要的回归。用表中入口验收成功和失败行为，并按[项目规范](conventions.md#验收清单)运行 Rust 检查。
3. 同一批更新表中对应的英文、简体和繁体正文。实际运行文档里的示例和命令，检查三语导航、链接和站点构建。
4. 在[项目进度](progress.md)按单元编号记录源码基线、文件范围、实际命令、环境和结果。整单元闭合状态见[核心功能闭合对账](audits/core-closure-ledger.md)，本轮资源阈值与授权见[当前交接](current.md)。

同一页面可分多批补齐。每批只关闭已验收的段落。该页所有关联单元均验收，且 PHP 专属或未纳入范围的内容已有明确映射或范围说明后，才关闭整页。表中锚点是该批的主要对照入口。验收前核对同一页面其余章节，遇到额外契约就分出单元或记录范围决定。

第一代必须交付 API 交互及下列 API 相关扩展，不能因其属于扩展包而整体后置；其余范围待确认的生态入口继续放在[逐页对照表](plans/laravel-docs-delivery-map.md)。每页先确认移植、Rust 对应方案或文档说明，再为选中的实现登记独立验收单元。Browser Tests 每批可用实际浏览器验证，Dusk 包的范围单独确认。

## 应用交互式初始化

<a id="artisan-init"></a>
<a id="install-full"></a>

2026-11-19 用户最新确认：统一使用 `artisan init`，取消之前的 `install:full` 命令，也不保留为别名或第二个公开入口。完整安装能力并入初始化流程，各模块单项安装命令继续保留。此决定覆盖此前命令命名及同时保留两个入口的建议。旧 `install-full` 锚点仅供既有文档链接继续定位，不表示保留命令。本项尚未完整实现及验收；状态和证据并入[版本验收清单](audits/core-closure-ledger.md#v010-acceptance)。

### 命令与安装范围

- 正式入口为 `./artisan init`；Windows 为 `artisan.bat init`。沿用同一 Artisan 命令分发机制；不增加 `install:all`、`setup` 等同义入口。
- 命令是 OpenRust 的便捷扩展，组合各模块正式安装流程，不改对应固定 Laravel 基线的迁移、发布、配置、路由或认证契约。保留全部单项安装入口，提取共享安装服务，不能递归启动各安装命令造成重复提示或重复构建。
- 发布前明确并公开 v0.1.0 的完整安装清单：API 与 Sanctum、Passport／OAuth2、第一代已确定的认证辅助扩展、广播／Reverb、gRPC，以及其他确需发布资源的已交付模块。按依赖登记，不盲目安装全部第三方包；未就绪的必需项必须明确报告，不能跳过后宣称完整安装成功。
- API 配置、路由及受保护入口仍按需生成，保留 `API_PREFIX`。Sanctum 和 Passport 都安装时不得擅自替换已有路由的守卫；需先确定并验收共同安装方案。OIDC／SSO 的范围沿用第一代 API 扩展计划，不将 Passport 等同于 OIDC。
- 安装不等于自动启动所有监听器或配置外部账号。运行方式沿用主应用与可选独立进程的既定边界；厂商凭据由开发者提供，缺失时明确说明哪些能力未配置。

### 交互式引导与配置

- **最终体验与验收目标（2026-11-19 用户再次明确）：** 开发者执行 `./artisan init`（Windows 为 `artisan.bat init`），只需跟随引导完成必要选择及配置，随后直接执行 `cargo run` 即可正常启动应用，无需手动补装、补注册、生成密钥或另跑迁移。能自动处理的安装、配置、构建和迁移统一处理，只询问必要信息，不让内部模块拆分增加操作负担。连接或步骤失败时明确指出具体问题并允许修正；仅当所选配置确实满足启动条件才提示初始化成功。用干净项目的实际初始化、启动及 HTTP 请求证明该目标，不能仅以 list/help、只读计划或前置阻断测试作为交付完成。
- `artisan init` 默认进入交互式向导，提供推荐配置和自定义配置。依次引导应用名称、地址、时区和语言，数据库类型及连接，缓存、Session、队列驱动，邮件与短信驱动，以及 API 认证和实时服务设置；只展示实际支持并可验收的选项。
- 数据库、Redis 等共用连接参数只填写一次并复用；提供连接检测，失败后可重填或明确退出。邮件与短信开发默认使用日志驱动，外部供应商由开发者填写凭据。
- 读取现有配置作为默认值，用户明确选择修改时才更新对应键；未选择修改的值和密钥保持原样。`.env` 缺失时按项目示例生成，APP_KEY 缺失时调用原有密钥生成机制；确认前只展示脱敏汇总，密码输入隐藏，不把凭据写入日志。
- `--no-interaction` 从既有环境和配置读取，不依赖终端提问；缺少必要信息时非零退出并准确提示。`--dry-run` 不保存配置、不生成密钥、不构建和迁移，不做有副作用的外部操作。
- 配置确认后调用共享安装服务完成完整功能安装、统一构建和迁移，验证启动条件，最后显示 `cargo run`。不自动启动长期服务；缺少外部服务或账号时分别报告待配置与阻断项，不误报全部就绪。
- 重复运行进入检查与补全流程；验收确认从全新项目完成向导后可直接启动应用，已有项目运行向导不损坏原配置及业务数据。

### 文件、迁移与执行流程

1. 预检项目、工具链、依赖和已安装状态，按上述向导读取、验证并确认配置，显示安装范围及冲突。
2. 按依赖安装并发布正式资源，更新 Cargo 特性及编译注册。迁移文件内容、命名、时间戳、顺序和账本沿用对应模块的固定上游机制及已确认的项目适配，不创建初始化专属合并迁移、不重复发布迁移、不改已有迁移账本。
3. 文件与依赖调整完成后统一重建，避免每个安装步骤重复编译。第一版面向有源码和 Rust 工具链的项目；发布二进制若不能修改编译特性，应明确前置条件，不假装仅靠生成文件即可启用代码。
4. 汇总待迁移并统一询问，调用原有迁移入口。保留生产环境确认与保护，不把无交互当成生产迁移授权。
5. 输出已安装、已存在、失败、冲突及待配置项目，并给出验证和继续操作说明。

### 选项、重复执行与失败行为

- 首版规划 `--force`（覆盖与生产确认见下条）、`--dry-run`（只读展示计划）、`--without-migration`（安装并重建但不执行迁移）、Artisan 通用 `--no-interaction`（不询问）。无交互时未获得所需明确授权的步骤应跳过并报告或明确失败，不能等待输入或绕过生产保护；实现前固定各路径的退出码及最终成功条件。
- 2026-11-19 用户明确要求首版支持 `init --force`，覆盖此前不提供该选项的建议。按各安装器原有契约覆盖安装清单内可发布的资源及脚手架；迁移步骤向原入口传递 `--force`，允许生产迁移免确认。默认保留并报告冲突，`--dry-run --force` 展示确切覆盖计划。不得借此任意删除目录、重置数据库、重复发布迁移或轮换已有密钥；各安装器同名选项含义不同的必须显式映射并验收。
- 重复执行只补缺失内容，不重复注册、复制迁移或重生成现有密钥。状态以实际文件、Cargo 配置及迁移账本为准，不新增容易失同步的持久安装状态数据库。
- 必需步骤失败返回非零退出码，停止依赖它的步骤，保留已完成内容并说明重试方法。统一安装命令可以有自己的汇总失败退出码，但不能改变单项命令原有行为。
- 迁移失败不自动删脚手架、不擅自回滚旧批次。密钥和凭据不得输出到安装日志。

此前旧命令的实现与验证保留在[历史在途记录](audits/00-03/install-full.md)，仅证明其当时范围。当前入口、测试和三语文档已迁到 init，MySQL／Redis／终端／HTTP、Reverb 随主应用启动、SMTP 连通预检、短信凭据引导及指定环境文件的证据见[初始化验收](audits/00-03/init.md)。2026-11-20 已接通 api／broadcasting／reverb／grpc 扩展选择与依赖补全，`--extensions=all` 会列出尚未就绪的第一代发布项并在写入前拒绝；Windows 44 项回归、ConPTY 隐藏密码／失败取消及补充 Clippy 通过，详情沿用同一验收记录。Passport 等认证扩展的实现及共享安装器、真实邮件／短信供应商投递仍未闭合，不能据此将整个完整功能集标记完成。

### 补充安装契约

- `.env` 默认只追加缺失项，已有值仅在用户明确修改对应项后更新；`--force` 本身不能重置账号和密钥。配置组及辅助方法注释遵循项目中文注释规范。
- 完整安装默认 `/user` 使用 `auth:sanctum`，Passport 使用显式独立守卫；不得覆盖已有自定义路由认证。
- 单项安装与完整安装交替执行必须互通；新版本补新增步骤，不把升级等同强制重装，不重写历史迁移。
- 同一项目的源码安装操作使用同一互斥锁，并发安装明确失败，不无限等待；中断后文件锁自动释放并可重试。
- 分开报告安装完成、迁移待执行、外部服务待配置、冲突和失败；必需步骤未完成不能输出完整安装成功。各状态与退出码在实现中固定并测试。
- 2026-11-19 用户授权开始开发。现有单项路由安装器可复用；Passport 目前仅部分安装资源就绪，不能绕过前置条件。先开发可运行的只读计划、阻断检查与共享源码安装并发保护，再随前置安装器闭合接通完整执行；这不是完整命令已交付。
