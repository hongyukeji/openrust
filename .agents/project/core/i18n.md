# `openrust::i18n`

> 受众：AI Agent
> 更新：2026-10-26
> 摘要：请求级国际化当前事实；contract 见 [ADR-032](../decisions/adr-032-request-internationalization.md)。

## 实现

- `Locale` 规范化常见 BCP 47 language/region/script 标签；`I18nConfig` 属于 `FrameworkConfig.i18n`，由 `[i18n]` TOML 与 `APP_I18N__*` 配置。
- `MessageCatalog` 内置英文与简体中文框架消息；应用可通过 JSON 字符串或 `insert` 合并/覆盖 locale 下的消息，不依赖额外运行时库。模板仅支持 `{name}` 字符串替换，缺参原样保留，缺失 key 原样返回。
- `I18nPlugin` 安装不可变 `I18n` service。HTTP response-context middleware 从 `Accept-Language` 按 q 值与受支持资源选择 locale；默认语言由 `[i18n].default_locale` 配置。配置 fallback 用于当前 locale 缺少消息键时查找最后资源。
- 请求语言存于 Tokio task-local，不是进程级可变状态。`RequestLocale` 可提取当前选择；`I18n::with_locale` 为认证后的用户偏好或后台任务建立显式覆盖作用域。
- 中英文资源覆盖框架 `ApiResponse` 成功消息、标准框架错误和内建 validator rule code。稳定 error `code`、HTTP status 与 validation field path 不变；未提供翻译的 application `Custom` 错误保留原展示文本，所有 5xx 仍隐藏来源。
- 邮件/短信内容由应用在 compose 前用共享 `I18n` catalog 生成；请求邮件使用 `RequestLocale`，后台消息显式选择 `Locale`。传输层不自行推断语言。SMS driver 暂未实现，实际集成归通信能力功能簇。

## 边界

不提供 Fluent 语法、复数选择、日期/数字地区格式化、自动 Session 用户偏好读取、自动邮件/SMS 发送 locale、HTML 转义或完整 Accept-Language 浏览器质量范围解释。应用负责资源装载和模板输出上下文转义。`*` 请求语言退回应用默认语言。

## 验收

- 6 项 i18n 单测覆盖 canonicalization、q 值排序、无效标签、JSON resource、覆盖、参数和 fallback、并发隔离、TOML section。
- `apps/server/tests/i18n.rs` 覆盖同一 router 并发中英错误消息、validator rule 本地化、code/path 稳定、未知 application error 保留原文、request locale、显式 locale 覆盖和应用 JSON resource 的 HTTP 调用。
- 新生成项目 `/tmp/openrust-i18n-generated-20261026` 的 `cargo check` / `cargo test` 通过；真实进程请求带 `Accept-Language: zh-CN` 的不存在路径返回 `code=not_found` 与 `请求的资源不存在`。
- 全工作区 default/all-features fmt/clippy/test、warnings-denied docs 和 `cargo deny check` 通过。详见 `memory/testing.md` 与 `memory/verification.md`。
