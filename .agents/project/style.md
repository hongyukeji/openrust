# `.agents/project` 文档风格

> 受众：AI Agent
> 摘要：第一方文档、代码注释与开发者说明的语言规范，以及文档写作、命名和清理规则。

## 语言规范

本框架以简体中文开发者为优先受众，**简体中文为主，英文为辅**。本节是项目文档、代码注释和开发者说明语言的唯一维护入口。

- 第一方 README、使用/贡献/安全说明、变更说明、Agent 文档、未来 `docs/`、Rustdoc（`///`、`//!`）、普通源码注释、配置/脚本注释、Cargo 元数据描述、示例及生成模板中的说明默认使用简体中文。根 `README.md` 及各模块默认入口本身提供中文，不把中文仅放入可选翻译文件。
- 新增或修改上述内容立即执行；既有英文说明按 `todo.md` 分批整改为清楚、自然的简体中文，保留原有条件、失败语义和边界，避免机械直译。整改状态以实际文件与验证为准，不以规范已写入代替完成。
- 英文用于必要术语、标准名称及辅助对照，首次出现可写“中文说明（English term）”；不要求每段或每条注释维护中英双份。完整英文文档在框架成熟后再评估，不属于当前 v1/可选快速开发模块 必交付范围。
- API/类型/函数/变量、package、路径、命令及参数、配置键、错误码、协议字段、URL 保持技术原名；示例代码行为、Rustdoc 链接目标、围栏属性、隐藏行及工具要求的标准标记保持有效。正文和标题翻译后同步检查站内锚点与交叉引用。
- CLI 帮助中的解释文字采用简体中文，保留命令/参数语法；由注释派生的帮助文本纳入相应命令和快照验收。普通注释整改不顺带改运行时日志、错误字符串、协议载荷或默认 locale；运行时多语言仍由既有 i18n 契约处理，中英文资源和 fallback 保持可用。
- 生成物从 `tools/cli/templates/`、生成器源码及配置示例的源头整改，再更新对应快照与生成结果；不只翻译快照或某个临时生成项目。
- 许可证、版权声明、第三方原文、上游许可与标准摘录保留原貌，必要时另附中文解释；不要求改写依赖源码、自动生成的第三方内容、Git 历史或 `target/` 产物。
- 注释继续只解释必要的原因、边界与失败语义，不为满足语言规范添加冗余注释。英文残留扫描用于定位，逐项判断技术词或来源例外，不以禁止 ASCII 或统计中文比例代替语义审查。

## 基本原则

1. **只写当前事实**：描述现在的 contract、边界、状态和验证入口。
2. **一个事实一个权威入口**：正式使用说明在 `docs/`，Agent 上下文在 `.agents/project/`，完成历史在 Git。
3. **短而可执行**：优先表格、清单、命令和明确路径，删除背景叙事与执行过程。
4. **过期即更新或删除**：不建立“已解决问题”“完成任务”“逐日进度”归档。
5. **路径可解析**：相对链接必须存在；重命名和删除后使用 `rg` 清理旧引用。

## 文件职责

| 文件 | 内容 | 不应出现 |
| --- | --- | --- |
| `context.md` | 当前版本、阶段、模式、关键约束 | 历史过程、长验证日志 |
| `todo.md` | 可领取、可闭口、未完成任务 | `[x]`、最近完成、候选方向 |
| `plan.md` | 当前里程碑、优先级、crate 路由 | 归档任务正文、逐日进度 |
| `progress.md` | 当前交付与验证摘要 | commit 流水 |
| `roadmap.md` | 版本方向 | 当前执行任务、完成列表 |
| `plans/*` | 待开发详细方案、边界和功能簇 | 已完成副本、执行流水、与 `todo.md` 重复的活跃状态 |
| `core/*` | crate 当前事实和后续边界 | 聊天记录、逐次修复日志 |
| `memory/testing.md` | 当前测试入口 | 每次测试的重复输出 |
| `memory/verification.md` | 当前验收口径 | 过期问题报告 |
| `decisions/*` | 决策、原因、影响、状态 | 执行流水 |

ADR 只记录一个决策：状态、日期、背景、决策和影响。被替代时更新状态并指向替代 ADR，不删除决策文件。

## 命名

- 文件名使用小写 kebab-case；目录索引保留 `README.md`。
- ADR 使用 `adr-NNN-<topic>.md`，编号唯一；废弃决策标记 `Superseded` 并指向替代决策。
- 框架模块/工具的事实文件采用职责名，如 `core/http.md`、`core/cli.md`；既有 `core/test.md` 继续记录 `tools/testing/`，不为包身份变更机械改事实文件路径。
- 详细方案使用 `plans/<topic>.md`；进入执行时只把当前可闭口功能簇移入 `todo.md`。

## 写作格式

- 文档首行使用唯一 H1；开头用 1-3 行说明受众、更新时间和摘要。
- 路径、命令、配置键、类型名和 API 使用反引号；命令放带语言标记的代码块。
- 配置示例使用 TOML，API 示例使用 HTTP 或 shell，Rust 示例只保留理解 contract 所需代码。
- 不写聊天恢复提示、夸张表述、无证据的“生产可用”。

## 长度与拆分

| 文件类型 | 建议上限 | 超长处置 |
| --- | --- | --- |
| `AGENTS.md` | 300 行 | 通用规则下沉到 `conventions.md` 或 ADR |
| `.agents/project` 顶层文件 | 250 行 | 拆到 crate 事实或 ADR |
| crate 事实 | 300 行 | 正式 contract 下沉到 `docs/` |
| `plans/*` 与正式专题文档 | 600 行 | 按能力拆分 |
| ADR | 100 行 | 拆成多个单一决策 |

## 收口检查

文档改动默认执行：

```bash
rg -n '<旧路径或旧名称>' .agents docs AGENTS.md README.md
git diff --check
```

完成任务后：从 `todo.md` 删除，更新受影响 crate 事实和正式文档，提交可复验 diff。

## 开发进度汇报

- 每次框架开发进度汇报都附当时最新的能力状态总览表，至少包含“能力 / 状态 / 当前边界”，详细目标、缺口与证据链接到[唯一概览](progress.md#laravel-11-功能与进度概览)。沿用其✅、🟡、🔵、📝、⬜、⛔图例，不另建状态体系；普通问答不强制附表。
- 汇报前依据当前代码、Git提交、todo与实际验收更新状态，不照搬上次表格。已验收子范围、未提交实现和整项未完成须分清，不把定向测试/规划当交付，不提供无可靠分子的整体百分比。
- 面向开发者统一表述目标为“**1:1 的 Laravel 框架 Rust 版**”，不用含糊的“Laravel完全体”。这是目标描述，不表示当前已经全部实现；正式架构范围仍为Laravel + laravel-modules，按[ADR-070](decisions/adr-070-laravel-first-rebuild.md)及固定矩阵执行，不缩减模块化或行为验收要求。
- 项目标题、简介和宣传文案中的组合名称使用“Laravel + Laravel Modules”；正式包名、依赖标识、源码路径与来源链接仍使用 `laravel-modules`，不改写第三方技术标识。
