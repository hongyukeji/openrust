# 工程规范

> 设计替代：目录、命名、CLI、响应/认证默认值按 [ADR-001](decisions/adr-001-framework-principles.md) 重新设计；下文区分当前实现与新目标，不能以目标描述代替实现验收。代码安全、验证、WIP 与 Git 规则继续有效。

> 受众：开发者与 AI Agent
> 更新：2026-10-28
> 摘要：OpenRust 框架代码、测试、文档与 Git 提交规范。

## 代码

- Edition 2024；MSRV 写入 workspace `rust-version`，为当前 stable 减两个小版本，CI 单独验证。
- 所有 crate `#![forbid(unsafe_code)]`；库 crate `#![deny(missing_docs)]`，公共入口类型附带可运行 doctest。
- `[workspace.lints]` 启用 `clippy::all` + `clippy::pedantic`；显式 `#[allow]` 必须注明原因。库 crate 拒绝 `unwrap_used` / `expect_used` / `panic` / `todo` / `unimplemented`；测试与 `cli` 二进制可放宽 `unwrap_used` / `expect_used`。
- 错误：库 crate 用 `thiserror`，`anyhow` 只出现在二进制边界；所有面向 HTTP 的错误最终进入 `openrust::Error`。
- 异步统一 tokio；静态分发 trait 优先原生 `async fn`，需要对象安全或异构注册时按既有 contract 使用 `BoxFuture`；跨任务 future 保证 `Send`，不为形式统一重写已定公开接口。
- 宏只做派生与属性标注，不改变控制流；宏支持代码放 `__private` 模块并 `#[doc(hidden)]`。
- feature 只做加法；已实现的名称以 `Cargo.toml` 为准，如 `db-postgres`、`db-mysql`、`auth`、`queue`、`queue-redis`、`http-client`、`mail-smtp`、`sms-twilio`、`encryption`、`signing`、`test-util`。计划中的 `storage-s3`、`otel`、`metrics` 等在能力落地时加入，不预建空 feature。
- Rustdoc、代码/配置注释和 CLI 解释文字遵循 [语言规范](style.md#语言规范)：简体中文优先，技术标识符保留原名；从生成器源头保证生成说明使用中文。
- 不写 `TODO` 注释；活跃任务进 `todo.md`。注释只解释非显然的原因、触发边界、失败语义或安全约束。

## 命名

- 产品身份保留 OpenRust；应用名称、数据表、配置和目录按 Laravel 心智模型与实际职责定稿，不为保留历史前缀增加兼容层。
- 当前包/模块以 Cargo.toml 和源码为准；未来目录与默认命令按 [全面重构计划](plans/laravel-rebuild.md) R1 验证后落地。此规范不宣称新 API 已实现。
- 类型/trait 使用 PascalCase，方法/变量/模块使用 snake_case；优先保留 Laravel 用户熟悉的概念，Rust 语言语法遵循生态惯例。
- 第一方生产源码、应用默认接线和生成源码模板使用职责或行为命名。类型、枚举、模块和文件、函数、配置键、错误码、运行输出及普通实现注释不得使用上游品牌词作为 OpenRust 命名。上游依赖的真实名称、对照测试与夹具的真实来源、许可证和版权声明须保留。设计和用户文档仍应准确标注上游出处。更名时同步公开调用方、模板和回归测试，保留业务行为及数据和协议语义。

## 框架规范

新目标按 [ADR-001](decisions/adr-001-framework-principles.md)；各功能簇先定公共 contract，再迁移所有调用方/模板/测试。旧 ADR 的行为事实作为回归输入，不能用旧命名禁令否决新设计。 Laravel官方有对应时，按其概念、命名、配置、默认行为、生命周期和公开扩展契约实施；官方没有时优先优秀Laravel生态，再参考成熟跨语言设计，仍接同一Laravel机制，不为下划线机械一致另造协议。用户明确批准的差异保留并分类记录，不擅自改掉。

### API 速查

- 目标以语义 HTTP 状态为默认；HTML、JSON Resource、redirect、stream、文件下载均有清楚语义。旧 ApiResponse/always_ok 仍是迁移前实现，不作为新接口强制规则。
- Resource 输出须支持授权、敏感字段排除、关系/分页；响应格式和错误 schema 按 R3/R5 定稿并测试。
- HTTP 协议边界保持正确：CORS、HEAD、204/304、流式响应不能套错误的统一包装；request ID/日志和错误渲染脱敏。

### 能力接入根集成宿主

- 新能力在同簇接入当前可运行应用、公共 API 测试和生成项目；迁移目录时保留原根 server 的集成验收职责。
- 外部服务和密钥能力须显式配置，实际验证 feature、provider/迁移注册与运行入口，不以声明替代装配。
- 测试、模板、示例、部署脚本和 CI 跟随目标目录迁移，不能只改框架源码。

### 普通业务模块布局

本仓唯一综合示例为 modules/example；根 app 可正常开发应用业务，也可按需使用 modules/<业务>，遵循 [ADR-001](decisions/adr-001-framework-principles.md)。以下是有实现才采用的职责约定，不是要求预建整棵空目录：

| 位置 | 职责 |
| --- | --- |
| mod.rs | 模块声明与接入导出，不堆放业务实现 |
| providers/ | 业务公开注册；当前使用真实 Plugin API，R2 后统一 ServiceProvider |
| routes/api.rs、routes/web.rs | 模块路由定义与组合 |
| http/controllers/ | 请求处理与业务调用 |
| http/requests/、http/resources/ | 输入 DTO/校验与输出资源 |
| models/、services/ | 实际实体与确有需要的业务编排 |
| database/migrations/、database/seeders/ | 模块专属迁移与种子 |
| resources/views/ | 模块视图与其他实际资源 |
| jobs/、events/、listeners/、notifications/ | 相应真实异步/事件业务，按需创建 |
| extensions/ 或既有 extensions.rs | 公开 driver/Plugin 扩展示例 |
| tests/ | 模块专有测试与 fixture |
| proto/、generated/ | 仅实际 gRPC 示例需要的协议与已生成代码 |

模块只保留实际业务与专属资源，不复制 app/bootstrap/main/Cargo 完整骨架。除 modules/example 外均为框架通用结构和代码；应用 Provider/模块清单及 Rust 编译声明是公开接入入口，根其余职责只提供通用加载/公开挂载，不加入样例逻辑、专有 build.rs 或 build 依赖。框架核心不反向依赖业务。

新能力在同功能簇同步 modules/example 实际调用/扩展与测试；文档或独立 consumer 不能替代综合模块覆盖。当前 Plugin 不是 Laravel ServiceProvider 等价声明，R2 收敛 register/boot 时统一迁移，不能形成双内核；provider 不替代 Cargo 依赖解析。

### 起名前三问

1. Laravel 中对应的概念和典型调用是什么，开发者能否直接找到它？
2. Goravel 如何跨语言表达，Rust 的类型/所有权/异步如何自然落地？
3. 名称和签名能否清楚表达职责、错误、资源与生命周期，而不要求用户猜隐式状态？

允许 ServiceProvider、Mailable、Factory、Seeder、Guard、disk 和冒号命令；普通 Rust 方法使用 snake_case。新增公共 contract 写入对应计划、矩阵或 core 事实文档，保持唯一方向 ADR，不继承旧命名禁令。

### 两层分工

| 层 | 目标 | 参照 |
| --- | --- | --- |
| 应用布局、术语、配置与命令 | Laravel 使用者可快速找到入口、完成工作流 | Laravel 为首要依据，Goravel 为跨语言参考 |
| 类型、trait、资源与执行 | Rust 类型安全、显式 async、可靠并发与工具支持 | Rust/Cargo、成熟运行时与库；语言差异写明理由 |

已有能力允许复用、适配或重写，但一个职责最终保留一套公共机制。依赖和 feature 变更同步 stack.md；旧接口删除后扫描全部调用方，不为了消除编译错误丢弃行为测试。

- 设计与静态自审先明确值/机制的所属领域及唯一权威来源；真实依赖读取最终有效配置，默认继承与显式独立覆写分开。去重不能仅抽常量，不能重复求值副作用或靠调用方记得同步多处；覆盖、缓存及资源生命周期也须一致。
- 通用装配依赖公开能力契约，具体driver差异留实现侧；区分源码编译、发现注册、运行激活与实际能力。新增既定实现不应散改业务入口，但不承诺连接trait自动提供迁移/锁等全部能力，不为假设场景预造通用引擎。
- 应用可编辑策略在所属config完整可见，bootstrap/config/tests/Provider/模块状态各守职责；Rust语法允许不等于开发体验合理。必要语言适配仍按固定官方contract提供具体理由与等价证据，不用这些原则另立方向或豁免默认/安全语义。
- 一个实例暴露根因时核根宿主、同类领域、唯一模块、模板与公开consumer传播；修真实源头，按归属重生成副本，历史证据及固定fixture保真。高价值验收包含只改所属默认/环境覆盖/新增实现后下游应跟随，以及独立覆写、非法输入、缓存重启和生成项目；不以字符串清零或并行数量证明完成。

| 场景 | 新目标/继续有效的工程规则 |
| --- | --- |

## 验证

### 功能簇提交前集中验证

当前开发、验收和交付统一归 Lead 总控对话。互不重叠的已授权任务可在该对话内由子智能体协作。Lead 在项目内调度 Cargo、真实服务和适用 main 门禁，核对精确源码树后提交并推送。既有独立任务只收取在途结果，保全独有源码、索引与回执后退役验收副本。

簇层级固定：能力族≠可独立交付的完整行为簇≠单方法/修复。开工固定簇ID、边界、上游与退出清单；源码/配套、Laravel逐项对照、适用运行验收、限定本地提交及资源交接全部满足后，主控才领取下一主线簇。已完成簇保持稳定事实，后续新缺陷/需求另建关联整改，不用同名反复完成/开发；上层能力族继续列未完成项。报告固定列簇ID/边界、编码、对照缺口、验收、commit、下一簇。并行owner可在互斥文件推进独立ready簇，不扩大当前冻结输入。

- 冻结源码SHA不单独证明复用target内的二进制来自该输入。负对照/探针与正式构建共享target时，恢复源码却保留旧mtime可能命中旧变体；相对dep-info路径也不能证明旧产物已被覆盖。正式接续前保全旧exe/指纹，受控刷新正式构建入口mtime或采用等价精确失效策略，保持源码SHA/mode、索引与运行夹具不变；记录实际Cargo packageId、target源路径、新exe/hash及能区分旧实现的回归结果。此为缓存身份校正，不把元数据刷新写成源码修复，不以全量clean或重跑掩盖原失败。

功能簇先按简短Spec固定官方来源与contract，再集中完成生产实现和所有配套代码；编码收齐后建立官方源码/测试→Rust生产链→配置/生成/唯一示例/文档→待运行验收映射，独立静态审查并批量修缺口，编码覆盖闭合才冻结集中运行。静态闭合只记冻结待验，实际适用门禁通过才记验收完成并提交。失败按影响修复复验；编译阻断、难定位故障或上游歧义允许最小typecheck/探针。边界始终为有限功能簇，不积成全部Laravel/整个ORM巨型WIP；在途冻结批次不重来、不追加后继拖延提交。

> 当前执行覆盖：本轮最新顺序：先收齐当前已在途 main 组合源码、调用方、模板、唯一示例和说明，冻结后一次集中适用验收，修复失败并通过后本地提交；不再追加新簇延长本批，也不以全计划最后测试无限推迟提交。随后处理今日尚未吸收的整改，再按 ADR-001 持续推进。未验证源码保持 WIP，旧证据不冒充本批通过；默认20%额度保留；构建产物累计达到 100 GB 或磁盘可用空间低于 5% 时，回收本项目全部可重建的编译产物，在途构建释放占用后也须清理，复测后继续。

- 默认先实现完整功能簇：源码、调用方、唯一示例、生成模板、测试代码与文档一并完成，再静态审查并登记ready_for_verify。实现期间不逐方法/文件反复执行测试、Clippy或整套门禁，不自动启动TDD；明确的类型/API编译阻断可运行一次最小必要`cargo check`诊断，记录原因，不扩成测试矩阵。用户另行明确要求TDD/回归实验时按该范围执行。
- 总控将代码稳定、写入者已交接的功能簇排入验证窗口；先fmt/廉价静态检查，再模块与新增行为定向测试，最后按变更范围执行集成、MySQL/网络/生成项目与完整门禁（其他数据库运行转发布矩阵），尽早发现廉价失败，不边改公共接口边跑整套验证。已有在途命令自然结束并收取结果，不为切换流程强杀他人构建。
- 独立任务分支提交前执行本簇适用fmt/Clippy、单元/契约测试、受影响consumer，以及必要真实后端/生成项目验证；记录未覆盖的main组合门禁，不将分支交付标成完整框架验收。main集成保持串行，在可审阅的集成结果上执行AGENTS规定的workspace fmt/Clippy/tests/docs及适用feature/MSRV/deny、MySQL/真实服务和生成验证（其他数据库运行转发布矩阵），通过后才创建集成本地提交。直接在main开发的功能簇同样提交前执行完整适用门禁，不先提交未验收代码。
- 失败后先修复，再重验失败目标与实际受影响范围；只有源码/依赖/编译feature/模板/配置或环境变化影响已通过项目时才使其失效。相同最终运行输入的有效证据可复用，无关Agent计划/进度文档变化不使Rust测试失效；必须记录输入、变更影响和证据，无法证明未受影响就重验，不沿用旧簇测试冒充新能力。快照差异须人工审源后接受，不能自动改期望来过关。
- 未通过适用验证不提交、不报完成；外部条件缺口保持未完成并继续独立项。每簇区分代码实现、验收、提交与main集成状态，汇报实际失败、等待及耗时，不以测试数作为进度。所有任务共享资源预算，禁止重复运行同一套矩阵争抢机器。
- 一个功能簇覆盖可独立交付的完整能力或紧密关联API家族；不按单个方法拆成反复验收的小簇，也不为凑大批次混入不相关能力。先完成该簇全部编码，再冻结验证输入；验收等待不阻止下一独立簇编码。
- 验证负责人一次领取完整适用检查链，按已确认的资源和顺序连续执行、失败即停并保存已通过证据；不在每个成功子阶段停下来等待模型重新派发。输入漂移、资源越界或新增授权边界才重新协调，编码/测试失败遵循AGENTS的自主诊断与最优方案处理规则，保留有效断言和门禁，不因固定失败次数额外请求确认。
- 每次验证保留一份最终结果索引，关联实际命令、输入、退出码、日志和资源状态；总控集中复核一次。稳定代码做一轮独立审查并批量反馈，后续只复核修复及受影响范围；不反复要求模型全文重读、重算同一证据。基线HEAD变化但实际验证输入相同的，记录对应关系，不仅因提交号变化重跑。
- 从现有日志区分编译/链接、测试执行、资源排队、交接及清理耗时；优先消除最长的可避免等待，不以新增代理数或测试数宣称提速。不另建高频监控或基准系统；只有同等输入与资源条件下的实际耗时才能支持提速结论。

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo doc --workspace --no-deps
cargo deny check
# M6：对已有源码版本做 API 兼容性比较；先明确源码 baseline，再执行 semver 检查。
```

| 模板与生成器 | 模板快照检查；日常普通与MySQL生成项目，其他数据库运行统一发布前另验；生成项目后 `cargo check` + `cargo test` |
| 文档-only | `git diff --check` + 相对链接检查 + `rg` 旧路径扫描 |
| 生成项目模板 | 模板快照检查；日常数据库型生成仅MySQL，其他数据库运行统一发布前另验；检查真实 `.env` / `.env.*` 忽略且 `.env.example` 可跟踪，生成项目后 `cargo check` + `cargo test` |

测试原则：只保留能发现真实回归、保护公共契约/安全边界/数据一致性/故障恢复，或验证跨模块与外部服务集成的高价值测试。按风险和独立行为选测试，不要求每个函数、字段或简单分支各写一例；相同输入、断言和失败原因的重复测试应合并。新增测试前须能用一句话说明它能发现的具体缺陷及为何现有测试发现不了；测试数量与覆盖率不是目标。能力 fake 可随该模块的 `test-util` 暴露；通用测试组合工具放在 `testing`，不得为目录统一引入根 package 对测试包的反向依赖。分目录迁移测试时核对 Cargo targets 和运行用例，避免子目录文件未被编译执行。

### 测试源码与生产源码分离

- 第一方框架、扩展、工具、应用、业务模块和生成模板都必须把测试用例、测试专用夹具、测试脚本和测试专用辅助实现放在各自的 `tests/` 目录。禁止在正式源码文件内编写测试函数或内联测试模块，也禁止在 `src/`、`app/`、`bootstrap/`、`routes/`、`config/` 等正式目录存放独立测试文件。
- 框架及扩展、工具使用所属 Cargo package 的 `tests/`，根应用使用根 `tests/`，示例模块使用 `modules/example/tests/`，生成项目用例使用 `tools/cli/templates/tests/`。需要访问私有实现的单元测试放在所属 `tests/unit/` 的对应领域目录，正式文件只保留 `#[cfg(test)]` 和必要 feature 条件下的 `#[path]`、`mod` 挂载。测试正文留在测试目录，无需为迁移放宽生产 API 的可见性。
- `TestApp`、公开测试 API 和显式 `test-util` 提供的 fake 仍按各自公共契约组织，其自身的测试用例和专用夹具归测试目录。Rustdoc 的用法示例属于接口文档。
- 新增和修改的测试须遵守本节。提交前检查涉及的正式文件与测试路径，按范围核对测试实际被 Cargo 收集和执行。历史混放纳入唯一 todo，按领域和现行验收边界迁移，保留原断言、feature 和进程隔离。第三方 vendor 保留原有布局。

### 测试分层与入口整合

- 基础语义矩阵集中在快速unit/contract层；`modules/example`验证公开API、Provider/路由与持久化接线；生成项目验证模板实际编译运行；真实TCP/DB保护协议与后端独有风险。不得在每层、每后端和生成变体机械复制全部边界；Laravel行为严格对应，不要求测试文件或用例数量对应。
- 合并前核对实际Cargo入口、独有缺陷保护和失败原因。纯行为测试可按领域聚合入口并保留子模块文件；进程环境变量、独立feature、真实服务和特殊harness需要的隔离必须保留，不用整套串行执行掩盖竞争。同步Cargo、`#[path]`、feature、模板/快照及消费者，受控删除走`git rm`。
- 先做小范围试点，记录删并理由与保留隔离点，并证明关键负例/回归仍实际执行。比较相同工具链、feature与缓存条件下的文件/用例/target数及编译、链接、执行耗时；数目减少不等于覆盖不变或加速已证实。在途冻结验收不因精简重排，按唯一todo在安全交接点领取。

日常实际数据库验收仅真实MySQL8.4；其他类型及最低版本运行统一发布前全承诺后端验收。测试入口整合须保留各后端测试、feature与必要隔离，不能把未执行PG算通过或删减发布矩阵。历史证据不改写。

### 构建产物与临时资源

- 本节适用于开发者与 AI Agent。main、worktree、consumer 和生成项目合计构建产物的软告警和硬上限均为 100 GB（十进制），磁盘可用空间的两级清理阈值均为 5%。构建产物达到阈值或磁盘可用空间低于阈值时，清理本项目全部可重建的编译产物。已有缓存、退役二进制和编译产物归档均计入。
- 总控在唯一 todo 登记 owner、target 真实路径、用途、预计新增量和最近检查结果。重型构建前运行 `python3 -B .agents/project/scripts/check-build-budget.py --planned-bytes <预计字节数>`。命令扫描 Git worktree 内可识别的 Cargo target，按设备和 inode 去重统计实际分配块。用 `--scan-root` 补充已确认归属的外部目录，用 `--artifact` 登记外置 target、二进制和归档，用 `--build-on` 选定新增产物所在卷。开始构建前核对报告的扫描范围和预计余量。退出 0 可继续，2 或 3 均要求按对应阈值执行全部编译产物清理，再复跑预检。

| 时机/状态 | 动作 |
| --- | --- |
| 构建前、命令结束、长矩阵阶段边界 | 检查累计产物与磁盘剩余；长命令由本地轻量采样检查磁盘余量，不为监测启动模型轮询或另一套守护；目录体积不做高频全盘扫描 |
| 正常预算内 | 同一簇连续命令可复用缓存，不每条命令clean；跨簇只保留下一实际已安排步骤明确需要的一份缓存，其余已完成产物及时回收，不无故复制target |
| 功能簇/生成验收结束，或任务取消 | 在途命令自然结束、收取证据后集中回收已完成簇、多feature、生成和测试产物；可完整清任务target，必要时协调无占用共享target完整清理后按需重建，不只删少量继续堆积 |
| worktree退役 | 源码worktree仍须已合入、无WIP且无占用；纯构建缓存确认归属和无占用后即可回收，不必等分支合入，不删除未交付源码或证据 |
| 累计达到 100 GB 或磁盘可用低于 5% | 清理本项目全部可重建的编译产物，包括 main、worktree、consumer 和生成项目的 target、项目外置 target、测试二进制及其归档。等在途构建自然结束并释放占用后清理相关目录。保全源码和验收证据。清理至阈值以内后仍须回收其余已确认的编译产物，完成后复测，预计产物低于 100 GB 且磁盘可用至少 5% 即继续。暂不能安全清理的路径记录占用者和解除条件，释放后补清 |

- 清理以完成即回收为准，不以节省重编译为由长期保留不再需要的主缓存或历史feature。先保护在途命令和有效证据，再集中核归属、锁与占用；完整清理先cargo clean --dry-run再执行。记录清前后项目产物总量、磁盘余量、删/留范围与理由、下一唯一构建目录。未知历史缓存集中核查一次来源并明确处理或保留条件，不静默无限积累。临时日志/证据须有界，保留可复验摘要，不把日志无限追加当缓存；不因此放宽验收或改写已有通过证据。清理延后说明占用者与解除条件，代码实现和无资源冲突的工作继续。
- 临时生成应用、干净源码副本及其 target 放在任务专属临时目录，记录创建归属，成功、失败或取消时均回收。诊断需要暂留时说明路径和保留原因；不得删除其他任务的目录。临时源码验证默认不把 `CARGO_TARGET_DIR` 指向仓库共享 target，避免一次性包名与 feature 组合长期堆积。
- `cargo clean` 只清理明确指定的Cargo构建target，不清理Cargo下载缓存和依赖源码；清后下一实际步骤按需重建。同簇连续验证可复用，跨簇保留必须说明下一具体用途及唯一目录；完成簇的多feature/测试产物不因仍低于硬上限就继续堆积。
- 删除前检查真实路径、符号链接、Git 跟踪状态和任务归属，确认目标只含生成数据；检查 Cargo、rustc、rustdoc 及关联构建进程。清理共享目录时还须使用已验证与当前 Cargo 兼容的构建锁，持锁期间保留锁文件；无法取得锁或发现其他使用者时延后，不能只凭一次进程快照判断安全。锁文件是否存在不代表锁是否被占用。
- 不清理仓库外的全局 Cargo 缓存，也不按文件名哈希或修改时间猜测删除 `deps`，不为清理擅自修改全局 Cargo 配置、profile 或关闭开发者的增量编译。仅在阈值处置、缓存退役或任务工作区安全回收时，对明确归属且经dry-run复核的target执行完整`cargo clean`；先检查并发构建锁和实际回收量，并说明下一次构建会重建哪些产物。目标为临时副本或独立示例时，只清理该副本/示例自己的 target。
- Cargo 的下载缓存回收不负责回收 target 构建产物；本规则是开发者与 AI Agent 的任务收尾责任，不代表 Cargo 已安装自动清理钩子。依据：[构建缓存](https://doc.rust-lang.org/cargo/reference/build-cache.html)、[cargo clean](https://doc.rust-lang.org/cargo/commands/cargo-clean.html)、[全局缓存回收](https://doc.rust-lang.org/cargo/reference/config.html#global-caches)。

## 并行开发与集成

- 模型按任务所需决策与关联复杂度路由：`gpt-6.1-sol`常规medium处理公共contract、复杂调用链/调试/合流；`gpt-6-luna`可从low承接已冻结方案的局部实现、同步、检索、日志/结构化汇总及已批准验证收证。Luna遇契约冲突/隐藏依赖或重复失败交Sol，保原证据；高风险改码仍不同模型/Provider独审。实际可用catalog/档位与账户预算为准，不将API价格比当Codex额度倍率，不预测省时/省额倍数；自然交接调整，不切换在途会话或改全局配置。

- 处理新消息先区分补充、纠正与明确替代，未取消任务保留；消息处理后恢复原owner/范围/停点和下一动作。需求/审计统一归并todo及既有矩阵，不以新消息覆盖旧未闭项，不按“已派发”关闭。切簇、压缩恢复及提交前核源码/验证/commit/交接证据，未验、未集成及外部缺口分开记录。

- 默认同一 OpenRust 项目与同一 main 物理工作目录。Lead 按不重叠文件分配本对话内子智能体；公共 API、manifest/lock、共享文档、Git 索引、target 和服务由 Lead 调度。冻结受验文件按实际验收输入保全。
- 既有worktree先交接全部WIP和证据，原owner停写后串行整合main；核实逐文件保全、来源映射、无遗漏和占用后才正常退役。下文任务分支/worktree规则只适用于既有隔离任务或后续明确获准的例外，不是新任务默认。
- 并行数受实际槽位、额度、CPU、内存、磁盘及文件冲突限制。就绪任务按依赖和文件归属并行。
- 项目管理目标为OpenRust下main与tasks任务分组同级，任务分支沿`tasks/<任务标识>`；tasks是显示组织，不是把不同分支的执行者放进一个共享checkout。若正式Paseo接口支持分组则使用，未核实支持时将同项目各独立workspace标题统一为`tasks/<任务标识>`，对话框注明实现/审查职责；名称前缀不冒称真正嵌套分组。不为显示层级新增项目、源码tasks目录或改Paseo内部数据库。
- 既有项目工作对话的在途结果由 Lead 收取。后续执行与审查统一使用 Lead 本对话及其子智能体。
- 总控在worker交接、审查结论、门禁完成、槽位释放或阻塞变化时主动收取结果、更新唯一todo、安排后续验证/集成并填补ready任务，不等待用户催促。架构协调会话每次进度检查核对真实提交、执行者、资源与清理状态，发现偏离时给具体提醒；相同未变化状态不反复发消息，不为跟进新建高频模型轮询或重复Goal/守护。
- 总控维护唯一todo依赖图，按本机资源与额度安排多个独立簇；每项登记负责人、冻结Spec/公共接口、前置、基线commit、分支/worktree、文件范围、构建/服务资源、验收、集成与清理状态。依赖未满足只做只读审计，不重复派发现有任务。
- 总控保持两条可重叠的工作流：已冻结簇验证/集成时，前置满足且本批范围允许的独立任务在共享main的明确文件范围实际编码，不只派只读分析。提前确认文件与公共接口边界；需要在途未提交实现的任务仍等待前置，不假定接口就绪。代码就绪后排队重验证，不能为增加并行数复制整套构建缓存。
- 创建临时资源时即登记owner、路径、下一明确复用步骤与清理条件。编码不依赖构建缓存；完成验证后集中回收不再需要的产物，只保留下一已安排步骤明确需要的一份缓存，不为节省重编译长期积累多feature或旧任务target。main提交与索引始终单一owner串行，文档更新按短窗口集中处理，不反复打断源码验证。
- 仅对既有隔离任务或后续明确授权的例外，在同一Git仓库创建本地任务分支（建议`tasks/<任务标识>`）与临时worktree；默认临时目录用`/tmp/openrust-worktrees/<任务标识>`，先确认路径未被占用。独立对话框或子代理均须绑定正确工作目录；不新建源码仓库、不默认给worker启动重复守护。
- 若既有任务误登记为独立Paseo项目，先通知原owner并保全分支/WIP/会话/证据；有正式归属迁移接口时优先使用，否则由总控在交接点将已提交工作接到当前项目的正确workspace并验证新执行者绑定，再正常归档旧会话/工作区。不得直接project delete（可能连同workspace一起删除）或修改Paseo内部数据库强制改归属；旧项目登记未安全收尾时保持可见并报告。
- 当前main未提交改动由原负责人继续闭环；不stash/reset、复制或强迁移他人WIP。新分支从明确的已提交基线派生，依赖未提交改动的任务须等待前置集成。稳定公共contract变化先由总控同步Spec与依赖，不让各分支各造接口。
- 同目录不并发写同一文件；分支间亦须约定共享核心、Cargo清单/锁、迁移编号和共享文档的归属，集成负责人协调交接。worker不递归派发、不擅改整体contract，不启动冻结产品。
- 分支worktree使用任务专属target、端口和测试数据，所有任务worktree/target纳入本项目 100 GB 软告警、100 GB 硬上限及磁盘阈值；Cargo/真实服务任务按CPU、内存、磁盘与额度统一调度；避免重复全量门禁或同时挤占资源。只清理本任务资源，不清其他worktree、共享target或服务。
- 验证资源按实际冲突分配，不设全项目Cargo独占锁：相同target、同一清单/锁文件写入、冲突端口或测试数据必须串行；独立target且服务数据隔离的轻量检查/定向测试可在CPU、内存与磁盘预算允许时并行。重链接、全特性和生成项目大构建错峰，避免通过复制target换取表面并行。资源不足时只暂停争用资源的步骤，代码实现、调用方迁移、静态审查和文档继续。
- 验证窗口在实际进程结束并收取结果后立即释放；存在ready任务且资源可用时，总控直接启动下一项，不等待固定汇报周期或另一次用户催促。等待须注明具体占用者/任务句柄、资源及解除条件；不得以其他簇尚未提交为由禁止无依赖任务完成实现。先定向验证已知失败的fixture/快照/行为，再执行剩余矩阵；共享文档变更不触发无关构建。
- 分支交付具备实现、示例/生成项目、文档、适用门禁和独立审查证据后创建本地提交。用户已持续授权已批准框架范围内的本地 main 集成，不再逐分支等待确认或发起同义问卷；该授权不扩展推送、发布、tag、force、已推历史改写或冻结产品开工。先整合本批已交付源码并解决冲突，再冻结同一组合输入集中验证，不按每合一个分支重复完整矩阵。总控核对工作区、基线/差异、依赖和结果，串行准备可审阅的集成结果，执行main完整组合门禁通过后才创建集成提交，不先生成未验收的合并提交；分支通过不能当main通过。冲突必须重新验证，不通过降低断言处理。
- 验证与提交完毕及时回收任务：先确认所有任务提交被main包含（保留祖先关系；改写/挑选则须等价树与commit映射证据）、无未提交/未追踪工作、无人占用且进程已结束；正常`git worktree remove`后再`git branch -d`，不使用force、`-D`或批量prune绕过检查。清理失败保留目录与原因，不丢弃工作。

## Git 提交

当前持续交付授权：真人已明确要求已验收的完整簇及时限定规范提交并推送origin/main，不等无关WIP或全部计划结束。Lead唯一负责索引/commit/push，Architect不并发push；先fetch核远端祖先，以验收绑定的准确commit SHA安全快进推送，ls-remote核远端hash。主目录有其他WIP时保护原索引/源码，使用临时clean detached树核准确提交后显式SHA推送，再正常移除；不stash/reset/夹带未验源码。此前1a7473ba及祖先已远端，禁止按旧全本地历史重组。旧仅本地/不推送口径由本次专门授权覆盖；force、tag、release、发布与改写已推历史仍不授权。

提交使用项目脚本：

```bash
AI_AGENT_SOURCE="<Agent 名称> <模型>[ (<档位>)]" ./.agents/project/scripts/commit <type>[(scope)] "<中文主题>" "<说明>" -- <pathspec>...
./.agents/project/scripts/commit validate HEAD
```

- type：`feat` / `fix` / `docs` / `style` / `refactor` / `perf` / `test` / `build` / `ci` / `chore` / `revert`；scope 可选，建议用 crate 短名（`core` / `http` / `db` / `cli`）。
- 主题用中文描述实际变化；正文最后一个非空行必须是 `AI-Agent: <Agent 名称> <模型>[ (<档位>)]`。
- 脚本优先读 `AI_AGENT_SOURCE`，其次 `AI_AGENT`，再次 `AI_AGENT_NAME` + `AI_AGENT_MODEL`（可附 `AI_REASONING_EFFORT` / `CLAUDE_CODE_EFFORT_LEVEL`）。Claude Code 会话中 `AI_AGENT` 可能被运行环境预置为非规范值，提交时显式传 `AI_AGENT_SOURCE`。
- 新增文件先 `git add` 再用 pathspec 提交；一个功能簇一个 commit，不夹带无关改动。
- 不 force push；推送 `main` 前确认准确待推提交已验证，并核用于推送的detached工作树干净；主开发目录的无关WIP按上述授权隔离保护。
