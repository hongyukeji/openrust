## 定位与范围

- 项目及计划统一命名为“AI模型平台”（`ai-model-platform`），其中可复用网关命名为 `ai-model-gateway`；具体部署可使用自有品牌。交付形态为“官方可选 AI 插件套件 + 完整平台应用”。平台应用与网关源码在本仓 main 按目录隔离，普通应用可只使用调用子层或网关，完整应用装配全部必交付模块与网站。
- 最终目标为 OpenRouter 公开功能与关键使用流程对标，包括已确认基线内的 Beta/实验能力；按需启用是使用方式，不是删减完整交付范围的理由。软件不承诺取得相同的供应商合同、模型供给、用户规模、私有算法或历史数据，不伪造效果和运营数据。
- AI模型平台独立于 OpenRust V1/V2 排期、版本和验收；插件及应用分别声明框架版本/commit、Rust、feature、数据库与协议兼容范围。V1 提供通用底层，V2 提供可选后台基础，AI 专用能力不成为框架隐含交付项。
- 当前结论为有条件可行，尚无 AI 实现、真实成本或全部外部供给验证。现有 `Plugin::build/finish`、服务和路由注册只证明存在装配入口，不证明协议、取消、费用或资源生命周期已实现。
- 23 个能力域不是已闭合的字段级规格。P0 须冻结有日期的功能/API/页面基线，将 Alpha/Beta、教程重复项和废弃行为逐项映射；不机械复活已停止服务。后续上游变化进入差异清单，由开发者确认目标变化，不让交付终点无限移动。
- 公开资料未知的算法、私有模型或后台行为须取证或确定可测试的等效契约；未知项标记“待取证”，服务/资格不足标记“待外部条件”。不能用 mock、空页面或仅转发 OpenRouter 一个上游宣称完成。

## 能力结构与源码组织

```text
AI模型平台
├── AI模型网关插件
│   ├── 统一接口与供应商适配
│   ├── router：模型选择、负载分配、故障回退
│   └── 鉴权、配额、限流、流式转发
├── 账号、组织与权限
├── 定价、充值、计量与账本
└── 模型展示、Chat、控制台与运营管理
```

- `router` 是网关内部模块，当前不另立 `ai-model-router` 插件或分支。网关内部保留可独立使用的调用子层；只调用模型时不要求平台账户、计费、UI 或网关服务进程。
- 这是职责总览，完整范围仍以 OR-01–OR-23 为准；文件/多模态、托管工具、Agent、沙箱与 SDK 等已规划能力继续交付，不因总览简化而删除，也不将平台改名为 Agent 项目。
- 依赖方向为平台应用 → 网关公开接口 → OpenRust 公开能力。网关通过宿主适配接口接收身份、租户、权限及预算，不反向引用平台私有模块、固定用户表或商业账本。

未来明确启动后，框架、网关与平台应用仍在本仓库 `main` 开发，按模块与目录隔离；建议源码布局如下，当前仅记录，不创建目录：

```text
项目工作区
├── src/                         # OpenRust 框架代码
├── plugins/
│   └── ai-model-gateway/         # 可复用网关源码，内部包含 router 与调用子层
└── apps/
    └── ai-model-platform/       # 平台应用、业务装配与配套界面
```

平台使用同一源码快照中的网关，通过 workspace/path 依赖及公开接口接入；框架、网关和平台的来源由项目 commit 与依赖锁定共同追溯。P0 确定必要的 Cargo 成员与 feature，保持默认框架构建隔离，不按上图每项职责拆 crate。获取该项目源码后即可构建，不依赖额外源码仓库、开发分支、外部包发布或运行时安装。须通过独立消费者测试证明网关可脱离完整平台复用。

阶段里程碑仅表示已授权开发后的内部顺序。G0 成熟前置仍必须满足；取得 AI模型平台开发授权后，按 P0 技术退出条件及 P1–P8 连续推进，不为已授权范围反复立项。上线仍单独满足 G3。

## 同仓主分支与模块隔离

- 当前及后续开发仅在本仓库 `main` 进行，不创建额外源码仓库、开发分支或隔离 worktree。框架成熟门禁和用户明确启动授权满足后，网关、平台业务、配置、迁移、前端、测试与部署文件按 [源码组织](#能力结构与源码组织) 在目录中隔离。
- 开始前核对基线 commit、Git/WIP、其他 Agent 与数据库；多 Agent 按明确且互不重叠的文件所有权并行，共享 manifest/lock、迁移、文档和提交由集成负责人协调。不得移动、清理他人改动或切换开发分支。
- `plugins/ai-model-gateway` 仅表示可复用模块目录，不是分支名。通过公开契约、兼容范围、依赖/许可证、配置迁移与默认构建隔离验证后，可纳入可选源码分发；不复制维护第二套网关实现。
- 平台领域模型、运营政策、供应商凭据与品牌界面归平台应用，不进入框架核心。同仓开发不改变公开接口、依赖方向、默认 feature、默认启动或 CI 隔离要求；发布与对外动作仍须独立授权。
- 未获明确启动授权前只维护本规划及索引，不创建产品源码目录、依赖、数据库或部署环境。

## 插件版本配置与迁移契约

依赖方向为“宿主应用 → 选用的 AI 插件/平台模块 → OpenRust 公开能力”；网关可复用调用层，各模块按需依赖，不形成强制线性链。仅调用模型不注册网关/管理路由，不要求平台账本、支付、Redis 或后台套件；只有选用功能实际需要的依赖才成为启动条件。

沿用现有 Plugin、服务/配置/路由和命令扩展；后台任务由命令 supervisor 明确持有、取消和 join，不建立第二套容器，不在 `finish` 留下无人管理的任务。供应商 adapter 可由外部源码实现，不依赖私有构造器或闭合 provider 枚举。

| 契约 | 必须明确与验证 |
| --- | --- |
| 源码接入与版本 | 首期使用本地 workspace/path 和公开 `Plugin::build/finish` 静态装配；网关及可选模块声明兼容版本，平台以包含其源码的项目 commit 和依赖锁定追溯来源，公布支持的框架/Rust/feature/数据库/协议范围，不承诺任意版本兼容。可选源码分发不自动改变内部 package 的 `publish = false`，不要求 crates.io 发布或动态加载 |
| 默认隔离 | 不选 AI 时不引入其运行时服务、外部请求、数据库迁移或部署要求；只选调用层时不编入平台 UI/商业账本及无关 driver。用默认构建与最小 feature 的依赖图及启动检查证明，允许源码工作区拥有独立的可选成员与测试入口 |
| 宿主身份与政策 | 用公开类型和适配接口接收已认证的主体、租户/workspace、授权和预算，不从任意请求字段推断身份，不耦合宿主用户表。验证两个不同身份模型的宿主；公网身份缺失或不匹配时拒绝，禁用商业计费须显式选择内部使用政策，不默认上游免费或无限调用 |
| 配置与路由 | 配置段、环境变量、路由前缀及服务注册冲突均有确定规则；非法配置、缺少依赖、重复注册或未支持组合在启动时失败。凭据使用框架加密/脱敏；供应商 URL 策略与 SSRF 防护不能由用户参数绕过 |
| 数据所有权与迁移 | 插件迁移和宿主迁移显式编排，记录版本及前置依赖；启动不自动改库、不创建默认管理员，不修改宿主用户表。普通调用不需要平台数据表；网关与账本仅为实际启用模块建表。验证新安装、重复执行、升级失败和历史数据保留 |
| 升级与回退 | 为配置键、持久数据、队列载荷、公开接口和协议适配器声明兼容窗口；验证目标旧新版本节点共存、排空和恢复。配置弃用有诊断与迁移说明，不能静默忽略；数据库回退用实际可行的备份/前向修复方案，不承诺删除业务数据即可回滚 |
| 关闭与资源归属 | 首期停用通过配置/源码组合变更后重启，不承诺热卸载。路由、连接、任务和流有明确所有者；运行中取消/排空/关闭后不遗留后台任务。禁用不自动删除表、账本或用户数据，待结算请求必须先排空或交接可恢复处理 |
| 可选交付 | 插件自身按声明范围验收，不要求调用子层或网关插件独自实现 OR 全矩阵。通过独立接入、兼容与依赖验证后可纳入官方可选分发，实际合并/发布遵守既有授权边界；不能以局部交付代替完整平台 G2/G3 |

供应商扩展沿用框架公开 driver/trait 原则：调用、流事件、能力与错误契约必须可由外部源码包实现，未知能力应明确拒绝或按已声明透传规则处理。宿主预算服务由平台模块或应用适配器提供；商业收费要求持久化预占/结算及恢复契约，不用普通事件监听器冒充资金一致性保证。

## 运行架构与协议边界

优先模块化单体与独立进程角色，不默认微服务。实际 crate 数量在 P0 按依赖隔离和维护边界确定，不按下表逐项拆包。完整平台装配全部必交付能力。

| 模块/角色 | 职责与边界 |
| --- | --- |
| API 数据面 | 身份/权限、预算预占、路由、上游适配及流式转发；同步推理不通过后台队列排队再等待，客户端连接内保持取消/背压 |
| 管理控制面 | 模型/渠道/价格版本、租户/策略/Key、客户/运营/供应商接口；配置以验证后的不可变版本发布，失败可回滚，不在长流中途更换价格或策略快照 |
| 计量与账本模块 | 唯一资金权威与结算 API，管理上游成本、客户消费及供应商应付；禁止控制台绕过服务直接改余额 |
| 作业 worker | 真实 Batch/视频等异步作业、回调、usage 核实、对账、通知、删除清理；复用持久任务，不把同步模型调用伪装成异步成功 |
| 文件与资产模块 | 上传/引用/授权/生命周期及临时链接，限制文件大小/内容/处理资源；对账保留必要元数据，正文删除政策不破坏财务可追溯性 |
| 沙箱执行面 | 与 API/数据库/密钥宿主分离，执行 shell/Agent 等不可信负载；资源/网络/身份隔离失败时不可用，不能仅用同进程 async timeout 当隔离 |
| UI/SDK/集成 | 客户、组织、供应商与运营不同权限视图，共用公开业务服务；SDK 绑定版本化 schema 与协议事件，不复制后台私有接口 |

- 应用通过 OpenRust 公开能力组装；框架缺失稳定 escape hatch 时形成独立通用任务。产品不覆盖框架统一响应规则来强迫所有框架用户接受 AI 协议。
- AI 兼容路径必须保留正确 HTTP 状态、header、JSON 错误结构、SSE/二进制及 multipart 语义，不能套 `ApiResponse<T>`/always-200 包装。鉴权、解析、限流、超时、panic、404/405 等中间件错误也要在产品边界转换；逐路由验证与默认框架行为共存。
- 上游 adapter 按真实能力声明字段/事件/取消/usage/区域；采用有界的协议转换与原样转发组合，不建立丢失全部供应商特性的万能最小结构，也不静默忽略未知参数。
- 模型/价格/能力目录有版本、来源、刷新与人工审核，自动更新不能未经验证改变历史价格、私有可见性或能力路由。

- Responses：已有公开取证基线为无状态，不支持 `store: true`/非空 `previous_response_id`；对标应验证相应拒绝行为。不能因为它叫 Responses 就承诺 OpenAI 的所有持久状态能力。
- SDK 兼容：必须覆盖响应字段、流式 delta/usage、工具与推理、错误码/header、取消和重试；只有 happy path 请求成功不算兼容。
- 身份隔离：组织/workspace、BYOK、文件、缓存、私有模型、日志、工具任务与预算统一授权，不能依赖 UI 隐藏或 Key 字符串猜测租户。
- 财务隔离：用户余额、平台上游成本、BYOK 服务费和供应商应付分别记账；缓存、失败尝试、工具子调用及批处理部分成功均需明确收费；无法确认的成本进入核实流程。
- 缓存与回退：response cache 不跨权限/数据策略复用；路由不能为了成功率跳过地区、隐私、能力与预算过滤；跨地区回退缺省禁止。
- 工具执行：shell/Agent 必须运行在产品专用隔离环境，网络/文件/时间/递归/费用有界，不能复用框架宿主机权限；不是简单增加一个 HTTP 路由。
- 路由质量：内部评分/训练数据不公开时，用可说明和可测的等效策略达成目标，不能声称重现相同内部算法；需要离线评测与在线指标，不能只做随机转发。
- 插件复用：调用层不能隐式要求平台注册/账本，网关不能耦合固定用户表；收费与非收费组合的预算来源明确，关闭商业计费不代表上游免费。AI 路由与普通应用响应共存、配置/迁移升级和依赖缺失的失败路径都须经独立宿主验证。

## P0 细项追踪与验证原型

用户明确要求开发 AI模型平台且满足 G0 后，在本仓 main 的产品目录维护执行细项与验收证据；本文件仍是统一规划入口，不能只沿用领域表。每条至少包含：

- 稳定 ID、官方来源 URL、观察日期、稳定/Beta/废弃标记及证据级别（文档、页面实测、真实 API 实测）。
- 用户角色、页面/动作、API method/path、请求/响应/流事件/错误/权限、计费与数据区域影响。
- 目标行为、兼容偏差、负责层次/模块、宿主前置契约、依赖能力/外部服务、阶段与验证用例；标明插件独立验收和平台组合验收各自覆盖项。
- 状态只用待取证/已规格化/开发中/已实现/已验证/待外部条件等可区分字段；“有入口”“有 mock”“只通过编译”不等于已验证。
- 按接口、用户旅程、能力域分别统计覆盖；不能按文件数或粗略模块数宣称完成百分比。全部最终项和未知项未关闭前，不宣称全面复刻。

先从官方文档索引与 API schema 建立清单，结合访客/客户/组织/供应商/运营角色的真实浏览器流程补证。登录或企业权限不可用时只记录缺口，不推测后台行为或索取不必要凭据；后续在获得适用访问条件时补验。

P0 保存适用官方 schema、页面观察、测试 fixture 的日期/版本/内容摘要，原文仅按许可和必要范围保存。依赖或上游升级后重跑对应契约，不能依赖实时网页作为唯一规格。启动时还需固定具体部署品牌、上游/模型、协议与客户端、收费单位/精度/舍入、余额不足政策、支付方式、隐私留存、部署规模和开放条件；未确认时用建议与测试替身，不启用真实付费。

### 必须先验证的原型

仅在用户明确要求开发 AI模型平台且 G0/G1 满足后，P0 在隔离环境进行最小技术原型，结果只写进当前证据清单。以下任一不可行时不得展开全部功能实现：

1. 用框架公开接口同时跑普通后台与 AI 原生 JSON/SSE 路径，覆盖 middleware 错误、UTF-8/事件切片、慢客户端和上游取消失败。
2. 使用可控上游与数据库验证预占后断电、发出请求未获 ID、结算前崩溃、重复/乱序回调，以及恢复后账本不变量。
3. 验证代表性真实上游的工具/usage/媒体/批处理能力和 API 差异；无法取得的关键供给在预算投入前明确。
4. 验证独立沙箱逃逸边界、网络策略、资源销毁、进程树取消与费用上限；无可用执行基础设施时记录阻塞，不转为宿主执行。
5. 验证目标区域的流量/存储/日志路径与账本授权延迟；实际支付/企业身份条件不具备时只做 mock contract，标记外部条件不通过。
6. 用独立宿主只接调用层，再用不同身份模型组合网关；证明不依赖平台私有代码、用户表或账本，关闭插件不遗留路由/任务，默认框架构建与启动不受影响。

| 供应商渠道 | 少量明确目标的真实供应商适配；凭据加密及轮换、连接/超时、健康检查、独立启停和配额；目标清单启动时确认 |
| 兼容 API | 首先实现 OpenAI 风格 `models` 与 Chat Completions、非流式和 SSE；工具调用/结构化输出仅对声明支持且经测试的路径开放，不宣称全部协议兼容 |
| 路由 | 先按能力/上下文/权限筛选，再按明确优先级选择模型与渠道；有界重试/回退、熔断及冷却恢复；禁止无条件重试所有 POST |
| 配额 | 客户/Key/模型/渠道的请求速率、Token 速率、并发与消费预算，明确计数窗口和分布式原子边界；不能只用请求数限流代替 Token 配额 |
| 计量与定价 | 输入/输出/缓存/推理等实际适用计量项、上游成本与客户售价、请求价格快照；无法确认的用量进入待核实状态 |
| 余额账本 | 充值、预占、结算、释放、调账/退款与可追溯流水；金额用定点/Decimal，幂等键与唯一约束防重复，数据库为权威状态 |
| 订单与充值 | 首先完成沙箱或受控测试闭环；真实支付方式、结算单位/精度、退款与费用规则启动时确认；回调验签、重复/乱序处理与对账 |
| 客户控制台 | Key、余额、账单/用量明细、模型目录与接入文档、基础图表；在线试用复用正式配额与计费路径 |
| 运营后台 | 客户/模型/渠道/定价、订单/账本查询、受权限控制的调账、故障与成本利润观察；敏感凭据不可读取导出 |
| 隐私与安全 | 默认不记录提示词和回答正文，元数据留存/脱敏；配置变更审计；上游 URL、远程图片/文件处理防 SSRF，客户端不能自由转发服务端密钥 |

## 请求结算与数据不变量

收费平台及启用商业计费的网关建议主路径：认证与模型权限 → 能力/政策筛选并冻结候选报价 → 配额与费用上界校验 → 持久化预占 → 按快照选择渠道 → 上游调用/流式转发 → 实际用量核验 → 幂等结算与释放剩余额度。回退前重新核对候选、费用与剩余预占，不能在无授权资金上界时切换更贵渠道。仅调用层不强制客户账本，由宿主明确承担上游费用并设置输出、超时、重试与并发上限；返回用量和未知执行结果，不自动向客户计费。

- 已向客户端输出内容后，不无缝切换另一模型并拼接结果；首字节、块间空闲、总时限分别控制，慢客户端有背压与有界缓冲。
- 以可信上游 usage 为主要计量来源；本地估算标明模型、算法与版本，不以同一 tokenizer 推算所有模型。流末 usage 缺失、崩溃与未知执行结果进入待核实/补偿状态，不直接按零消费或盲目释放全部预占。
- 价格、单位与舍入规则绑定请求快照；历史账单不随当前定价变化。充值、人工调整与结算保留可审计流水，通过反向分录更正而非覆盖历史。
- 并发预占与最终扣款使用数据库事务/约束，余额及权限关键判断走主库；Redis 仅承担允许的加速/共享配额，不成为无法重建的唯一资金账本。
- 后台任务负责核实、对账与修复，但不能把无持久记录的扣费异步“发出去就算完成”；实际一致性方案先形成 contract。

| 对象 | 最少状态/约束 | 必须发现的缺陷 |
| --- | --- | --- |
| 逻辑请求与尝试 | 独立 ID；tenant/workspace、配置/价格快照、上游请求 ID；重复请求指纹明确 | Key 重试和上游尝试被混淆、失败回退成本丢失 |
| 预占与结算 | reserved → settled/released，未知结果进入 reconciling；状态转移使用版本或行锁/唯一约束，终态不可重复计入 | 同时结算/释放、超时后双扣或全部预占提前释放 |
| 上游作业 | created/submitted/running/terminal 与 outcome-unknown 分开；请求发出但任务 ID 未持久化有恢复规则 | 崩溃恢复重复创建收费视频/批处理任务 |
| 事件与回调 | 业务状态和 outbox 同事务；inbox/事件 ID 去重，乱序校验，worker 租约和 fencing/版本拒绝过期执行者 | 数据已提交但事件丢失、重复/迟到回调覆盖终态 |
| 资金流水 | 定点精度、币种/计价单位、平衡分录、原单与反向更正关联；余额可从流水和有效预占核对 | 浮点误差、覆盖历史、跨单位直接相加与余额漂移 |
| 租户资产 | tenant/workspace 从可信身份解析；Key/BYOK/文件/缓存/日志/任务/私有模型关联可校验 | 参数改 ID 越权、缓存跨租户命中、删除后资产仍可访问 |

推荐账本采用复式分录或可证明等价的平衡约束；P0 固定科目、单位、舍入与不变量，并用测试向量验证充值、手续费、预占、消费、退款、拒付、应收/应付。不由“Decimal 已用”推定账本正确。

- 不持有数据库事务/行锁跨越上游网络请求或整个 SSE。持久化预占后提交短事务，网络执行后另起短事务结算；通过状态机和补偿处理跨边界失败。
- 预占必须覆盖有上界的计费风险：输入/最大输出、推理/缓存、工具次数、媒体单位/时长与可能的回退尝试等。平台不接受无限输出、无限 Agent 递归或无限上游尝试。
- 无可靠费用上界的渠道，在 P0 定义追加预占或平台风险资金限额；不允许未经规则使用客户负余额。实际费用超出预占时分别记录应计成本和合同允许的客户收费，由已确定的规则处理差额与告警，不能伪称上游永不超额。
- outcome-unknown 不按 TTL 自动视为未执行。明确核实窗口、渠道查询能力、人工处理期限、争议资金状态与最大挂账风险；到期的处理规则在 P0 决定，不无限冻结也不盲目退款。
- 客户断开应尝试取消上游，但不能假定已停止或不计费；超时也不证明未执行。Key 撤销、政策改变与节点排空的在途处理必须明确，已产生费用不能靠事务回滚撤销。流内容通常不可完整重放，幂等重复的状态查询/拒绝/重放按协议确定，不能重新调用上游冒充幂等；失败尝试的上游成本与客户收费分别记录。
- 上述预占/结算规则适用于商业计费组合。仅调用层由宿主承担上游费用，必须有最大输入/输出、并发、重试/工具循环、流缓冲与各阶段时限；超时和取消失败返回可区分的未知执行/用量状态，不能默认成本为零。插件不自动启用付费 provider 或后台真实探测，不在客户端已收到流内容后重试拼接另一结果。

## 区域、隐私与分布式预算

- 区分控制面元数据、财务数据与提示词/文件/工具输出。内容、缓存、临时文件、日志、追踪、工具网络和备份都必须符合所声明的数据范围，政策在创建上游尝试之前生效。
- P0 推荐先为每个财务账户设置唯一权威写入域；跨区域预算使用预先持久化且总额受约束的区域额度分配，或访问权威账本完成授权。选择一种并证明网络分区时无双花，不把异步复制余额当可立即消费余额。
- 权威账本不可达时，默认拒绝新付费授权；如采用已分配区域额度，只能消耗有效且不重叠的配额。不能在 Redis 故障或网络分区时无条件放行。
- 区域不满足时拒绝该请求，不回退其他区域；跨区域元数据、支付处理及 BYOK 端点的政策差异明确列出，不声称单区域数据库就自动满足全球驻留。
- ZDR 与故障排查冲突时优先履行已选策略：默认元数据脱敏；允许的内容日志需显式授权/留存/删除；以合成数据排查无法合法留存的正文。

7. 任何最终必交付项存在未知、未验证或真实外部阻塞时，完全体验收不通过，继续内部开发，不允许发布差异阶段版绕过上线要求。范围变更只能由开发者明确决定，不能由 Agent 自行降级。
8. P8 验收包须列出基线版本、全部细项结果与证据、独立审查结论、已锁定依赖/产物和部署恢复演练结果；满足 G2 后再提交 G3 上线决策。验收包不是部署授权。
9. 独立宿主只用调用层、使用自有身份组合网关、完整平台全量组合三类接入均通过公开 API 实测；套件的框架/Rust/feature/数据库兼容范围、配置迁移、升级/排空和默认隔离证据齐全。单个插件只需通过自身声明范围，但其完成不能代替其余插件与完整应用的验收。
