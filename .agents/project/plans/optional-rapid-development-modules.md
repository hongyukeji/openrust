# 可选快速开发模块计划

> 状态：仅保留设计，暂不开发。原V2独立版本计划已取消，原有后台/App需求改为按需选择的模块与模板，不再作为框架下一版本阶段。

## 开发与使用边界

- 目标是帮助开发者快速组合应用：用户/权限、组织、字典、参数、审计、通知、任务与文件管理等按职责拆为可复用模块；后台页面、Vue Admin、uni-app等是可选接入/模板，不强制全套安装，也不是框架默认应用。
- 开发者选择模块后，通过现有Laravel Modules、Provider、公开服务、配置与模块专属迁移/资源接入；不要求修改src核心，不复制认证/队列/调度等内核，不建立第二模块系统。业务表、权限与界面不进入框架通用默认路径；未引入者不承担模块专属依赖、路由或迁移。
- 当前仅记录，所有模块实现、界面原型和端侧工程均不启动；只有用户明确要求开发后，才按模块需求/依赖领取和验收。R14、框架两个阶段及持续Goal“全部完成”不自动授权本计划，框架验收和发布前整理不等待它。
- 当前main只推进通用框架与唯一示例；未来模块的分支/目录/交付组织在明确开工后决定，不现在创建分支或默认合回main。不删除已有WIP、模板、证据或源码；AI产品的单独授权边界不变。
- 下列B1–B5与端侧/模块清单是可复用设计输入，不是承诺全部立即开发。实施时先按真实应用收敛模块粒度、公开接口、版本兼容、独立启停/卸载及数据保留边界，避免为了方便把完整业务平台绑定到框架。

Laravel官方可选工具本身的Dashboard、授权页面与前端资源按[官方全量交付规则](laravel-official-coverage.md#全量交付授权与两阶段)在阶段二覆盖，按包启用，不属于本业务后台冻结范围；不得为实现官方工具借机启动本计划的组织/菜单/业务管理/App。

## 定位与依赖

- 框架交付通用 Rust 应用底座，可选模块提供可组合的业务功能与后台模板，帮助开发者快速开始应用开发；具体模块显式选择，不默认安装完整后台。模块复用按 [ADR-001](../decisions/adr-001-framework-principles.md) 实现的框架机制；若依与芋道仅在用户另行启动此类后台模块时作业务流程参考。
- 后台套件依赖 v1 的公开能力，不把后台表结构、组织模型或前端依赖放进框架 core；API 项目无需安装后台。服务端使用 Rust，Admin Web 使用 Vue，App 使用 uni-app；PC 端仅规划设计、暂不开发。
- v1 的数据库、缓存、认证、会话、加密、国际化、通信、任务、实时接口和审计不重做。v1 底层补齐计划 中的租户隔离、查询权限、外部身份/TOTP、CSV/XLSX 等也由可选模块复用；模块负责后台数据模型、接口、页面、默认权限与完整使用流程。
- 本计划暂不开发，遵循上方边界；既有技术前置不等于开工指定，不为模块给框架加入后台业务模型或提前UI。
- v1 完成门槛包括全部范围、真实双库/生成项目、共享状态与跨节点实时/文件、故障恢复/滚动升级、性能和干净环境路径；M3 本地验收或 M4 基础队列交付不能替代这些门槛。入口见 v1 能力覆盖、集群计划 与 性能计划。
- 本计划不改变当前开发包版本，不启动 tag、发布或远端动作。[AI模型平台](ai-model-platform.md) 独立排期，OpenRouter 仅作其产品能力对标；只有用户明确要求开发且框架成熟门禁满足后才启动，不包含在本计划开发授权内。

## 可选模块与模板范围

### 端侧选型与范围

| 端侧 | 已定路线 | B1 细化与交付边界 |
| --- | --- | --- |
| Admin Web | Vue，采用 pure-admin 精简国际化版 + Element Plus 作为后台视图骨架 | 锁定兼容的 Vue 3、TypeScript、Vite、pure-admin 与 Element Plus 版本及上游提交，接入真实 Rust API；交付完整后台页面与桌面/窄屏浏览器体验 |
| App | uni-app 框架 | 明确角色/页面/权限矩阵、目标系统、运行时版本和组件方案；实际交付移动流程与平台验收，不仅交付 H5 演示 |
| PC 端 | 仅做规划设计 | 明确用户场景、信息架构、交互稿、技术选型比较与 API 复用边界；不创建实现工程、桌面壳、安装包或发布流水线。后续开发另行明确启动 |

Admin 选用 [pure-admin 精简国际化版](https://github.com/pure-admin/pure-admin-thin/tree/i18n) + Element Plus。此选型与现有 OpenSpring Admin 的 Vue / Element Plus 技术路线一致，便于复用页面规范、组件经验和测试方法；以精简版建立独立应用，按实际功能引入组件，不复制完整业务工程、演示页面或 mock 后端。二次开发保留 [MIT 许可](https://github.com/pure-admin/pure-admin-thin/blob/i18n/LICENSE) 与来源记录。B1 通过登录、权限菜单、表格表单的真实 Rust API 原型锁定兼容版本、上游提交和锁文件，不把模板可运行当作套件验收。

复用 OpenSpring 通用组件前逐项核查许可、依赖与业务耦合，按需适配表格工具栏、实体选择器、表单和交互规范；不引入其组织业务模型、Java 专属协议或整套依赖。响应/错误/分页、token 刷新与撤销、菜单/按钮权限、上传下载和实时通信均以 OpenRust 已定公开契约接入，尤其不沿用 OpenSpring 的字符串 `Result.code == "200"` 约定。组件与业务生成模板统一使用选定的 Element Plus 体系，前端权限显示不能替代 Rust 服务端授权。

uni-app 的经典版/uni-app x、渲染模式、编译器与插件兼容性在 B1 结合 [官方维护说明](https://doc.dcloud.net.cn/uni-app-x/) 明确；不把用户的框架方向自动等同于某个实现代际。App 与 Web 共用 Rust API 的错误、认证、权限与国际化契约，平台请求/存储/导航分别适配，不要求复用全部 UI 组件。Android/iOS 的支持范围与最低系统版本必须写入矩阵；其他目标不自动纳入。

前端工作流入口见 [项目技能](../../skills/README.md)。设计规范维护在对应应用文档，不另起根目录产品事实。技能准备和 PC 设计不放宽 v1 完整验收门槛；此处 PC 规划范围不影响 Admin 的桌面浏览器适配。

### 功能范围

| 领域 | 后台套件交付 | 复用 v1 与验收边界 |
| --- | --- | --- |
| 应用骨架 | 可运行的后端与前端、布局/导航、登录/退出、个人资料与密码修改、环境配置和部署模板 | 沿用 v1 JWT-first API、refresh 轮换和国际化；Session 显式可选，PAT 用于机器/服务集成；外部身份登录、绑定及 TOTP/恢复码流程按套件配置接入 v1，不另建认证协议 |
| App 视图 | uni-app 应用骨架、移动导航、账号流程，以及 B1 页面矩阵中的通知/文件等适用流程 | 共用 Rust API 与权限契约；覆盖返回栈、前后台、弱网、系统权限及目标设备；不机械移植桌面管理表格 |
| PC 规划设计 | 场景、页面结构、交互稿、技术方案比较及与 Web/App 的复用边界 | 只验收设计文档和决策依据，可选模块 不要求 PC 实现或安装包 |
| 用户与权限 | 用户管理、角色分配、菜单/路由、按钮权限、权限变更生效 | 复用 Policy/roles/permissions；前端控制不替代服务端授权，覆盖越权测试 |
| 组织与数据权限 | 部门树、岗位、用户归属、可配置 DataScope | 组织语义归套件，查询限制复用 v1 公共规则；列表、详情、修改、批量及导出均验证权限，不能只过滤列表 |
| 字典与系统参数 | 字典类型/条目、可管理参数、缓存刷新及变更记录 | 静态启动配置仍属框架；参数按白名单和权限管理，密钥不作为普通可读参数 |
| 操作与登录审计 | 登录记录、操作记录、查询/筛选/导出与留存管理 | 复用审计事件与持久化；脱敏、访问授权及删除权限明确 |
| 登录状态管理 | 在线用户、refresh family/可选 Session/PAT 元数据查询与主动撤销 | 复用 v1 身份和共享状态；不展示令牌原文。明确 JWT access token 到期、refresh/Session/PAT 撤销及实时连接的不同生效时限，不伪称无状态 JWT 可被立即强退 |
| 通知公告与收件箱 | 公告发布、站内通知列表、已读/未读与发送记录页面 | 复用薄通知编排、Mail/SMS/Queue、WebSocket/SSE；站内信数据模型归套件 |
| 任务管理 | 定时任务配置、运行历史、队列状态、失败任务与重试/取消页面 | 只暴露已注册/白名单任务，不执行任意 Rust/脚本/系统命令；复用队列/调度与审计 |
| 文件管理 | 上传、下载、授权、删除、存储后端信息与配额展示 | 复用 Storage 与上传下载契约；不以公开 URL 绕过私有文件权限 |
| 运行监控 | 服务就绪、依赖状态、数据库连接池、缓存和任务指标及诊断入口 | 复用日志/metrics/trace；敏感配置和任意缓存内容不直接暴露 |
| 业务代码生成 | 生成后端资源、模型/迁移/验证/Policy/测试，以及前端列表/表单/API/权限菜单 | 复用 v1 生成器，支持双库与冲突预览；生成物可编译、测试、构建，已有文件默认不覆盖 |
| 表格与导入导出 | 查询、分页、排序、选中批量操作、业务导入模板、错误报告与导出下载流程 | 复用 v1 CSV/XLSX、查询权限、验证、Queue 与 Storage；套件验证字段映射、权限、批量事务策略和产物访问，不另写解析器或传输链路 |
| 开发与发布体验 | 统一开发入口、样例业务模块、国际化资源、前端构建、容器/反向代理说明 | 干净环境从创建到登录、生成模块、测试、部署可走通；不宣称有 Rust 就自动高性能 |

## 框架与可选模块 的能力分工

| 能力 | v1 | 可选模块 |
| --- | --- | --- |
| 认证、角色与权限 | 通用机制、最小模型、外部 OAuth2/OIDC/SSO 客户端与可选 TOTP/恢复码 | 完整用户/角色/菜单/按钮管理页面，以及身份接入、绑定和二次验证操作流程 |
| 登录状态、审计、验证码 | JWT/refresh、可选 Session、PAT 与公共审计/验证码服务 | 在线用户、凭据撤销、日志查询与账号管理页面，沿用 v1 的生效时限 |
| 国际化、加密、签名、幂等、限流 | 默认可用、可配置、可扩展的通用入口 | 页面和套件操作复用，不另建实现 |
| 数据库/缓存/存储/通信 | 驱动、统一契约、多实例、fake 与真实验证 | 管理、诊断和业务配置页面，不暴露全部底层权限 |
| 队列/任务链/批处理/调度 | 运行机制和命令 | 配置、进度、历史与人工操作页面 |
| WebSocket/SSE/通知 | 基础实时收发与渠道编排 | 后台通知体验和站内消息；跨节点在线投递复用 v1；持久离线重放按候选门槛决策 |
| 生成器与文档 | 后端项目/资源/测试生成和 API 文档 | 前后端整套业务模块、菜单与权限联动 |
| 查询权限与租户 | 公共查询权限规则、可选可信租户作用域与隔离，不强制组织模型 | 部门/岗位 DataScope；租户管理与运营按下文候选评估，复用 v1 隔离机制 |
| 数据交换 | 通用 CSV/XLSX 解析、转换、验证、错误与有界处理 | 业务字段/模板、表格页面、导入结果与导出产物操作流程 |
| 性能与运维 | 基准、资源边界、故障恢复、部署与诊断 | 带后台负载的性能回归、管理面权限和升级验收 |

## 可选模块 扩展候选与推荐决策

以下建议归入 可选模块 评估，不作为核心套件发布的隐含阻塞项；采用前明确需求、依赖、contract 与验收。不以“可选模块”表示必须穷举所有实现。

| 候选 | 建议 |
| --- | --- |
| Passkeys、独立 OAuth 授权服务器 | 官方Fortify/Passkeys及Passport底层按框架阶段二全量对应，本计划仅业务管理页面暂不开发；不以本表延后既有外部身份、TOTP/恢复码或官方包底层 |
| 租户管理与运营 | 可选套件扩展，定义开通、成员、管理权限和运营流程；隔离与查询规则复用 v1，不建立第二套租户基础设施 |
| 更多数据库/SQLite | 根据使用群体增加真实驱动和 CI；仍复用 v1 扩展边界，不因为底层兼容就宣称正式支持 |
| 更多 MQ 适配 | RabbitMQ/Kafka 等按实际需要扩展既有消息/队列契约，分别验证确认、重投、顺序与故障恢复；不因驱动可连接就承诺等价可靠性 |
| 搜索 | 先定义索引同步、重建、查询权限与一致性边界，再选择适配；不把后台筛选页面等同全文搜索基础设施 |
| 运行时 feature flags | 先确定求值、缓存/共享传播、失败策略与审计；与 Cargo 编译期 features 分开，不作为 v1 必交 |
| 持久离线消息、可靠重放 | 跨节点在线路由/广播已是 v1 集群要求；可选模块 有真实需要时补消息持久化与离线重放，不把在线 Pub/Sub 当作可靠历史 |
| 移动推送供应商 | 扩展现有通知渠道与契约，不另建发送平台；没有真实目标/凭据时不假称验收 |
| SSR/静态页面 Starter | 按开发者画像单独评估，不改变已定 Admin Vue 路线；复用 v1 认证、CSRF、验证与安全模板能力 |
| 扩展包目录 | 先交付清晰 contract、独立示例与兼容测试，再建设包发现/目录；不做运行时任意代码加载 |
| 表单可视化/工作流 | 表单可视化可作为套件后续增强；任意 DAG、审批流程引擎及完整聊天系统不自动纳入两个版本的核心交付 |
| 外部密钥服务 | 不作为 框架与模块 默认依赖；仅有明确企业集成需求时扩展，本地加密与简单轮换继续可独立使用 |

## 设计建议与实施顺序

1. B1 契约与骨架：核对 v1 公开接口，按已定 pure-admin 精简国际化版 + Element Plus 与 uni-app 路线锁定兼容版本、上游提交、端侧角色/页面/权限矩阵和 API/数据模型，完成通用组件复用审计与 Rust API 适配原型；规划 PC 交互与技术方案，不启动 PC 实现。
2. B2 账号与组织：JWT/refresh 登录、用户/角色/菜单、部门/岗位、DataScope 和登录状态管理，按套件配置接入外部身份与 TOTP/恢复码；复用 v1 查询规则，Session 只有显式选择才启用，优先完成前后端授权与隔离测试。
3. B3 通用系统模块与视图：字典/参数、审计、通知/文件、任务/监控等 Admin 页面及页面矩阵中的 App 流程逐项接入 v1 能力，不复制框架逻辑。
4. B4 业务生成：选择代表性业务表走完生成、权限菜单、查询、导入导出与测试；明确增量生成/覆盖边界。
5. B5 交付验收：双库、前后端构建/测试、关键浏览器流程、App 目标平台构建与设备/模拟器流程、权限绕过、配置迁移/升级、性能/故障恢复、文档和干净环境路径；复测多副本权限传播、任务人工操作、通知与私有文件访问。H5 不替代 App 验收，PC 只交付设计；不能因 v1 集群通过而跳过后台管理面组合。

复用他人代码须遵守许可并记录来源，依赖版本与新增依赖需记录；不沿用已知漏洞或宽权限默认值。具体测试应覆盖默认配置及有效组合，失败先修复，不以截图或目录存在代替功能验收。
