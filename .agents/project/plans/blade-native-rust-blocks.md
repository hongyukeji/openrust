# Blade 原生 Rust 代码块开发计划

日期：2026-11-23。状态：方案定稿、实现完成，约定范围验收通过。验收范围与结果见末尾执行记录。

## 目标与推荐结论

为现有 Blade 增加可选的 `@rust … @endrust` 原生代码块：构建应用时将代码块编译为真正的 Rust 函数，渲染到对应节点时执行。保留现有模板语法、指令树、继承、组件、转义、翻译及缓存机制，不替换整套模板引擎。

这项能力是 OpenRust 扩展，不宣称完整兼容 PHP 执行语义。不能把有限表达式解释器或普通文本回调包装成“支持 Rust”。生产请求和 Artisan 运行期间不启动 Cargo／rustc，不要求部署机器安装工具链。

本计划只覆盖原生代码块，不扩展到历史讨论中的语言选择、欢迎页链接或其他功能。最初仅授权记录计划；2026-11-23 用户随后明确授权按本计划实施和验收，不授权暂存、提交、推送或发布。不向其他对话发送消息。

## 已核对的现状

- 固定行为基线见 [Laravel 对照基线](laravel-rebuild-baseline.md)：Framework v13.40.0，提交 `1449bf241017087fbd38c118ecaabef3f6797fdc`。
- `vendor/openrust/framework/src/view/compilers/blade_compiler.rs` 当前将模板编译为可序列化指令树，缓存版本为 39；这不是编译进应用的原生 Rust 渲染函数。
- 现有指令回调接收 `&[ViewValue]`，返回文本或 HTML，没有直接读写当前渲染作用域的契约。仅注册一个名为 rust 的指令不能完成本计划。
- `vendor/openrust/framework/src/view/compilers/template.rs` 显式拒绝 `@php`／`@endphp`／`@use`；没有原生 Rust 代码块实现。
- `vendor/openrust/framework/src/view/mod.rs` 的视图数据是 `IndexMap<String, ViewValue>`；任意应用对象、结构体方法和类型信息不会自动保留到模板。
- 现有文件引擎运行时读取模板；原生代码块必须补充构建产物与模板的一致性检查。
- 根 `build.rs` 已有迁移、Seeder、Factory 和包发现的构建期生成模式，应优先复用相同职责边界，而不是把通用模板生成器堆进应用入口。
- 前轮检查旧版 `v0.x` 的视图实现使用 MiniJinja，没有可直接复用的原生 Blade 代码生成管线。实施前按现行规范再次核对可复用部分。

以上是记录时快照。工作区已有协作者对 Blade 编译器、表达式、测试和三语文档的改动；实施前重新检查 Git 差异和最新实现，不覆盖其他工作，不沿用过期缓存版本数字。

## 调研依据与采用理由

以下官方源码／README 已在本轮联网读取。除固定 Laravel 源码外，其余读取的是当时默认分支，尚未固定提交，也未在 OpenRust 中集成验收；实施者须固定实际采用版本，核对许可证、维护情况、Rust 1.94.0 及依赖成本。

| 来源 | 链接 | 可借鉴机制与必要差异 |
| --- | --- | --- |
| Laravel 固定源码 | [CompilesRawPhp.php](https://github.com/laravel/framework/blob/1449bf241017087fbd38c118ecaabef3f6797fdc/src/Illuminate/View/Compilers/Concerns/CompilesRawPhp.php) | 将表达式转换为宿主 PHP 代码；继续核对 BladeCompiler 的原始代码块提取、编译执行链及对应测试，不能仅凭此文件解释全部块语义。Rust 改为应用构建阶段编译。 |
| Sailfish | [官方仓库](https://github.com/rust-sailfish/sailfish) | 模板内书写 Rust，通过派生与代码生成编译进应用；最接近目标机制，但使用另一套语法，不能直接当作现有 Blade 的替换件。 |
| Askama | [官方仓库](https://github.com/askama-rs/askama) | 模板在编译期根据上下文结构体生成类型安全的 Rust；借鉴构建与检查机制，不能据此声称动态 ViewValue 的字段和类型也能在编译期检查。 |
| Maud | [官方仓库](https://github.com/lambda-fairy/maud) | 宏生成 Rust，借鉴生成与转义边界；不将现有 Blade 改成 HTML 宏 DSL。 |
| Rust 语法及生成工具 | [syn](https://docs.rs/syn/)／[quote](https://docs.rs/quote/) | 实施前评估版本与功能集，优先复用解析和 token 生成，不手写 Rust 语法解释器；当前存在传递依赖不等于可直接作为构建依赖使用。 |

本轮没有找到已经验证可直接接入当前 OpenRust Blade 的完整方案。成熟项目支持的是机制选择，不能作为本项目实现正确或性能提升的证据。

不推荐直接换用 Askama、Sailfish、Maud：它们会改变现有模板语法、数据和运行契约。不推荐为加入一个指令就把全部 Blade 改为原生代码生成；如将来确需整份模板的原生词法作用域，应另做完整迁移评估。

## 推荐执行模型

1. 构建期：发现受支持的应用与包模板 → 解析原生代码块 → 生成 Rust 函数与来源映射 → 由应用构建编译并登记。
2. 模板编译：现有 Blade 指令树增加原生执行节点，引用对应构建产物；沿用现有分支、循环、组件执行顺序。
3. 渲染期：节点获得当前视图作用域 → 执行已编译函数 → 按明确契约写回视图数据 → 后续 Blade 节点正常渲染。

通用实现属于框架现有视图／编译职责；应用构建文件只保留必要接入。优先复用已有应用和包装配，不另建全局可变注册中心、平行视图框架或不必要的兼容层。具体模块、公开类型、方法和配置名称尚未定稿，不将本计划描述当成现有 API。

## 必须固定的行为契约

### 数据、作用域和执行顺序

- 使用明确上下文读取当前模板数据，明确写回需要供后续 Blade 使用的结果。最终 API 由最小闭环确定，避免每个代码块手写重复的类型转换和错误包装。
- 原生 `let` 变量遵循 Rust 作用域，不自动导出为后续 Blade 变量；不承诺自动将 `let title` 映射为 `{{ $title }}`。
- 可以对真正的 Rust 表达式做编译检查；动态键缺失、值类型不符仍须有清楚的运行期错误，不能宣传为全模板静态类型安全。
- 代码块在渲染到该位置时执行；未进入的条件分支不执行，循环按实际迭代执行。构建与 view:cache 不执行代码块或业务副作用。
- 读取当前循环、组件和 include 的有效数据；写回的可见范围、变量遮蔽与恢复按现有 Blade 作用域核对并明确记录，不让局部修改意外泄漏。
- 保持应用、请求、任务和嵌套渲染之间隔离；核对现有阻塞渲染线程的数据快照和 Send／Sync 约束，不引入共享可变全局状态。

### Rust 语法与错误

- 首版代码块是同步函数体中的真实 Rust 语句；`use`、局部变量、可调用函数等遵循生成位置的正常可见性与所有权规则，不承诺访问控制器栈上的任意变量。
- 确定 `?`、提前返回、返回值和错误类型的合法语义；不能让代码块中的 return 意外结束整个模板渲染。
- 不同时引入异步渲染运行时。需要 await 的 I/O 优先放入控制器、服务或 View Composer；文档明确同步上下文限制。
- 识别代码块边界时处理 Rust 字符串、原始字符串、注释及类似结束标记的文本，不能简单字符串切割造成误判；覆盖与 Blade 注释、verbatim、转义指令的交互。
- 编译／解析错误至少能定位模板路径和代码块位置。精确到任意 Rust 编译诊断的原模板行列映射需实际验证，不假定 token span 自动完成外部文件映射。
- 模板代码具有应用 Rust 代码权限，仅用于可信源码；这不是用户提交模板的沙箱执行能力。

### 输出与缓存

- 首版以计算及写回数据为主，输出复用现有 Blade 转义入口。正常插值继续 HTML 转义，原始 HTML 沿用既有显式契约，不新增默认无转义通道。
- 普通模板保留现有运行时行为；新增或修改原生代码需要重新构建应用。
- 对代码块身份、内容及必要的编译契约建立一致性检查；不能只依赖模板路径、块顺序或旧缓存存在，也不能让身份碰撞执行另一份代码。
- 不同二进制／构建版本、代码块新增删除重排、模板覆盖和缓存命中均不能静默执行旧代码。不一致时明确失败并提示重新构建。
- 只改普通 HTML 且原生契约未变时，尽量保留现有模板更新能力；具体失效粒度以安全且可验证的方案确定。
- view:cache／view:clear 继续管理现有视图缓存，不能暗中编译应用或删除已编译函数；缓存格式变化同步版本与回归。
- 运行时动态模板不能引入未构建的新 Rust 代码，明确拒绝而不是偷偷编译或忽略执行。

### 构建、包与部署

- 构建发现规则需明确覆盖应用视图、包视图和已发布覆盖视图，命名空间及优先级复用现有规则；不能运行应用启动流程来发现源码。
- 核对包代码的 Rust 可见性和依赖边界，不假设包模板生成到应用后可访问包私有符号；给出明确可用方式和失败说明。
- 通过 Cargo 依赖追踪覆盖模板修改、新增、删除及发现范围变化；不只监听已存在文件而漏掉新增模板。
- 保留独立二进制、资源复制及 standalone 部署约定，验证离开源码目录后可以运行，部署环境没有工具链也可渲染。
- 不为该功能新增默认示例业务 Provider、额外启动包装器或整套可选引擎依赖。依赖复用需检查许可证，并保留必要归属声明。

## 开发顺序与决策门槛

1. **重新核对。** 阅读根指引、当前交接、固定基线、视图范围指引与 Git 差异；复核上游源码／测试及旧版复用，不重复实现协作者已补齐的功能。
2. **最小闭环。** 在隔离验证范围完成“视图数据 → 真实 Rust 计算 → 写回 → Blade 转义输出”，包括非法 Rust 编译失败、未构建代码块拒绝、并发隔离。原型也走真实构建和渲染入口，不能只测辅助函数。
3. **固定正式契约。** 根据闭环结果确定公开名称、上下文借用／转换／写回、执行节点、构建登记、来源映射及失效规则；记录 Rust 约束和选择理由。常规选择由负责 Agent 自主处理，实际不可行项如实说明，不用空实现掩盖。
4. **补齐消费者。** 接入分支、循环、组件、继承、包视图、覆盖、缓存和部署；实现有意义的正反回归。
5. **验收与文档。** 同步三语 Blade 指南并完成实际消费者验收，再记录实现完成／验收通过及剩余阻塞。

若最小闭环必须付出整套视图重写或大量重复注册成本，应记录实测原因并重新评估范围，不以“架构已推荐”为由强推。不要承诺一次设计即可永远不变；公开 API 定稿应有真实闭环依据。

## 验收矩阵

| 范围 | 必须覆盖 |
| --- | --- |
| 真实 Rust | 标准库计算、函数调用、类型检查失败、借用失败、错误传播；结果确由构建后的代码产生 |
| 数据 | 读写、缺键、类型不符、空值、错误不吞掉；编译期与运行期错误边界 |
| 作用域 | 分支未执行、循环每轮、组件／include 局部覆盖恢复、嵌套视图和数据遮蔽 |
| 输出 | HTML 注入字符默认转义、已有原始输出契约、无意外双重转义 |
| 解析 | 多代码块、标记出现在字符串／注释、嵌套花括号、未闭合块、verbatim／Blade 注释交互 |
| 隔离 | 多请求不同数据／语言快照、两个应用实例、并发及重复渲染无串值 |
| 构建与发现 | 修改／新增／删除模板触发重建，应用／包／已发布覆盖视图优先级正确 |
| 失效 | 冷／热缓存、代码块变更／重排、不同二进制读取旧缓存、未知原生块显式失败 |
| 生命周期 | 构建与 view:cache 不执行块；view:clear 后仍能使用已编译块；运行时新 Rust 源码被拒绝 |
| 实际运行 | 控制器到视图的 HTTP 消费者、独立二进制搬迁、无源码／无工具链运行环境 |
| 既有功能 | 受影响 Blade 表达式、继承、组件、指令、翻译与缓存定向回归 |
| 质量 | Rust 1.94.0、适用 fmt／严格 Clippy／测试、三语内容检查与文档构建 |

按项目约定使用隔离源码及独占 Cargo 构建目录，全部临时源码、日志、参考资料和产物位于项目 `target/tmp/`，子进程 TMPDIR 同样在项目内；保留正常并发、增量和可复用缓存。触及 32 GB 停线按规范安全停构建、核对并持锁清理本项目编译产物。

本任务未改变数据库或缓存驱动时，无需为凑矩阵启动无关数据库／缓存服务。不能将跳过、编译成功或旧测试通过算作原生模板消费者验收。没有测量前不宣称更快；评估时分别观察构建耗时、产物大小与冷／热渲染成本。
