# 本地 AI 能力扩展

> 标识：`local-ai`；定位为阶段二的可选通用扩展。
> 状态：已授权规划，尚未实现或验收；不立即开工，不改变当前唯一 todo 队列及 C04-D1 主线。

## 目标与范围

让开发者通过 Laravel 风格的配置、容器服务及公开扩展，在自有服务器使用轻量模型完成内容审核和翻译，减少重复人工处理和第三方接口调用。以降低总成本为目标，不承诺零成本、零误判或完全替代人工/商业服务。名称中的本地指部署在应用方控制的服务器，不限定开发者个人电脑。

| 能力 | 交付边界 |
| --- | --- |
| 关键词过滤 | 词库、规范化及高效匹配，支持命中位置与替换；规则优先，不为确定性匹配引入模型。词库来源/许可证与更新策略明确，保留原文位置映射 |
| 文本语义审核 | 专用分类小模型识别经实际评估的广告、辱骂等类别；类别、语言、阈值和效果随模型版本声明，不笼统承诺所有敏感内容 |
| 图片审核 | 专用图像分类小模型评估声明的内容类别；先支持经验证的静态图片，不把图片分类等同 OCR、视频审核或全语义理解 |
| 机器翻译 | 专用翻译模型，显式源/目标语言、长度限制与术语/格式支持范围；只承诺验收过的语言方向，不以模型名代替质量证明 |
| 业务处置 | 输出命中项、类别分数及可选策略建议，由业务决定放行、拒绝或复核；人工流程/第三方补充通过公开接口组合，不内置运营后台 |

本扩展不替代已有 i18n 翻译文件、复数及语言回退；UI 固定文案仍使用 i18n，用户生成内容翻译是独立调用。训练/微调、通用聊天、Agent 编排、向量平台、视频/OCR不纳入首批；后续有真实需求再评估，不预建万能 AI 平台。

## Laravel 风格接入与架构

- 使用现有 ServiceProvider/Container、领域 config/.env、默认/命名模型配置及公开 driver 契约；业务通过审核、翻译服务调用，不直接操纵张量或第三方 eventloop。Facade 若提供，与 DI 共用服务，不另建全局推理体系。
- 按任务定义最小公开契约：文本/图片审核和翻译。模型分词、预处理、推理及输出解释封装在适配器内；不要求所有任务共用一种输出或一种万能模型。公共 API 名称、配置键和结果 schema 在 LAI-0 用真实调用示例收敛，本计划不把草拟名称当作既有 API。
- 外部开发者能注册自己的模型/driver，不修改框架 src；框架提供结果与错误边界，业务模块复用应用服务。沿现有上传扩展、验证、事件、Queue、Cache、Storage接入，不另造上传/任务/审核工作流引擎。
- 默认只在本地处理；不因低分、超时或模型缺失自动外发数据。只有业务显式配置并授权第三方适配器时，才允许后备调用；付费调用、计量和数据外发单独说明。
- 模型输出是评估结果。分数不直接当作校准概率；`uncertain`/不支持类别或语言明确返回。缺模型、超限、繁忙、超时和推理失败返回类型化错误，不能默认为审核通过；待复核状态与服务故障分别表达，处置策略由业务显式选择。

## 运行与资源边界

1. **真正可选**：未选择对应 Cargo依赖/feature，不编译专属推理/图像依赖、不注册服务、不加载权重、不创建推理线程或访问网络；文本、图片、翻译按实际构建成本隔离，不能选择文本就拉全部图像模型。最终 feature/package 拆分在选型后最小化确定，Cargo.lock 解析影响与默认构建隔离分开验收。
2. **成熟组件**：首选验证 ONNX Runtime + Rust `ort`，Candle 为模型适配或部署约束下的备选，不默认集成两个引擎。LAI-0核对具体版本、MSRV、许可证、算子/模型格式、量化、目标CPU及原生库打包；第一方保持 forbid(unsafe_code)，不要求生产主机安装 Python、训练环境、GPU 或自动安装系统软件。
3. **有界运行**：Provider 注册/校验不立即加载权重；已配置任务首次使用或显式预热时加载并复用。推理使用受限执行资源与并发闸门，不阻塞 Tokio 工作线程；同时限制引擎内部线程、排队长度、输入大小和输出量，避免每个 session 自建满核线程池。取消等待不等于已停止 CPU 推理，须验证原生调用截止/取消与关闭边界，不在取消后无界释放并发名额。
4. **同步与队列**：轻量请求可同步，图片/长文本/批量翻译优先复用现有数据库队列和独立 worker 运行角色。队列载荷存受权对象引用，不塞大型原始图片；重试有界，结果幂等。审核前公开发布、异步 pending 的可见性与租户访问由业务策略约束，示例不能先公开再审核。
5. **模型资产**：清单保存模型ID、不可变revision、任务/语言/类别、分词及预处理版本、格式、许可证、来源和校验值；权重与原生运行库作为明确部署资产，不放 Git、Cargo target 或默认应用安装包。安装/更新由显式操作或部署流水线完成，离线运行不偷偷下载或加载任意远程代码；应用缺资产明确报错。不执行模型包携带的脚本/自定义算子插件，额外格式须评估后显式纳入。
6. **升级与多节点**：首批采用固定模型版本与滚动重启，不承诺权重热替换。节点报告已加载版本，队列任务/缓存键携带模型和策略版本；跨版本结果不混用，旧任务版本不可用明确失败/待处理。共享DB持久化配置、任务和必要结果，Redis仅可选缓存；每节点权重需随部署迁移或从固定制品源校验恢复，不能承诺只迁DB就自动恢复模型文件。
7. **隐私和成本**：日志/指标默认只记模型版本、状态、耗时与资源，不记原始文本/图片；结果缓存按租户隔离，包含内容摘要、语言、模型/词库/策略版本并设置TTL，原文/译文缓存显式受控。图片解码限制字节数、像素、帧数与格式；默认接收受权存储对象，不让模型自由抓取URL。内容与译文不作为可执行命令，展示时沿业务转义规则。

管理员未来可在既定受权动态设置机制交付后通过该机制修改明确允许的阈值、词库或已安装可信清单内的模型选择，配置版本与审计复用现机制；模型文件加载和切换的生效方式须单独声明，首批不可热换的变更标记待重启。框架不提供强制后台或固定管理路由，也不为本扩展新建动态配置系统。

## 实施顺序与验收

阶段二在 Provider/配置/扩展契约、存储/上传及适用安全基础具备后启动；队列子项另依赖 Queue 已收口。与 MCP、AI模型平台、可选快速开发模块互不构成强制前置。现在只登记总计划入口，实际领取时分簇进入唯一 todo，不并行抢占当前核心工作。

| 顺序 | 工作 | 验收要求 |
| --- | --- | --- |
| LAI-0 可行性与 Spec | 每种任务选择候选模型，先定义质量/资源/成本目标，再测效果；确定最小公开API、配置、结果/错误与原生依赖打包 | 固定引擎/权重/许可证/格式/CPU与测试语料；候选适配失败保留缺口，不以加载成功等同可用。普通无GPU Linux CPU为必验方向，4核8GB仅首轮试验规格，不能作生产承诺；质量或资源不达标先调整模型/范围，不直接上重型平台 |
| LAI-1 接入与词库 | Provider、按需依赖、模型清单/加载/预热与受限执行，词库驱动 | 默认构建无专属依赖/加载/网络；未调用且未预热时不加载权重或启动推理；公开consumer可替换；Unicode/绕写/原文命中边界、版本和加载失败有测试 |
| LAI-2 文本审核与翻译 | 真实文本分类与固定语言方向的专用翻译模型，缓存和必要队列调用 | 独立保留语料测分类准确率/召回/误报、阈值及不确定性；翻译评估由独立参考与适用人工评审补充，不能模型自评代替。记录P50/P95延迟、峰值内存、CPU与吞吐，缓存不得混租户/版本 |
| LAI-3 图片审核 | 真实模型、解码边界及上传隔离/复核接入示例 | 有权使用的代表性图片测误报/漏报和资源；损坏/超大/非承诺格式可控失败；上传前后公开扩展可用，无 pending 内容泄露 |
| LAI-4 交付与部署 | 唯一 modules/example、生成应用、README/config、公开扩展与部署说明 | 真实CPU模型端到端、并发过载/超时/关闭、离线安装及迁移/滚动升级；适用双库队列及租户隔离；生成应用check/test与仓库门禁，fake只用于业务单测，不替代推理效果和部署验收 |

资源与成本测试必须同时观察普通HTTP请求的P95、引擎线程和worker进程总内存；同机应用/DB/Redis的资源预算单列。报告词库/模型各命中比例、人工复核率与第三方调用减少量，比较新增计算、维护及模型升级成本；不预填未经实测的节省比例或吞吐。
