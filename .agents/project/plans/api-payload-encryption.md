# API、SSE 与 WebSocket 加密及客户端接入

> 状态：仅规划，阶段二可选增强；不属于 Laravel 内置双向加密协议，不启动被冻结的 V2 界面开发。执行状态仅在[唯一待办](../todo.md)。

## 开发者选择边界

提供通用的可选API请求/响应正文、SSE事件及WebSocket业务消息加密能力，不限定业务用途，由开发者按需组合。加密不替代服务端认证、对象/字段级授权、输入验证和资源限制；控制客户端的人仍可观察解密后的数据，敏感数据继续按最小权限返回。验收覆盖与既有安全机制组合时的行为边界，不因正文加密放宽权限或隐藏错误。

这是供开发者按需选用的方案，不是标准应用或前端的强制要求。未启用扩展时使用宿主选择的HTTP或HTTPS与普通JSON，业务可继续使用现有认证和请求封装；仅显式引入扩展并为选定路由/路由组挂载中间件时启用正文加密。未使用者不承担专属第三方依赖、握手、防重放存储或Vue加解密封装的配置与运行成本；普通生成项目不默认启用，提供按需接入示例。不要求同时加密所有接口，不自动改写HTTP状态、统一返回或现有认证协议。正文加密协议不因HTTP传输而拒绝启用，生产部署仍建议HTTPS；认证、Cookie等既有传输安全策略独立生效，不为兼容HTTP而自动放宽。

## Laravel 式最小接入体验

- 普通开发者路径为“按需引入扩展→在既有领域配置中提供必要密钥/可信来源→通过现有路由/路由组挂载一次加密策略”。全站业务API可在顶层API组统一启用，并有清楚的排除规则；不要求每个Controller标注、手写加解密或修改Request/验证/Resource。Provider沿既有注册/发现机制接入，不另建启动体系。
- 协议版本、算法组合、随机材料、密钥标识、请求关联、响应上下文、防重放与错误映射由扩展封装，提供安全默认值及少量必要配置；不要求普通用户理解JWE字段或逐请求组装协议。密钥/信任配置缺失明确报错，不能生成默认共享secret或静默降级。
- Vue适配器和Apifox脚本一次安装/导入后，业务继续提交普通JSON并接收解密结果，成功和错误路径均适配。不得把nonce、时间戳及响应密钥维护推给每个页面或接口脚本作者。
- 全站API策略覆盖HTTP业务正文、SSE事件和WebSocket业务消息，不承诺所有HTTP字节或协议控制帧加密。GET/空正文的响应上下文、初始化公钥、上传/下载及解密前错误须在Spec给出默认处理或显式排除；不暗改HTTP方法、不破坏状态码和认证，未支持场景明确诊断。
- 从干净生成应用按文档完成顶层API组配置，用普通Controller/Resource及现成Vue适配器、Apifox脚本完成正常/错误调用，不编写额外密码学代码；局部和全组启用、未启用应用无额外配置负担均须验收。不能用伪API片段或仅底层库测试代替开发者接入路径。

## Spec 与职责

1. 业务数据加密与传输方式解耦，HTTP/HTTPS及WebSocket的ws/wss均纳入服务端适配；JWT/Session、Gate/Policy、CSRF与限流继续承担身份和访问保护。普通HTTP首要覆盖有界JSON，SSE/WS另作逐事件/逐消息适配，不替代TLS，不宣称防止浏览器用户读取自己的数据。
2. 复用Provider/Container、领域config与现Request/Response/Resource及异常渲染。框架提供公开加密服务、必要Contract与可挂载中间件，不固定HTTP路由、公钥地址或后台；宿主自行定义路径与授权。未选择扩展不引入专属依赖，未挂载的接口照常处理。
3. R7先收敛密钥/安全contract，R3请求及响应生产链路稳定后于R11阶段二集成，R14完成真实多节点/双库验收。现Encryptor的or1封装是应用数据格式，不当作JWE或现成跨语言协议，不另建请求输入仓储或密码算法。
4. HTTP优先评估成熟JWE实现；SSE/WS评估同一成熟组件的逐事件/逐消息认证封装，不把持续流整体缓冲后加密或自创流密码。共同协议Spec固定版本、允许的alg/enc、kid、内容类型/子协议、认证数据和资源上限；拒绝任意算法、远程密钥地址或自动降级。Rust与浏览器库的算法交集、许可证、维护和Web Crypto兼容性先验证，再选型登记stack，不本轮安装依赖。

## 密钥与交互边界

- 请求采用受信服务端公钥的标准混合加密；私钥仅服务端保存，所有节点按统一轮换窗口接受新旧kid。公钥由宿主通过受信渠道分发，可随可信客户端预置/固定、通过认证的签名材料验证，或经HTTPS获取；不能把普通HTTP上未验证的公钥当作可信身份，不由客户端指定任意jku/x5u等远程地址。
- 响应接收方必须能解密，不能只用服务端公钥加密回复。优先评估浏览器为每次请求生成短期响应密钥，并把它放入发给服务端的加密请求内；服务端按已验证协议加密响应。该候选需安全审查和JWE互操作后定稿，不能把任意客户端公钥直接视为已认证身份，也不能自创握手协议。
- APP_KEY、服务端私钥和长期共享secret不得进入Vue源码、VITE_*或localStorage；短期密钥只在内存按请求持有并清理。内存密钥也不能防御同源恶意脚本/XSS，不能把正文加密当作XSS修复。
- 方法、规范化目标、请求ID、签发/过期时间须处于协议认证保护并与实际请求核对，响应绑定同一请求ID；JSON序列化/URL规范化与代理边界在Spec固定。不以加密nonce代替业务防重放。
- 防重放使用身份/会话隔离的短期请求ID与共享原子去重，配置允许时钟偏差与TTL；共享存储失效显式拒绝，不退回节点内存。重试生成新传输请求ID/随机材料；业务幂等键保持同一操作语义，不能把防重放等同可靠业务幂等。
- 明确中间件与解密后的规范化/验证、认证/授权、Cookie/CSRF的顺序：先做可用的身份与密文资源检查，解密后走唯一Request内核，不能让依赖明文的授权提前错误放行。GET敏感查询、multipart、下载及任意字节流不自动转换；SSE/WS按下述专用适配交付，不把JSON中间件直接包在无限流外层。
- 保留HTTP状态。已成功建立加密上下文后，业务结果及适用异常通过同一响应加密出口；解密前失败采用脱敏普通错误，不回显密钥/明文/密文或密码细节。声明哪些错误必须加密，客户端遇到预期加密却收到成功明文时拒绝，不能静默降级。敏感响应使用合适no-store策略，日志/观测不记录secret。

## 全站与局部策略

- 使用同一公开策略及Laravel式路由组/单路由挂载入口，支持顶层API组统一启用、子组/单接口选择及显式排除。这里的“全站”是宿主选定的API范围，不自动接管静态资源、第三方域名和浏览器全部流量。
- 父组要求加密时子项默认继承，明文例外只能由开发者在服务端明确声明；同一路由重复/矛盾配置须可诊断，未知策略启动失败。最终优先级/入口名称先Spec，不允许客户端参数或缺少加密头把服务端required策略降为明文。
- 公开例外与受保护接口必须清晰分开；预检OPTIONS、HEAD/204/304等无正文响应、初始化信任材料、health及上传下载按语义明确处理，不为完整覆盖制造递归握手或给空响应强塞密文。禁止“识别不了就明文放行”，未支持内容协商明确拒绝或按服务端显式排除处理。
- HTTP中间件负责正常请求/响应，SSE事件出口与WebSocket会话/消息适配挂到现有生产生命周期；现有handler处理普通业务值，基础请求验证/频道授权仍复用现内核。WS升级响应上的HTTP中间件不代表已保护升级后的消息。

## SSE 与 WebSocket 专用适配

当前事实以[实时模块](../core/realtime.md)为准：已有SSE/WS在线推送与共享transport资产，但SSE不支持Last-Event-ID回放，现WS主要处理关闭/心跳；不能把既有推送称为已具备加密双向业务消息。新增适配及必要业务收发契约按R11 Spec补齐，复用现会话/transport，不复制第二实时服务。

| 通道 | 加密单元 | 保持原语义 |
| --- | --- | --- |
| HTTP | 单次请求/响应的有界业务正文 | 原方法/状态/认证、Request/Resource/异常链 |
| SSE | 每条业务事件的data中放认证密文 | text/event-stream、UTF-8、flush/心跳/取消与背压，不缓冲整个流 |
| WebSocket | 完整业务消息经认证加密，接收后验证再交handler | ws/wss握手及标准帧结构、fragment重组边界、Ping/Pong/Close保持协议语义 |

- 三种适配共享可信密钥与授权基础，密钥按用途/方向及连接隔离；会话建立、密钥确认、超时、版本/能力协商先Spec并复用成熟协议构件，不自创密码握手。未完成认证/密钥确认前不发送应用数据、不加入敏感频道，初始化报文有严格大小/速率/期限，拒绝明文降级。
- 流会话epoch/连接ID、消息序号、方向、频道/事件类型等必要上下文纳入认证保护，密钥下nonce不得复用；序号上限/轮换/重连、重复/乱序/跨连接及跨方向替换有明确失败语义。方案在成熟组件与互操作安全审查后冻结，不以一个共享计数器覆盖所有节点。
- SSE只单向推送，密钥建立/参数提交需客户端适配负责。默认评估fetch流读取器以便使用认证头和显式上下文；原生EventSource不支持任意自定义请求头，不能假装Axios拦截器能控制它。保留可用且实测的Cookie/原生EventSource适配边界，不把秘密或Bearer token塞URL。
- SSE保持标准data/event/id/retry与心跳语义，业务事件类型等敏感信息可放密文内并使用通用外层event；所有可见字段列入元数据边界。重连需新加密会话并重新授权；Last-Event-ID只是游标，不能当作认证凭据、恢复nonce计数或持久回放保证。若底层无持久事件日志，明确不保证断线消息补回/恰好一次；有回放时明确去重和新会话重新加密规则。
- WebSocket浏览器构造器不能任意添加Authorization头，优先沿既有安全Cookie/Origin或受控短期握手机制，具体选型与非浏览器Token路径分别验收；任何临时票据须有界、绑定且不得当长期密钥暴露。只加密业务消息，不修改标准控制帧、不把mask视为加密。明确文本/二进制类型及内容大小，先限定已验收的业务消息格式，不假称任意文件流已支持。
- 逐连接限定明/密文、重组帧、待解密队列和待发送缓冲的大小/数量/时限；慢客户端背压或关闭，不无界spawn加解密任务。解密失败、篡改、超限、会话过期/撤销与轮换超时按可观察错误/关闭语义终止；流开始后不尝试改HTTP状态。
- 重连与滚动部署重新协商密钥，已发业务消息不自动重发成重复副作用；应用ACK/可靠投递仍按原服务契约，不因加密宣称实现。跨节点广播复用现共享transport，按连接/授权域在交付边界加密；不把单个客户端密文广播给无对应密钥的其他用户，不扩大本扩展到数据库/Redis全链路加密。

## Vue 接入方式

Vue组件只调用普通业务方法；在独立Axios实例内处理协议，不把加密逻辑散落各页面，不全局影响第三方请求。必须交付可直接引用的TypeScript请求适配器及完整接入示例，不能只写流程或要求开发者自己拼装加密代码；这是通信工具，不是UI组件，也不启动V2。交付Axios、SSE与WebSocket薄适配，协议核心与Vue组件解耦；共同配置、信任与消息封装复用，不为三个适配各造一套客户端内核。

- 对外提供一个明确的初始化/安装入口（最终名称待协议Spec），接收宿主Axios实例、公钥可信来源及显式接口范围，内部封装JWE编解码、密钥/请求上下文、成功及错误拦截；返回可释放句柄，避免重复安装拦截器。业务调用保留普通post/get及Axios响应/错误类型，不另造与现有前端冲突的请求体系。
- 示例须包含依赖声明、TypeScript类型、初始化、同项目普通/加密接口并存、业务调用、错误展示、取消/超时、重试边界、密钥轮换和释放；标明Vue SPA/SSR作用域隔离，不在共享服务端模块保存用户密钥或token。未选扩展不要求安装前端加密依赖。
- Vue3/Vite生成或示例项目实际运行，使用同一适配器与真实Rust服务双向交互；验证并发响应不串线、非2xx解密、重复安装/卸载、轮换及不降级、HTTP/HTTPS兼容范围。协议与Rust服务尚未定稿时不提供伪装为可用的演示实现，不以mock替代端到端验收。代码组织及导出入口在实施Spec确定，保持同仓维护，不本轮建立独立前端产品或发布npm包。

- 使用成熟浏览器JWE库候选[jose](https://github.com/panva/jose)与Web Crypto；精确版本/算法待Spec冻结。按宿主约定获取和缓存经验证的公钥，验证kid/轮换，不能相信密文本身给出的任意密钥来源。
- 浏览器兼容性单独验收：Web Crypto的subtle接口要求安全上下文，HTTPS页面访问HTTP API还受混合内容策略限制；localhost等例外与原生客户端须分别验证。不得声称任意公网HTTP Vue页面均可直接使用jose/Web Crypto，不自动引入不安全随机数、降级算法或绕过浏览器限制。HTTP环境的客户端选型及可信脚本/密钥分发方式在Spec明确，不能只换请求URL就宣称可用。
- 请求拦截器只处理显式标记的同源/允许目标JSON请求：序列化业务值、建立请求关联及短期响应密钥、加密并设置协议Content-Type。限制密文大小，防止重试重复加密，令牌/Session沿已有认证流程。
- 成功与错误响应都经过同一受限解密器：核验协议类型、允许算法及请求关联，再把明文JSON交给原有API响应处理。Axios非2xx走错误分支，同样解密后保留status与reject语义；取消、超时、并发请求、重试、退出登录均清理相应上下文。
- 公钥轮换可有一次有界刷新；已经发出的非幂等请求不能因解密失败/密钥失效就自动重发。业务重试依已定义的幂等契约，不自动重做支付/发信。
- SSE适配器提供解密后的事件订阅及关闭/取消入口，WS适配器提供普通业务消息send/receive与受控连接状态；密钥协商、逐条校验、顺序及重连由适配封装。浏览器WS缺少内建发送背压需有界策略，事件异步解密不得改变原交付顺序；这些不是UI组件，不自动注册全局连接。
- 文档提供上述可直接引用的请求/事件/消息适配器和普通业务调用方式，既有项目只需在请求初始化处接入；不预设全局UI或管理路由，不扩张成通用前端SDK。

## Apifox 调试工具接入

必须交付可直接复用的Apifox前置/后置脚本和可导入调试示例，与Vue使用同一已冻结协议、测试向量及可复用编解码核心；Axios只是传输适配，不把Axios/Vue或浏览器专属全局对象耦合进协议核心。不建设通用前端SDK平台，其他工具按实际脚本运行时验证后扩展，不承诺所有工具直接兼容。

- 前置脚本在变量替换之后读取最终业务JSON，绑定实际方法/目标与请求ID，生成并加密报文，更新正文及Content-Type；用户仍编辑普通JSON。防止第二次发送把上次密文当明文重复加密，重试与认证遵同一协议。
- 后置脚本读取真实响应，完成协议校验、请求关联及解密，再供展示与业务断言使用；保留原HTTP状态和可检查的原始密文，不修改状态伪造成功。解密失败须使测试明确失败，不输出密钥；非2xx和解密前普通错误分别处理。
- 短期响应密钥仅保存在已验证的请求隔离临时上下文，不能放团队共享/同步环境或日志；必须实测前后置变量作用域及并发关联，不能用一个全局变量承载所有请求。示例只提供公钥/占位值和最小接入配置，不导出服务端私钥、APP_KEY或真实token。
- Apifox脚本不是完整Node.js或浏览器环境，必须核实工具版本、模块格式、异步等待、Web Crypto/安全随机数和所选JWE算法支持。内置crypto-js或RSA示例不等于支持所选JWE，不为兼容而改成无认证加密或自创算法。优先交付固定版本、可审查的本地脚本产物/受支持的导入方式；不把每次请求动态下载未固定代码作为默认依赖。
- 首先验收实际Apifox桌面版的导入、普通JSON编辑、前置加密/后置解密展示与断言、并发/错误/轮换/重试及HTTP/HTTPS路径，联调同一真实Rust服务。Web版、CLI/自动化运行器与其他工具分别记录支持矩阵和限制，未验证不称支持；可用假测试验证转换逻辑，但不能代替真实Apifox运行证据。

依据：[前置脚本](https://docs.apifox.com/pre-request-scripts)、[后置脚本](https://docs.apifox.com/post-request-scripts)、[变量替换后加密](https://docs.apifox.com/5831263m0)、[JS类库](https://docs.apifox.com/js-libraries)。HTTP前后置脚本不能假称自动拦截SSE持续事件或WS帧；SSE/WS调试需核实Apifox实际版本的持续消息脚本钩子，支持时交付可直接使用的适配，不支持时明确限制并提供同协议的可运行诊断示例，不能假造工具能力。官方文档提供前后置扩展点，但外部库与运行环境兼容性仍须选型实测，不据此宣称jose可直接在全部Apifox环境运行。

## 验收与证据

Rust↔浏览器真实双向JWE互操作，篡改/未知kid/错误算法/过期/重放/跨路由与跨请求替换、缺认证/无权限、错误正文解密、轮换/并发/取消/非幂等重试、超限/明文降级拒绝。验证无依赖应用不引入专属包、无中间件接口不变化、正常Request/Resource及异常链无二次读取。

唯一modules/example提供模块自定路由真实调用，生成应用按需引入并check/test，Vue浏览器实际请求，服务端HTTP与HTTPS两条路径、浏览器安全上下文/混合内容支持矩阵、至少两个API节点共享防重放状态；PostgreSQL18/MySQL8.4及实际选择Redis路径验证故障不静默退化。动态设置若支持该扩展仅暴露安全白名单，密钥轮换不能以普通Config::set冒充资源热替换。未实测互操作/集群不标完成。

### 扩展验收补充

- 全组继承/局部启用/显式排除/策略冲突与客户端降级企图；HTTP/SSE/WS正常认证及失败，空正文/错误/预检/内容类型边界。
- SSE真实浏览器逐事件及时解密、UTF-8/多行分块、代理flush/心跳、取消、重连/过期/授权撤销、Last-Event-ID边界；WS双向文本/二进制已支持格式、fragment/控制帧、密钥确认期限、消息篡改/序号/跨方向与跨连接重放、慢读/缓冲上限及关闭。
- 至少两个API节点、共享防重放与在线广播、重连跨节点、滚动部署/密钥轮换、共享服务失败和资源回收；PG18/MySQL8.4及实际Redis路径真实执行，验证无任务/密钥/连接泄漏。SSE/WS不能仅以普通HTTP单测或fake完成；Apifox各通道支持矩阵单列。
- 按HTTP→SSE→WS的依赖拆可验收子簇，可先提交HTTP，但三种通道全部达到既定验收前，不宣称整个加密扩展完整交付。V2仍冻结；本轮文档无实现、依赖安装或服务变更。

## 依据

- [Laravel Encryption](https://laravel.com/docs/13.x/encryption)：应用加密职责，不能直接等同API协议；实施时固定到仓库上游基线。
