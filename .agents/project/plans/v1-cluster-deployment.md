# v1 集群部署与多副本一致性

> 受众：AI Agent
> 更新：2026-10-25
> 摘要：集群部署是 v1 必须交付与验收项；定义多副本正确性、共享状态、实时跨节点路由、故障恢复及部署边界，不代表已经实现。

## 必须支持的拓扑

- 一个负载均衡入口，至少两个 API 副本；worker 与 scheduler 可独立运行多个副本，使用共享 PostgreSQL 或 MySQL，按需使用 Redis 和共享存储。
- 单机与集群均为正式拓扑：标准应用默认 Redis（见 [ADR-015](../decisions/adr-015-redis-default-calibration.md)），memory/file 显式选择，库层 feature 按需组合，见 [ADR-013](../decisions/adr-013-deployment-and-redis-cache-default.md) 与 [ADR-014](../decisions/adr-014-cache-driver-and-store-contract.md)。进程内 memory、节点本地 file 和本地磁盘不能作为集群权威共享状态；依赖共享语义的能力必须显式配置兼容的共享后端。
- 不将黏性会话作为 HTTP 身份、幂等或授权正确性的前提。实时连接在建立后由所在节点维护，但消息必须能路由到其他节点上的目标连接。
- 不要求框架实现数据库 HA、负载均衡控制面或自研共识协议；提供依赖要求、配置示例和故障行为。节点故障容错不等于数据库/存储已具备高可用。
- 复用既有能力与 [v1 覆盖计划](v1-capability-coverage.md)，每类职责仍一个入口。集群支持不改变本地加密不依赖外部服务的约束。

## 逐能力的集群要求

| 能力 | 必须满足的行为 | 建议与验收 |
| --- | --- | --- |
| HTTP/负载均衡 | 多节点健康/就绪、可信代理配置、请求 ID 和节点可观察性 | API 基本无状态；测试轮询访问和节点摘除，不记录敏感配置 |
| Session/认证 | 任意节点可识别有效会话，轮换/撤销按明确时限在所有节点生效 | 默认共享数据库、Redis 可选；访问 A 登录后访问 B，撤销后 A/B 都拒绝；实时连接撤销另测 |
| 缓存 | 明确权威缓存和节点本地缓存，跨节点失效有明确策略 | Redis 共享驱动与本地 memory/file 范围分开；依赖共享语义的功能禁止静默降级到本地 |
| 限流/验证码 | 全局配额、尝试次数、重发频率及一次消费不能通过切节点绕过 | 复用共享存储和原子操作；并发请求分布到多节点验证 |
| 请求幂等 | 同身份/接口/键跨节点竞争仍只提交一个受保护业务结果 | 数据库唯一性和事务优先，补并发、进程崩溃及恢复；外部副作用仍有独立幂等约束 |
| 锁与租约 | 所有权、续约/超时、持有者退出及过期持有者行为明确 | 原子释放、所有权令牌；需保护共享写入时评估 fencing 或数据库事务，不能仅靠 TTL 宣称无重叠 |
| 队列/任务链/批处理 | 多 worker 竞争领取、租约恢复、重试与取消的状态共享 | 复用数据库 SKIP LOCKED，明确至少一次执行与任务幂等，节点退出不使任务永久卡死 |
| 调度 | 多 scheduler 对相同计划触发点产生一次受保护投递 | 唯一触发记录/锁，补长任务与节点退出测试；不把投递去重描述为外部副作用恰好一次 |
| 迁移/seed | 多副本启动不会并发破坏 Schema 或重复初始化 | 推荐独立迁移部署步骤和迁移锁；开发自动迁移与生产策略区分，seed 幂等由应用明确 |
| 文件上传下载 | 任意 API 节点都能访问已上传文件及权限状态 | 使用 S3 兼容或明确配置的共享文件系统；本地磁盘不能宣称跨节点共享，临时文件和清理有界 |
| WebSocket/SSE | 发送端与目标连接在不同节点时仍能授权路由/广播，断开和迁移可恢复连接 | 至少一个真实跨节点 transport；跨节点路由纳入 v1，持久离线重放不是默认保证 |
| 事件与通知 | 清楚区分进程内事件与跨节点通知，每条连接不无故重复推送 | 复用通知/队列与实时 transport；在线路由、集群消费者与广播订阅语义分别设计 |
| 加密/签名 | 所有副本拥有兼容密钥配置，滚动轮换中可互相解密/验签 | 本地运算，按已有轮换计划先分发解密配置再切写入，密钥不进日志，不需要云 KMS |
| 配置与状态变更 | 静态配置的发布方式、运行期共享状态及传播时限明确 | 不暗示所有 TOML 修改自动全局同步；缓存失效/授权更新有可验证时限和诊断 |
| 停机与滚动升级 | 先撤就绪/摘流，再处理在途请求和连接，worker 交接与超时明确 | 新旧副本混跑、扩缩容、强制终止和数据库短暂故障都有验证 |

## 需要设计决策的建议

- 标准部署默认以 PostgreSQL/MySQL 为外部基础依赖，队列/会话复用共享数据库；Redis 是需要缓存跨节点共享时显式启用的服务。依赖共享语义的能力必须配置可用共享后端，不能静默退化为本地状态。
- 共享缓存、限流、验证码与锁按能力需求选择实际可用后端。集群配置缺少必需共享实现时启动报错并给修复路径，不能以进程锁或本地 map 替代分布式保证。
- 实时 transport 优先评估现有共享数据库通知表/轮询或可选 Redis 等成熟机制；必须支持双库部署路径或明确所选依赖条件。根据延迟、吞吐、清理与运维成本形成 contract，再选一个可验证实现，不为每个后端建消息平台。
- 在线推送明确临时断线/transport 故障时的丢失、重复与重试语义；业务关键数据经权威 API/存储确认。可靠离线历史重放可列 v2，不以临时 Pub/Sub 宣称可靠送达。
- 租约时间与触发时刻优先使用共享存储时钟；节点标识只用于诊断和所有权，不依赖不受管理的机器编号生成全局唯一业务主键。
- 集群关键指标包含节点身份、在途请求、连接数、共享存储等待、任务积压及实时投递耗时；不要用高基数的用户/连接标识作为默认指标标签。
- 先沿用通用 contract，补有界资源和并发保证；API/配置命名、默认时限、失效传播 SLA、锁/transport 与部署依赖需设计 Agent 定稿，不在本计划硬编码任意数值。

## 必过的多副本验收

1. 同一个构建产物启动两个以上 API、副本化 worker/scheduler，经过真实负载均衡访问；PostgreSQL 与 MySQL 分别完成基线测试。
2. 在 A 登录、B 请求；切换节点不能绕过验证码/限流；撤销权限/会话后按声明时限验证所有节点及既有实时连接。
3. 多节点同时使用同幂等键、同锁和同调度时段，验证业务结果、释放/续约、投递与恢复行为。
4. 在 A 上传、B 下载；在 A 建立 WebSocket/SSE，B 触发目标通知；验证授权、跨节点投递及断开清理。
5. 领取任务后强制终止 worker，确认恢复；暂停持锁节点直至租约过期再恢复，检查过期持有者不会破坏声明的写入保证。
6. 通过负载均衡摘除/终止一个 API 节点并滚动升级、扩缩容，记录请求错误、恢复、连接重建与资源占用；依赖故障也需观测。
7. 提供可复跑的多容器示例、测试脚本、配置/共享存储要求、反向代理与滚动发布说明；不只运行两个互不通信的进程。

以上是验收要求，不要求自动对用户真实服务器部署。依赖高可用、数据库备份和编排平台由部署侧负责，文档明确责任边界；框架必须给出在其声明条件下通过的证据。

## 执行顺序

- M2/M3 先审核数据库、会话、限流、验证码、幂等与密钥契约，避免后续推翻单节点假设。
- M4 落实任务竞争、租约、调度/迁移与通知路由；M5 接入共享存储/缓存、WebSocket/SSE transport 和可观测性。
- M6 完成双库多副本、滚动/故障恢复和性能验收。当前 WIP 先闭环，不同时开启多个功能簇；新增依赖和公共接口照仓库规则先设计后实现。
