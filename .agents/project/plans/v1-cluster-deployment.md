# v1 集群部署与多副本一致性

> 受众：AI Agent
> 更新：2026-10-27
> 摘要：集群部署是 v1 必须交付与验收项；定义多副本正确性、共享状态、实时跨节点路由、故障恢复及部署边界，不代表已经实现。

## 当前证据边界

现有证据覆盖 PostgreSQL/MySQL 读写复制拓扑、部分认证共享状态、队列基础与 scheduler 双进程竞争/退出，以及 WebSocket/SSE 经 Redis Pub/Sub 的独立双 API 节点在线消息路由；这些证明各自契约的局部行为。经过负载均衡的完整多 API/worker/scheduler 拓扑、共享文件、gRPC 多节点完整集成、滚动升级、扩缩容和持续负载故障恢复仍待完成。已有证据见 [数据库](../core/db.md)、[认证](../core/auth.md)、[队列](../core/queue.md)、[调度](../core/schedule.md) 与 [实时通信](../core/realtime.md)。

## 必须支持的拓扑

- 一个负载均衡入口，至少两个 API 副本；worker 与 scheduler 可独立运行多个副本，使用共享 PostgreSQL 或 MySQL，按需使用 Redis 和共享存储。
- 单机与集群均为正式拓扑：标准应用默认 Redis（见 [ADR-015](../decisions/adr-015-redis-default-calibration.md)），memory/file 显式选择，库层 feature 按需组合，见 [ADR-013](../decisions/adr-013-deployment-and-redis-cache-default.md) 与 [ADR-014](../decisions/adr-014-cache-driver-and-store-contract.md)。进程内 memory、节点本地 file 和本地磁盘不能作为集群权威共享状态；依赖共享语义的能力必须显式配置兼容的共享后端。
- 不将黏性会话作为 HTTP 身份、幂等或授权正确性的前提。实时连接在建立后由所在节点维护，但消息必须能路由到其他节点上的目标连接。
- 不要求框架实现数据库 HA、负载均衡控制面或自研共识协议；提供依赖要求、配置示例和故障行为。节点故障容错不等于数据库/存储已具备高可用。
- 复用既有能力与 [v1 覆盖计划](v1-capability-coverage.md)，每类职责仍一个入口。集群支持不改变本地加密不依赖外部服务的约束。

## 逐能力的集群要求

| 能力 | 必须满足的行为 | 建议与验收 |
| --- | --- | --- |
| HTTP/负载均衡 | 多节点健康/就绪、可信代理配置、请求 ID 和节点可观察性 | API 基本无状态；测试轮询访问和节点摘除，不记录敏感配置 |
| gRPC/HTTP2 | 至少两个 gRPC 节点、标准 health 与摘流、明确 RPC 负载分配和流断开语义 | 按 [ADR-040](../decisions/adr-040-grpc-integration.md) 验证四类 RPC、TLS/mTLS、metadata 身份/trace、deadline、慢流背压、滚动退出及重连；连接级均衡不能冒充逐调用分配，已有流不自动迁移 |
| JWT/Session/PAT 认证 | JWT 为 API 主路径，refresh/可选 Session/PAT 共享状态与撤销时限明确 | JWT access token 本地验签，当前不逐请求查询撤销状态，不能声称登出立即使已签发 access token 失效；refresh family、Session、PAT 按各自共享存储契约验证 A/B 轮换/撤销。可选 Session 默认数据库，启用 Redis 驱动的路径须以真实 Redis 验收；实时连接过期/撤销另定契约并验收 |
| 可选租户/查询规则 | 可信作用域覆盖已登记的数据、缓存/锁、任务、文件与审计 | F5/F6 在两 API 节点和 worker 验证租户串用、缺上下文、批量/关联绕过及跨租户授权；默认关闭路径另验 |
| 外部身份、MFA 与 SSO | Provider 绑定、短期挑战、恢复码与关联会话撤销状态共享 | F7 跨节点回调/挑战、恢复码并发消费、issuer/绑定冲突和限流，双库验证；另按 [SSO 范围](v1-foundation-completion.md#sso-登录与统一退出) 验收双 client/每应用多副本的登录与统一退出、旧 challenge/refresh 竞态、通知故障恢复和 JWT 声明时限；不能用双副本替代双应用 |
| 通用数据交换 | 导入/导出任务、授权范围与私有产物可跨节点执行和访问 | F8 验证 worker 接管、重试/取消、分批事务与报告清理；不同节点仍执行相同租户/权限规则，不依赖 API 节点本地文件 |
| 缓存 | 区分共享与节点本地，tag/SWR/加载协调按作用域保证 | F4 真实 Redis 双节点失效/旧 loader 回填、陈旧时限、锁过期与停机回收；故障不得退回本地，不声称 loader 恰好一次 |
| 限流/验证码 | 全局配额、尝试次数、重发频率及一次消费不能通过切节点绕过 | 复用共享存储和原子操作；并发请求分布到多节点验证 |
| 请求幂等 | 同身份/接口/键跨节点竞争仍只提交一个受保护业务结果 | 数据库唯一性和事务优先，补并发、进程崩溃及恢复；外部副作用仍有独立幂等约束 |
| 锁与租约 | 所有权、续约/超时、持有者退出及过期持有者行为明确 | 原子释放、所有权令牌；需保护共享写入时评估 fencing 或数据库事务，不能仅靠 TTL 宣称无重叠 |
| 队列/任务链/批处理 | 多 worker 竞争领取、租约恢复、重试与取消的状态共享 | 复用数据库 SKIP LOCKED，明确至少一次执行与任务幂等，节点退出不使任务永久卡死 |
| 调度 | 多 scheduler 对同一逻辑触发点受保护派发 | F1 cron/时区/DST/有界补跑、时区数据版本和计划变更均验证；不把派发去重描述为副作用恰好一次 |
| 迁移/seed | 多副本启动不会并发破坏 Schema 或重复初始化 | 独立迁移部署步骤和同库互斥/等待超时/异常恢复均须交付并双库验证；开发与生产策略区分，seed 幂等由应用明确 |
| 文件上传下载 | 任意 API 节点都能访问已上传文件及权限状态 | 使用 S3 兼容或明确配置的共享文件系统；本地磁盘不能宣称跨节点共享，临时文件和清理有界 |
| WebSocket/SSE | 发送端与目标连接在不同节点时仍能授权路由/广播，断开和迁移可恢复连接 | ADR-059 与 `tests/consumers/realtime` 已用两个真实 API 进程、Redis 8、真实 WebSocket/SSE 客户端验证跨节点投递、Origin、撤销、SIGTERM drain 和 Redis 不可达 fail-closed；Pub/Sub 断开期间消息仍可丢失。完整负载均衡滚动/故障门禁与 PostgreSQL/MySQL 全栈验收留在 M6 |
| 事件与通知 | 清楚区分进程内事件与跨节点通知，每条连接不无故重复推送 | 复用通知/队列与实时 transport；在线路由、集群消费者与广播订阅语义分别设计 |
| 加密/签名 | 所有副本拥有兼容密钥配置，滚动轮换中可互相解密/验签 | 本地运算，按已有轮换计划先分发解密配置再切写入，密钥不进日志，不需要云 KMS |
| 配置与状态变更 | 静态配置的发布方式、运行期共享状态及传播时限明确 | 不暗示所有 TOML 修改自动全局同步；缓存失效/授权更新有可验证时限和诊断 |
| 停机与滚动升级 | 先撤就绪/摘流，再处理在途请求和连接，worker 交接与超时明确 | 新旧副本及任务 payload/Schema 兼容、扩缩容、强制终止和数据库短暂故障都有验证；给出迁移与回滚边界，不能默认破坏性迁移适合滚动发布 |

## 需要设计决策的建议

- 标准应用默认使用 PostgreSQL 或 MySQL 与 Redis cache，队列/可选会话复用共享数据库；库使用者仍可按 feature 与插件选择能力，memory/file 必须显式配置。Redis 默认不等于所有共享状态都迁入 Redis，也不证明集群已经可用。依赖共享语义的能力必须配置可用共享后端，不能静默退化为本地状态。
- 共享缓存、限流、验证码与锁按能力需求选择实际可用后端。集群配置缺少必需共享实现时启动报错并给修复路径，不能以进程锁或本地 map 替代分布式保证。
- 实时 transport 优先评估现有共享数据库通知表/轮询或可选 Redis 等成熟机制；必须支持双库部署路径或明确所选依赖条件。根据延迟、吞吐、清理与运维成本形成 contract，再选一个可验证实现，不为每个后端建消息平台。
- 在线推送明确临时断线/transport 故障时的丢失、重复与重试语义；业务关键数据经权威 API/存储确认。可靠离线历史重放可列 v2，不以临时 Pub/Sub 宣称可靠送达。
- 租约时间与触发时刻优先使用共享存储时钟；节点标识只用于诊断和所有权，不依赖不受管理的机器编号生成全局唯一业务主键。
- 集群关键指标包含节点身份、在途请求、连接数、共享存储等待、任务积压及实时投递耗时；不要用高基数的用户/连接标识作为默认指标标签。
- 先沿用通用 contract，补有界资源和并发保证；API/配置命名、默认时限、失效传播 SLA、锁/transport 与部署依赖需设计 Agent 定稿，不在本计划硬编码任意数值。

## 必过的多副本验收

1. 同一个构建产物启动两个以上 API、副本化 worker/scheduler，经过真实负载均衡访问；PostgreSQL 与 MySQL 分别完成基线测试。
2. 在 A 登录、B 请求；切换节点不能绕过验证码/限流。分别验证 JWT expiry/key overlap、refresh family、Session、PAT 及授权变更的声明时限；不要把 refresh 撤销当作 access token 即时失效。既有实时连接按单独契约验证过期/撤销。
3. 多节点同时使用同幂等键、同锁和同调度时段，验证业务结果、释放/续约、投递与恢复行为。
4. 在 A 上传、B 下载；在 A 建立 WebSocket/SSE，B 触发目标通知；验证授权、跨节点投递及断开清理。
5. 领取任务后强制终止 worker，确认恢复；暂停持锁节点直至租约过期再恢复，检查过期持有者不会破坏声明的写入保证。
6. 通过负载均衡摘除/终止一个 API 节点并滚动升级、扩缩容，记录请求错误、恢复、连接重建与资源占用；依赖故障也需观测。
7. 对启用 gRPC 的拓扑执行四类调用、慢流、deadline、身份/证书失败、节点 NOT_SERVING 与摘流、滚动后重连和 proto 新旧兼容。HTTP 与 RPC 联合运行失败须清理全部 listener；通过负载均衡观测实际节点分布，不只启动两个互不通信的服务。
8. 提供可复跑的多容器示例、测试脚本、配置/共享存储要求、反向代理与滚动发布说明；记录构建、版本、拓扑和实际结果。PostgreSQL/MySQL 两条路径均须真实执行，不只运行两个互不通信的进程；Redis 6.2+ 的最低兼容性和 Redis 8 日常基线按版本政策验证。
9. 对启用外部身份的应用执行 [F7 SSO 专项](v1-foundation-completion.md#sso-登录与统一退出)：同一 IdP 下两个独立 client、每应用至少两个副本；验证应用/IdP 发起退出、任一副本接收通知后的关联状态撤销、JWT 生效窗口、并发与故障恢复。保持应用本地身份/凭据隔离，不用共享 Cookie/JWT 冒充单点登录。

以上是验收要求，不要求自动对用户真实服务器部署。依赖高可用、数据库备份和编排平台由部署侧负责，文档明确责任边界；框架必须给出在其声明条件下通过的证据。

## 执行顺序

- 复用 M2/M3 已有数据库、认证、会话、限流、验证码与密钥契约，补缺少的跨节点/过期边界，不将局部验收升级为完整集群完成。
- M4 补编排/事件、请求幂等、旧 worker 接管、生命周期与通知边界；M5 接入共享存储/缓存、WebSocket/SSE transport、gRPC G1–G3 和可观测性。
- M6 完成双库多副本、滚动/故障恢复和性能验收。当前 WIP 先闭环，不同时开启多个功能簇；新增依赖和公共接口照仓库规则先设计后实现。
