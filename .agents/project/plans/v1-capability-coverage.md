# v1 通用能力覆盖与归属

> 受众：AI Agent
> 更新：2026-10-25
> 摘要：补齐通用基础能力的交付范围，明确单一职责入口、复用位置与验收；不将底层库支持、内部专用实现或空壳视为框架交付。

## 交付原则

- v1 以迁入框架后可直接进入业务开发为标准。常见应用反复使用的底层机制由框架整合，不要求业务开发者重新拼装驱动、生命周期、错误处理和测试工具。
- 通用机制完整交付；具体业务规则、业务数据模型、后台 UI 与所有供应商实现不要求框架穷举。数据库正式矩阵仍为 PostgreSQL/MySQL，其他后端按 ADR-009 扩展。
- “待决策”表示还需确定公共契约、布局、默认值和实现方案，不能以此省略本计划已纳入的能力。
- 每类职责只有一个公共入口，复用既有模块和成熟 Rust crate。新增能力不等于新增 crate；内部函数具备相似行为不代表应用已有可用接口。
- 框架封装必须有明确附加价值：配置/注册、生命周期、安全默认值、统一错误、测试支持或跨驱动契约。避免没有价值的逐方法包装，也不让用户自己完成整合。
- 具体能力按 [通用能力计划](v1-common-capabilities.md)、[补强计划](v1-performance-and-readiness.md) 与本表协同实施；同一能力只登记一个 contract，不创建平行系统。

设计时可按 [跨语言参考规则](framework-design.md#跨语言设计参考) 核查 OpenSpring 的相关实现，提炼解决问题的方法并记录取舍；能力归属、Rust 契约与本项目验证要求仍以本计划和有效 ADR 为准。

每个功能簇须按 [扩展性自主判断](framework-design.md#开发-agent-的自主扩展性判断) 主动核对常见业务接入场景。示例不穷举，机制可灵活选择，合理扩展通过公开 API 完成且不增加重复能力。

## v1 能力覆盖与单一归属

下表包含已规划能力的深度补强和新增通用机制，均为 v1 范围；实现状态必须另查代码与 `core/`。

| 能力 | 唯一归属与复用 | v1 最低交付与验证 |
| --- | --- | --- |
| 业务流程钩子与事件 | 复用 Plugin 注册、对应能力事务/认证边界及事件/队列 | 提交前后、注册/登录、上传等公开类型化扩展点；顺序、短路、错误、提交语义及集群投递边界按 [设计规则](framework-design.md#关键流程的公开扩展点) 验证，不修改核心即可扩展 |
| 国际化 | 请求上下文与统一消息资源机制 | 中英文框架资源、业务资源扩展、默认/请求/回退语言、参数替换和并发隔离；错误 code 稳定 |
| HTTP 客户端 | 单一出站客户端，供业务和供应商适配复用 | JSON、表单/multipart、流式读写、连接复用、超时、取消、错误、受控重试与 fake；有界资源 |
| 加密、哈希与签名 | 一个安全能力契约；密码哈希复用认证实现 | 进程内认证加密、本地密钥生成/轮换，无 KMS/外部服务必需依赖；当前密钥写入、历史密钥解密；签名与限时链接校验供邮箱验证和私有链接复用，不能另造多套签名规则 |
| 审计 | 统一审计入口与 sink，复用事务/事件 | 持久化、fake、脱敏、成功/失败/回滚语义及清理；无需管理页面 |
| 请求幂等 | 统一可选中间件/服务契约，复用数据库事务 | 身份与接口隔离、指纹、并发、响应重放、过期及崩溃恢复；与限流和任务去重分开 |
| 通用 Session/Cookie | 公开会话能力，认证消费该能力 | 读写/删除/过期、会话轮换与失效、Cookie 属性、CSRF 接入；数据库默认、既定可选 Redis 适配，fake 与并发测试 |
| 通用限流 | 统一限流机制，认证端点复用配置 | 可选 key/窗口策略、共享或本地范围、稳定拒绝响应和重试提示；不能只有登录内部专用实现 |
| ORM 与查询体验 | `openrust-db` 与现有 ORM；不自研第二个 ORM | 关联加载、批量操作、分页、软删除/恢复、事务、受控原生 SQL 及查询诊断有明确入口或直接复用说明；覆盖 N+1、数据泄漏和双库差异 |
| API 数据输出 | 现有响应包装与 DTO/资源转换约定 | 字段白名单、敏感字段排除、关联数据与分页输出；生成物和 OpenAPI 一致，不重复建立响应体系 |
| 缓存操作与锁 | `openrust-cache` 公共契约和独立锁能力契约（driver/store 与默认 memory 见 [ADR-014](../decisions/adr-014-cache-driver-and-store-contract.md)） | memory/file/可选 Redis；命名空间、统一 serde 序列化、TTL 与未命中/故障区分；基础/批量操作、条件写入与数值操作的原子性；锁的所有权、超时与释放规则明确，不支持时显式拒绝而非伪装成功 |
| 文件上传下载 | `openrust-storage` 与 HTTP 适配 | multipart 上传、流式下载、私有访问授权、大小/类型校验、临时链接及 fake；接收前、内容可读且发布前、完成/失败扩展点允许应用接入内容检测，验证发布门槛与清理，不强制审核服务；避免整文件无界入内存 |
| 队列常用编排 | `openrust-queue`，复用任务与状态模型 | 唯一任务/禁止重叠、明确顺序的任务链、有限并发批处理与进度/失败/取消；不扩成任意 DAG 工作流引擎 |
| 调度与进程运行 | 现有调度与命令生命周期 | 多实例去重、重叠策略、任务观测、API/worker/scheduler 独立生产运行和本地编排；避免多个入口重复启动 |
| WebSocket 与 SSE | 复用 HTTP、认证及可观测性 | WebSocket 按通用能力计划；SSE 提供事件流、心跳、断开取消、慢客户端和代理示例；重连 ID 不等于自动持久化重放 |
| 多渠道通知 | 薄通知编排层，调用现有 Mail/SMS/Queue | 按收件人/渠道选择、模板参数、语言、同步/排队、结果与 fake；复用发送驱动，不重写供应商；持久化渠道提供可选记录接口，不强制业务收件箱模型或 UI |
| 集群部署 | 复用各能力共享后端与运行生命周期 | 按 [集群计划](v1-cluster-deployment.md) 交付双库多副本正确性、跨节点在线投递、共享文件、故障恢复与滚动发布；不依赖黏性会话维持正确性 |
| 多实例配置 | 由各能力统一管理配置及注册 | 普通应用使用默认实例；需要多个连接/缓存/存储实例时有受支持的选择方式和隔离测试；具体是否称 store/connection 仍待命名决策，不平行新增缓存入口 |
| CLI、生成器与调试 | `openrust-cli`、应用命令和测试工具 | 生成、运行、诊断、路由/配置/数据库状态、队列检查及清理入口；默认配置可运行，生成物可测试；调试输出与生产日志边界明确 |
| 扩展、测试与部署 | Plugin、契约测试、现有宿主及模板 | 独立扩展示例、默认及单驱动组合、真实双库与 fake、容器/代理/停机、性能基线与干净环境黄金路径 |

## 需要决策的实现建议

- Session、签名链接、限流与审计优先检查已有认证设计，抽出可复用入口，让认证成为调用方；避免每个功能簇各做一遍。
- 多实例是通用使用能力，先提供简单默认路径；具体配置布局、类型化选择方式及切换时机由设计确定。缓存入口仍叫 `Cache`，“store”不是新的顶层能力。
- 原子锁优先复用后端真实原语，锁由所有权令牌保护释放；业务锁、队列唯一性和调度锁共享契约或实现，但各自保证不能混淆。不用进程锁冒充分布式锁。
- 任务链与批处理优先复用数据库队列状态，限制批规模和并发；明确失败中止/继续、重试、取消与崩溃恢复，不承诺外部副作用恰好一次。
- 通知编排放在现有发送层之上，只解决选渠道、选模板与派发；真实发送结果仍来自 Mail/SMS。是否持久化发送记录、留存策略和事务一致性先定 contract。
- SSE 与 WebSocket 共用资源控制、认证和停机约定；跨节点在线投递按 [集群计划](v1-cluster-deployment.md) 在 v1 交付，持久历史重放另行扩展，不将进程内事件描述为可靠消息总线。
- ORM 能力优先直接复用 SeaORM 的稳定接口并给出框架示例；仅在一致性、安全或易用性确有收益时封装。多个连接不意味着必须支持跨库事务或读写分离。
- 上传类型识别不能只信任扩展名/MIME；流式操作、请求幂等、响应包装与 OpenAPI 的兼容边界要有测试，不能为统一 JSON 而缓存整个流。

## 推进与完成定义

- M3：国际化、HTTP、安全、审计、验证码、通用会话/限流及相关契约，和认证/通信一并闭环。
- M4：请求幂等、事务派发、锁与调度、任务链/批处理及薄通知编排；依赖未就绪时先定契约，后接实现。
- M5：缓存、存储与上传下载、WebSocket/SSE，跨能力复用与实例配置收口。
- M6：生成器/文档/调试入口、完整示例、有效 feature 组合、性能、故障恢复与部署验收；不以“库里有这个方法”标记完成。
- 每项有唯一实现归属、公开调用路径、配置、成功/失败及并发测试、示例与可执行验收。具体公共 contract、依赖选型和默认值需设计审查后实施。
- 当前活跃功能簇继续独立闭环；按依赖顺序更新 `todo.md`，不把所有未执行能力同时标为进行中。本计划只要求本地开发与验证，不新增远端发布或外部通信授权。
