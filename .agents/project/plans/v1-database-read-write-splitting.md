# v1 数据库基础读写分离计划

> 受众：AI Agent
> 更新：2026-10-26
> 摘要：`openrust::db` 显式只读副本路由已实现；PostgreSQL 18.6 与 MySQL 8.4.13 真实复制拓扑的暂停、主库新读和副本追平测试通过。完整集群与业务负载性能基线仍按集群/性能计划验收。

## 目标与边界

- 普通项目只配置一个数据库，维持现有使用体验；开启应用集群不要求数据库读写分离。仅在需要分摊读取负载时启用副本。
- 复用 SeaORM、`Db`、`DatabasePlugin` 和既有配置/生命周期，不创建第二个 ORM 或平行数据访问入口；多个命名数据库与同一逻辑库的主副本路由分别建模。
- v1 正式覆盖 PostgreSQL/MySQL。数据库自身负责复制与选主，框架负责连接、选择和错误语义；不交付复制系统、自动提升副本、分库分表或跨库事务。
- 不解析 SQL 字符串猜测所有操作的安全性，不宣称可以透明拦截全部 SeaORM/原生连接调用。公共契约必须说明受管理入口及逃生口的覆盖边界。

## 最低交付契约

| 场景 | 要求 |
| --- | --- |
| 配置与兼容 | 一个主库、可选多个只读副本，独立且有界的连接池；未配置副本时全部走主库；现有单库配置及自定义连接初始化保持可用或同步迁移全部调用方 |
| 路由 | `connection()` / `primary_connection()` 始终主库；调用方只能通过 `read_connection()` 显式选择可接受延迟的只读副本。原始 SeaORM SQL 由调用方负责读写语义，框架不解析 |
| 事务 | 框架事务默认在主库开启，事务内所有读写使用同一事务连接，不能因查询是 SELECT 就切到副本；嵌套事务/savepoint 与重试边界沿用现有契约 |
| 写后读 | 显式主库读取可用；提供请求/工作单元内写后保持主库的能力，明确传播与释放边界。该能力不承诺跨请求、跨节点读后写一致性，也不能覆盖绕过框架的写入 |
| 副本选择 | 使用简单、可测试且低开销的策略；推荐先做轮询，避免无依据的复杂权重或自动拓扑发现 |
| 故障 | 副本连接/读取故障明确报错；不自动回退或重试，避免因原始 SeaORM 连接无法证明操作只读而放大主库流量或重放业务操作 |
| 内部关键路径 | 认证撤销/权限判断、幂等判定、队列领取/状态、调度锁、迁移/seed 等依赖最新状态或锁的操作显式使用主库，不自动跟随普通读取路由 |
| 可观测性 | 当前以启动连接错误和查询错误显式传播，不自动回退；本 crate 尚无路由指标系统，指标接入留给通用可观测性功能簇，不宣称测得复制延迟 |

异步复制可能返回旧值；文档须用“修改资料后立即读取”的例子解释。跨请求要求最新数据时使用主库；不以固定等待时间、黏性会话或 Redis 标记冒充复制完成保证。

## 本轮最小 contract（ADR-029）

1. 保留 `[database].url` 作为主库；新增 `read_replicas = ["..."]` 可选配置，默认空列表，副本需与主库同一官方 backend。
2. `Db::connection()` 与新增 `primary_connection()` 永远返回主库；`Db::transaction()`、MigrationPlugin、SeedPlugin 和现有框架关键路径继续固定主库。
3. 新增显式 `Db::read_connection()`：未配置副本时返回主库；配置副本后以原子轮询选择一个副本。调用方须只执行可接受副本延迟的只读操作，框架不解析 SQL。
4. 新增 `Db::with_primary(future)` 任务局部 scope；scope 内的 `read_connection()` 返回主库，适用于明确写后读的请求/工作单元；独立 `tokio::spawn` 不继承 scope。
5. 启动时验证所有 URL、feature、backend 与连接；任一配置副本不可用即启动失败，避免静默缩容。副本查询错误原样返回，不自动重试、回退或重放。
6. 自定义连接插件可用 `Db::initialize_with_replicas(primary, replicas)` 提供同一契约；底层连接逃生口仍允许应用自行绕过路由，文档明确责任边界。
7. 每个 pool 使用现有有界连接数与超时；配置 N 个副本时总上限按 N+1 个 pool 计算。默认无副本，不增加连接。
8. 真实流复制拓扑、复制暂停/追平、强制主库新读、两个 API App 的 scope 隔离均由 PostgreSQL/MySQL 集成测试覆盖；多个互不复制的数据库不算通过。

## 验收

- 契约测试验证单库兼容、副本选择、强制主库、写后保持主库、事务/锁定读取固定主库、自定义连接扩展和错误分类；一个事务中不能泄漏出副本查询。
- PostgreSQL 18 与 MySQL 8.4 各使用真实主库及只读副本完成集成验证。受控暂停/恢复复制测试覆盖可观察的旧读、主库新读、两个独立 App 的 scope 隔离及副本追平；两个独立数据库不能冒充复制拓扑。
- 两个独立 `App` 实例验证主库新读与 task-local scope 隔离；完整负载均衡、多节点认证撤销、幂等、队列/调度回归仍属于最终集群验收，不由本 M2 能力单独宣称通过。全量 Rust 门禁与 PostgreSQL/MySQL 集成检查按仓库规范执行。
- `apps/server/benches/db_routing.rs` 提供 release 模式、单并发 `SELECT 1` 的主库/副本路由微基准；记录吞吐与 p50/p95/p99。它不是代表性业务性能报告，不据此宣称副本带来吞吐提升；完整 CPU/内存/负载基线按性能计划完成。
- 2026-10-26 已在隔离临时服务完成 PostgreSQL 18.6 和 MySQL 8.4.13 真实复制拓扑测试；当前仍未建立完整负载均衡集群。临时服务不是用户数据库；不得自动更改已有服务、凭据或服务器配置。
