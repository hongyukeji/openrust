# 内容安全与内容审核开发计划

记录日期：2026-11-25。状态：**用户已确认四家供应商及建议方案，等待用户安排其他 agent 实施；本轮不开始编码**。

用户要求将本轮需求、两轮联网调研和建议完整落盘，用户随后确认国内两家、海外两家，其他按建议执行，并保留由用户安排其他 agent 开发的约定。本文件记录已确认方向与接续要求，工程细节按下文落实；不因计划提交而创建包、修改默认应用、调用付费服务或标记实现完成。接手者先阅读[项目指引](../README.md)、[规范](../conventions.md)、[固定 Laravel 基线](laravel-rebuild-baseline.md)及最新工作区。

## 1. 用户需求与本轮交付边界

### 已明确的需求

1. 内容安全能力需要覆盖**文本内容、图片文件、视频文件**，不能只有敏感词或文本过滤。
2. 先联网调研 GitHub 热门项目、Laravel 生态与成熟实现，优先借鉴或复用有源码、测试和实际应用依据的设计；Star 数仅用于发现候选。
3. 尽量沿用 Laravel 的命名、结构和使用习惯，同时遵守项目 Rust 原生命名规范，避免重复造轮子和过度设计。
4. 当前先形成完整开发计划，待方案讨论完成后由用户安排其他 agent 实施；本轮不开发业务代码。

### 用户后续确认与最终范围（2026-11-25）

- 用户先明确阿里云和腾讯云都接入，随后要求“海外也接入两家，这样国内和海外都有的选。其余的按照你的建议”。据此采用此前列出的 Sightengine 与 Hive，**必接范围为阿里云、腾讯云、Sightengine、Hive 四家**；Hive 不再只是备选，海外不再是至少一家或名称待定。
- 四家均通过统一具名驱动入口提供文本、图片和异步视频审核，各自协议与能力分别验收。国内／海外各有两种可选实现，不默认同时向四家发送内容，不自动根据 IP 切换供应商。
- 采用此前建议：独立可选内容审核包、强类型异步能力契约、Manager／Provider／自定义驱动、复用 HTTP Client／Queue／Storage／Scheduler、分离检测与发布决策，默认未完成／失败保持待审核，Review 交人工。
- 海外账号、目标地区可调用性、所需语言／类别／音轨／OCR及付费条件仍需实际核对；这些是执行与验收条件，不再是是否实现四家驱动的选型问题。Hive 的合同／项目开通限制单列，不允许无声省略或自行换成第三家。
- 本轮仅更新已确认计划；仍由用户后续安排其他 agent 实施，不将“按建议”理解为立即开始本轮业务开发或采购。

### 已确认的架构与范围

- 首版采用**独立可选内容审核包＋具名可扩展驱动＋四家云审核适配＋现有队列／存储**。采用 `openrust-content-moderation`、`vendor/openrust/content-moderation/`、`config/moderation.rs` 作为实施命名基准；工程接线如需调整按项目规范记录原因，不重开已确认范围。
- 提供和短信／存储相近的调用体验：默认配置、具名配置、同服务商多配置、应用 Provider 注册自定义驱动。四家均核对文本／图片／异步视频；音轨／OCR及资源上限按各家实际协议落实，不支持或待外部开通项须显式记录，不能伪装完整通过。
- 文本与图片提供即时检测能力；视频通过异步任务、结果查询与可选回调完成，业务服务决定是否发布。
- 文件恶意代码扫描、PII、重复违规内容哈希、自托管模型、额外供应商作为条件性后续，不进入首版默认依赖；AWS／Azure仍为专项候选，不计入本次四家替代交付。
- 框架与适配实现保持 Rust，不自行训练模型，不强装 Python／PHP／GPU或媒体处理平台。未来若核定额外服务，明确其运行环境，不能称整个部署栈纯 Rust。

### 不混淆的能力

| 能力 | 职责及边界 |
|---|---|
| 内容审核 | 色情、暴力、仇恨、骚扰、违禁、垃圾广告等检测；具体类别以所选服务和业务策略为准 |
| 文件安全 | 实际类型、大小／解码资源限制和恶意代码扫描；不因文件无病毒就批准其内容 |
| PII 检测与脱敏 | 检测及处理隐私实体；单独决定是否接入，不能充当通用有害内容识别 |
| 页面／输入安全 | XSS 输出处理、请求校验等继续使用既有机制，内容审核不能替代 |
| 文本机器翻译 | 将文字翻译为指定语言，已在[DRV-03](../todo.md)登记；与本计划独立，不先翻译成英语再默认视为已审核原文 |
| Lang 本地化 | 查询已有语言资源，不接入网络审核，不改 `Lang`／`__`／Blade 翻译行为 |

## 2. 项目现状与可复用基础

本轮为源码与测试静态复核，未构建或运行审核候选，未调用真实供应商，未验证准确率、容量、价格或部署可用性。关键词扫描只提供线索；当前结论是**未确认已有可直接承担上述完整需求的公开模块**，不是宣称全仓穷尽审计已完成。

| 现有基础 | 已核对入口及建议复用方式 | 实施前仍需核对 |
|---|---|---|
| 自定义驱动注册 | [SmsManager](../../../vendor/openrust/framework/src/notifications/sms/sms_manager.rs)：`extend`、具名解析、实例缓存、`forget_drivers` | 外部消费者如何解析包 Manager；工厂替换、失败重试、旧句柄和多应用隔离 |
| 文件存储 | [FilesystemManager](../../../vendor/openrust/framework/src/filesystem/filesystem_manager.rs)：使用既有 local／S3 存储操作、私有文件与临时授权访问 | 所选供应商接受的对象／URL／上传协议，不能假设 Storage 已支持任意外部驱动 |
| 队列 | [Job 契约](../../../vendor/openrust/framework/src/contracts/queue/job.rs)、[UniqueJob](../../../vendor/openrust/framework/src/queue/unique_job.rs) | 独立 Worker 注册、提交时机、重试／超时／关停、共享存储；唯一锁不等于业务幂等或外部恰好一次执行 |
| HTTP Client | 复用现有连接、TLS、请求发送、重试及错误机制 | 固定供应商签名、请求体及错误语义；提交任务重试可能重复创建和计费 |
| 图像能力 | [image 模块](../../../vendor/openrust/framework/src/image/mod.rs) | 安全解析、格式／动画覆盖和资源上限；已有编解码能力不等于已有审核模型 |
| 容器／配置／调度 | 按既有 Provider、包发现、配置缓存和 Scheduler 装配 | HTTP、独立 Artisan、常驻 Worker 中均可用，不能依赖父进程注册闭包 |

旧版 `openrust-v0.x` 的本轮初筛未确认可复用的审核模块；实施前依规范复查相关源码及测试，不复制旧业务示例或把名称命中当成能力。

### 3.2 已实际阅读的关键源码与反例

- [Prism PendingRequest](https://github.com/prism-php/prism/blob/385022b5e0fec9be49a5b8e4a468fdafaa8f1267/src/Moderation/PendingRequest.php)接收文本／图片，构建请求后委托 Provider；[自定义 Provider 指南](https://github.com/prism-php/prism/blob/385022b5e0fec9be49a5b8e4a468fdafaa8f1267/docs/advanced/custom-providers.md)展示 Manager 工厂注册和仅实现所需能力。可借鉴职责，不移植 PHP 运行时。
- [Prism OpenAI 测试](https://github.com/prism-php/prism/blob/385022b5e0fec9be49a5b8e4a468fdafaa8f1267/tests/Providers/OpenAI/ModerationTest.php)通过 fixture 模拟响应，核对文本、批量、URL／本地／Base64 图片、数组／可变参数、混合输入与非法类型。是协议和装配参考，不是本项目已运行结果，也不证明供应商检出率。
- [Prism Handler](https://github.com/prism-php/prism/blob/385022b5e0fec9be49a5b8e4a468fdafaa8f1267/src/Providers/OpenAI/Handlers/Moderation.php)映射结果、模型、请求标识和限流信息；缺 results 的映射路径使用空数组。[Response::isFlagged](https://github.com/prism-php/prism/blob/385022b5e0fec9be49a5b8e4a468fdafaa8f1267/src/Moderation/Response.php)对空结果返回 false；OpenRust 不应把“未标记”直接等同“审核完整且允许发布”，须验证供应商结果完整性和覆盖关系。这是设计反例，未做上游漏洞定性。
- Prism 文档说明混合文本／图片可能把文字作为图片上下文，而不是分别返回每个对象结果。输入数量不能普遍等同结果数量；适配器须按实际供应商协议核对覆盖关系，需要独立判定时分别调用。
- [Laravel ClassificationProvider](https://github.com/laravel/ai/blob/1d269f2359aa166aaf10b212151bf556dd86a02e/src/Contracts/Providers/ClassificationProvider.php)是分类能力契约；本轮未确认它能直接替代本计划的全套审核流程。
- [HMA 当前说明](https://github.com/meta/ThreatExchange/blob/9f627fb1d6d2a4a26c9b5ee1d6ca5e5ccc8e06a2/hasher-matcher-actioner/README.md)明确 copy detection、内容库、REST、Docker／PostgreSQL 和不同角色；[目标与非目标](https://github.com/meta/ThreatExchange/blob/9f627fb1d6d2a4a26c9b5ee1d6ca5e5ccc8e06a2/website/content/hma/goals.md)须与实际实现区分，不能把规划容量或复杂视频匹配目标计作本地已验。
- [openmoderate 视频源码](https://github.com/karammm/openmoderate-image-moderation/blob/5c2c734fe5774726237eeb19d28cacb6f08b386f/src/openmoderate/video.py)按帧采样并形成片段，携带截断／提前终止信息，`is_safe` 主要按片段列表判断。OpenRust 必须将采样、资源限制、部分覆盖和音轨缺失显式表达；不能仅复制布尔结果作为完整视频通过依据。

| [Azure AI Content Safety](https://learn.microsoft.com/en-us/azure/ai-services/content-safety/overview/) | 文本、图片的有害内容检测与严重程度 | 可选文本／图片后端；不能据此承诺完整视频服务，实施时复查预览功能与容器退役公告 |
| [Prism 中的 OpenAI 审核适配](https://github.com/prism-php/prism/blob/385022b5e0fec9be49a5b8e4a468fdafaa8f1267/docs/providers/openai.md) | 本轮确认 Laravel 生态适配了文本／图片审核 | 属生态实现证据；若选为内置驱动，另核对届时官方协议、分类／输入限制、区域和供应商政策，不直接推定视频／中文特定类别覆盖 |

- Hive 官方 Visual Moderation 说明 V3 演示与 V2 企业项目的差异，图像／视频按帧输出，音频与文本需独立接线；合同和开通门槛列为已选驱动的外部验收条件，不默认已采购或可调用，不以此降为备选或从计划删除。

- 这些是官方公开文档调研，不是供应商协议实测或质量／价格验证；不存在本轮真实账号开通、付费调用、合同采购或数据传输。

## 4. 拟议架构与公开契约

### 4.1 组织与职责

```text
vendor/openrust/content-moderation/    可选包，按已确认命名基准
  src/
    contracts/                       文本、图片、异步媒体能力
    drivers/                         各供应商 HTTP／鉴权／结果映射
    moderation_manager.rs            具名配置、工厂注册与实例生命周期
    moderation.rs                    对外门面，复用现有装配方式
    results/                         检测结果、任务状态、证据位置
    provider.rs                      配置合并、容器绑定、包发现
    storage/                         必要的审核记录存储适配
    services/                        最小通用审核任务与状态协调
  config/moderation.rs                包配置模板
  tests/                             独立测试与外部消费者
```

上述是职责示意，不要求为每行强建目录或类型。实施前按项目正式包布局核定；无需改造整个 Manager 基类或为包新建泛用插件系统。包 Provider 不强接默认应用，不在根应用留下安装残留的平行实现。若有迁移／发布模板，由包持有并通过既有安装／发布机制提供。

| 层 | 负责 | 不负责 |
|---|---|---|
| Moderation／Manager | 默认及具名解析、注册、自定义外部驱动、实例缓存、公开错误 | 硬编码业务发布条件、全局跨应用状态 |
| 能力契约 | 强类型输入／输出及能力边界；不支持操作明确返回错误 | 强迫文本驱动假装支持视频、任意 JSON 大一统接口 |
| Driver | HTTP、鉴权、供应商任务号／标签／证据／错误映射 | 修改业务模型、直接决定文章或视频公开 |
| 通用审核服务 | 执行状态、幂等、版本绑定、查询／回调协调 | 搬入整个内容管理后台或训练平台 |
| 存储适配 | 查询、条件更新、事务及必要锁 | 远程调用期间占用长事务、把所有流程塞入模型 |
| 应用业务服务 | 场景阈值、发布／拦截、人工复核、申诉及用户反馈 | 自己拼装各家供应商鉴权与协议 |

### 4.2 公开能力要求（方向已确认，具体签名在 CM-00 落实）

- `ModerationManager::driver(name)`：解析具名配置；默认选择使用现有项目习惯核定，不引入含糊名称。
- `ModerationManager::extend(driver_name, factory)`：外部 crate 在应用 Provider 中注册工厂；不得仍要求修改内部封闭枚举。
- 文本及图片即时审核能力：传入强类型输入与场景选项，返回 `Result` 异步结果；文本、文件和远程对象不能仅靠字符串猜类型。
- 异步媒体能力：提交、查询；取消／回调按供应商能力拆分或显式声明支持，不能伪装全部供应商一致。
- 能力检测：让调用者可判断是否支持文本、图片、视频、音频、OCR、批量、自动回调等；具体采用能力 trait 还是小型能力描述在 CM-00 定稿，不预先造庞大继承体系。
- 配置默认名、具名 profile、驱动类型、凭据引用、地域／端点、供应商场景策略、超时与限流；配置缓存只保存可序列化值，不保存客户端、闭包或运行时状态。
- Profile 与 driver 分开：同一服务商允许多个账号／策略；实例和注册表归应用容器，不使用无界全局缓存。
- 工厂失败可重试；缓存失效、`forget_drivers` 类能力、替换后旧句柄快照行为须明确。HTTP、Artisan、独立 Worker 各自完成 Provider 引导。
- 只有需求证明有用时再加批量 Builder／链式 API／校验规则；视频不得隐式放进同步 Validator 或全局 HTTP 中间件等待完成。

### 4.3 输入与输出

输入建议包含：内容类型、内容或私有对象引用、对象版本／摘要、业务内容标识及修订号、明确语言（可选）、审核场景／策略、请求关联标识。图片／视频使用对象或流／文件接缝，避免不加限制地整体 Base64 读入内存；供应商要求的转换由适配层在资源限制内完成。

输出至少区分以下信息，正式字段与公开类型待 CM-00 核定：

| 信息 | 必须表达的语义 |
|---|---|
| 运行状态 | Pending、Running、Succeeded、Failed；是否取消／过期另核定；成功提交不等于完成检测 |
| 审核建议 | Allow、Review、Block，与执行状态分开；未完成／失败／覆盖不足不能产生有效 Allow |
| 分类和分数 | 保留供应商原始标签与映射标签，分数标度／含义明确；不同服务商分数不直接横比 |
| 覆盖信息 | 审核模态、片段／帧范围、音轨／OCR 情况、截断／采样／部分结果；“没有命中”与“没有检查”分开 |
| 证据 | 文本位置、图片区域、视频起止时间／帧、音频片段等；单位固定，不能丢失时间基准 |
| 可追溯信息 | profile／driver、请求号、任务号、模型／策略版本（供应商有则记录）、内容版本、检测时间 |
| 原始响应 | 可选、限量且受访问控制；不默认进入日志／对外 API，不泄露凭据或敏感素材 |

本地业务阈值和供应商策略版本各自记录；审核建议不直接修改业务发布状态。多检查聚合时不能“有一个通过就通过”，也不简单平均分数；必须按已核定的必检项、Review／Block 和缺失状态裁决。

## 5. 各内容类型的处理边界

| 类型 | 首版建议 | 必须验证的边界 |
|---|---|---|
| 短文本 | 支持同步等待的异步网络调用，明确最大时间预算 | Unicode／零宽字符／组合字符、混合语言、空文本、隐语、广告、类别及上下文，不能静默截断 |
| 长文本／批量 | 队列任务，按供应商限制分段或明确拒绝 | 分段上下文／重叠、完整覆盖、结果关联；截断和部分成功不得当整篇通过 |
| 图片 | 基础文件校验后送审；同步或异步按服务支持 | 声明 MIME 与实际格式、尺寸／像素上限、损坏文件、EXIF 方向、压缩／缩放后的对应关系、OCR／二维码识别是否覆盖 |
| 动图／多帧图片 | 明确多帧支持或拒绝；如采样则记录范围 | 不能只审首帧、缩略图或封面就称完整通过；帧数／时序及转换后原内容关联 |
| 点播视频文件 | 私有存储＋异步提交／查询／可选回调 | 画面、音轨、字幕／OCR、音画同步、片段时间单位、无音轨、多个音轨、可变帧率、损坏文件、长度／大小限制及结果分页 |
| 音频 | 视频音轨为必讨论项，独立音频上传是否进入首版待定 | 不能只把所有审核归为图像；如转写后审核需记录语言、转写覆盖和上下文损失 |
| 其他文件 | 类型和大小限制；病毒扫描／内容提取按需独立核定 | 压缩炸弹、加密压缩包／文档、提取失败／不支持类型明确处理，不默认安全 |
| 直播 | 不默认为视频文件能力已覆盖 | 首版是否排除待确认；若纳入，单列持续审核、延迟、停流、恢复和计费，不借用点播结果计完成 |

原始内容不因审核需要而偷偷改写。归一化、转码、抽帧、OCR、语音转写若使用，记录处理版本及证据映射。图像库、FFmpeg／OpenCV、ONNX 等不是默认新增依赖，只有核定本地处理需求、许可、平台与收益后引入。

## 6. 审核与发布流程

```text
接收文本／文件
  → 基础校验；文件存入私有隔离位置
  → 记录内容修订与审核意图
  → 提交后触发审核任务
  → 即时结果，或异步任务号＋轮询／回调通知
  → 验证来源、任务归属、内容版本和结果覆盖
  → 持久化检测结果并应用业务策略
  → 允许发布／等待人工复核／拒绝
```

### 6.1 事务与幂等

- 审核绑定不可变对象版本或摘要，并关联业务修订号。用户编辑／覆盖对象后新建审核，旧回调不得批准新版本；摘要重用须包含策略／模型版本和租户范围。
- 数据库事务内持久化意图与必要状态，不在持有行锁的事务中等待网络服务。复用提交后派发，并解决“事务已提交、任务未发出”的恢复窗口；是否需要 outbox 由实际持久化方案裁决，不默认建设全局事件平台。
- 幂等键至少区分租户／应用、内容修订、审核场景与配置。队列唯一锁只用于减少重复执行，数据库条件更新／幂等记录承担状态一致性。
- 提交请求超时可能是供应商已接收；优先使用供应商幂等字段或关联查询，不能无条件重试产生重复任务／计费。记录未知提交结果，采用可恢复策略。
- 回调、轮询、Worker 重试与人工操作可能并发。通过版本／状态条件更新及必要短事务保证重复通知不重复发布、旧结果不覆盖新结果；采用至少一次处理假设，不承诺跨服务恰好一次。
- 人工复核结果、操作者与理由另记；自动重试不得悄悄覆盖人工决定。重新送审、人工撤回和申诉入口范围待定。

### 6.2 回调、查询与失败恢复

- 按所选供应商官方协议核对签名／鉴权、原始请求体、时间戳及重放边界；不能自创签名协议后宣称供应商支持。
- 来源不能可靠认证的通知只触发服务端查单，查单后核对任务所属账号、内容修订及完整结果；不能仅凭一个任务号或 URL 参数批准内容。
- 回调可重复、乱序、延迟或丢失；查询作为恢复路径，结果分页必须取全。校验后可靠接收／持久化，再按供应商要求返回响应。
- 错误区分输入不支持、配置／鉴权、限流、网络／TLS、响应损坏、服务错误、任务失败和覆盖不足。保留结构化来源与请求号，不提前全部转字符串。
- 超时／限流采用有限重试、退避和抖动；尊重 Retry-After（若协议提供）。超出期限进入可观察的失败／待处理状态，告警并允许受控重试。
- 默认建议公开发布保持待审核；故障不能自动允许。可用性与审核要求的取舍由业务明确配置，不能静默降级为更弱类别或换供应商。
- Worker 重启／正常关停／部署后可恢复未完成任务；取消与超时不代表远端任务已停止，须记录供应商真实能力和计费边界。

## 7. 文件访问、隐私与资源管理

- 待审文件不公开，不为云服务抓取开放整个 bucket；使用供应商支持的最小授权对象访问、短期签名 URL 或受控上传。授权有效期覆盖实际排队／抓取时间，过期需受控重签，不能长期裸露素材。
- 审核通过后发布同一已审核版本；业务／下载入口保证不能绕过状态读取原始公开 URL。派生封面／转码文件的继承条件须明确，失败／撤回时处理关联公开资源。
- 远程 URL 若由框架抓取，限制 scheme、端口、内网／元数据地址、DNS 解析及重定向每跳、响应大小、时长和并发；优先受控对象引用，不能让审核接口变任意代理。
- 检查实际文件类型／解码结果，限制文件字节、像素、帧数、时长、解压量、CPU／内存及执行时间。解析不可信内容的外部工具须有隔离与进程清理，不把临时目录或 shell 参数交给用户拼接。
- 秘钥不进入源码、配置输出、队列载荷或原始响应；任务只保存受控配置名与内容引用。调试日志不记录完整敏感文本、带签名 URL、Base64、原始视频或凭据。
- 原始素材、证据、审核记录及人工复核访问受权限控制；保留期限、删除／撤回、第三方数据地域与传输范围按业务定稿，不无界留存。
- 样本使用合法、授权、受控数据；自动测试使用合成／无害样本和模拟标签，不为验收抓取或传播违法素材。实际标注与申诉反馈在受控环境处理。

## 8. 验收矩阵与完成定义

后续每批明确“骨架完成／实现完成／行为验收／真实效果验收”状态。以下是拟议最低矩阵，CM-00 根据最终范围给每项分配实际测试和公开入口；CM-V01至CM-V12须对阿里云、腾讯云、Sightengine和Hive分别记录，不以共享Manager测试代替逐家协议／能力验收，不能只靠同名搜索或编译通过关闭。

| 编号 | 验收项 | 必要正反例和证据 |
|---|---|---|
| CM-V01 | 外部消费者 | 独立 crate 实现文本驱动和已承诺的其他能力，经正式 Provider 注册，由 Manager／门面真实调用；不能只调用内部 Driver |
| CM-V02 | 生命周期 | 默认／具名、同服务商多配置、未知驱动、无凭据、工厂失败后重试、实例复用、替换／失效与旧句柄、并发和多应用隔离 |

| CM-V10 | 文档与安装 | 三语可编译公开用法、配置缓存、外部驱动示例、安装／重复安装不覆盖自定义配置、包发现及默认应用不强依赖可选服务 |
| CM-V11 | 业务效果与费用 | 同一标注集按语言／类别统计漏检、误判、人工复核比例；记录样本量和适用范围、p50／p95、任务耗时、限流恢复、并发及实测费用，不编造统一准确率 |

模拟验收可验证协议、结果映射和故障闭环，但不能证明真实模型识别、供应商配额／费用／权限或生产投递。无凭据时把这些列为真实环境未验项；用户若日后授权按模拟范围交付，明确记录范围，不将准确率或全模态覆盖一并计通过。
