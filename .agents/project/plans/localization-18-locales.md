本轮建议范围：

- 正式语言资源、框架已接入翻译的用户文案、欢迎页、语言菜单、验证、认证与密码状态、分页、框架邮件／通知、Artisan 已本地化输出及生成器说明。

- 更新英文、简体中文、繁体中文开发者说明，**不默认新增15套完整开发者文档**。完整18语文档属于独立翻译与维护范围。
- 应用自有业务文案及可选扩展自有语言包由其所有者维护；盘点实际消费者，修复本次扩展暴露的核心假定，但不将所有可选扩展或第三方错误输出强行翻译。
- 项目内部日志、断言、未国际化开发错误仍按简体中文规范；不扩展成全仓字符串国际化重构。
- 本轮不改变默认 APP_LOCALE、APP_FALLBACK_LOCALE，不升级固定上游，不新增语言管理器或第三方运行时翻译服务。

## 调研依据与采用方式

2026-11-23 已在线读取以下官方／项目原始资料；网页检索工具未返回正文，改用官方 raw 内容及 GitHub API 核对。这里只记录方案依据，不表示已运行上游测试。

1. 固定 Laravel Framework v13.40.0，提交 `1449bf241017087fbd38c118ecaabef3f6797fdc` 的 [FileLoader](https://github.com/laravel/framework/blob/1449bf241017087fbd38c118ecaabef3f6797fdc/src/Illuminate/Translation/FileLoader.php)，以及固定文档提交 `960eedf0911155ad16326ade49c0ea5d18eda0b8` 的 [Localization](https://github.com/laravel/docs/blob/960eedf0911155ad16326ade49c0ea5d18eda0b8/localization.md)。沿用按语言／组加载、应用覆盖、缺词回退、替换与复数职责。上游目录下划线约定不取代本项目已确认的BCP 47规范；Eloquent单复数推断也不等于消息复数，不因界面语言自动改变模型表名。
2. [Laravel-Lang/lang](https://github.com/Laravel-Lang/lang)，本次查询main提交 `3fc62be68ac6d462f6a679944526fbddf5fced09`。API及LICENSE显示MIT许可，非归档，包含本计划新增语言目录；法语目录提供 php.json、json.json 等数据。采用与本项目实际键契约相符的标准翻译，并保留作者及许可，不引入PHP、Composer或整个生态运行依赖。实施时固定此提交核对真实键、版本差异与变量，不按最新词条盲目覆盖固定框架契约。
3. [ICU消息格式资料](https://unicode-org.github.io/icu/userguide/format_parse/messages/)。借鉴复数、替换和语言数据的职责划分；继续使用已有ICU规范化／格式化机制。**不将ICU MessageFormat语法直接写入现有Laravel风格消息选择器**，也不为扩展译文替换现有译器。

社区目录如zh_CN、zh_TW只作为来源映射，分别审校为本项目zh-Hans、zh-Hant译文；不据此宣称地区与文字标签普遍等价。社区没有的 OpenRust 专有文案（欢迎页、命令、生成说明、schema）单独翻译并核对术语。

## 设计决定建议

### 资源与发布

沿用 `lang/<BCP47>/<group>.json`、现有FileLoader和Lang；母语名称存各自 `languages.json` 的 `name`，阿拉伯语增加 `direction: rtl`，不使用国旗代表语言。

应用语言根承担正式可用资源，框架标准stubs承担可发布的标准模板。实施前先核对现有脚手架／安装器的拷贝来源，在已有资源交付链中确定唯一维护来源或确定性的同步校验；不手工维护两套会漂移的标准词条，不在Provider硬编码18语。

标准资源发布继续走lang:publish。若扩充其可发布文件集合，默认只发布缺失文件，--existing只处理已存在文件，--force才允许覆盖，逐一回归；不新增语言专用管理命令或同义参数。不得让新语言发布影响用户其他语言文件。

对邮件、通知及认证实际使用的原句JSON键／分组键按消费者补齐；不假定翻译auth.json就能自动翻译邮件正文。保留用户自定义文案和包命名空间覆盖优先级。

### 语言选择与回退

保持既有顺序：localeUsing → 显式URL → 安全Cookie固定偏好 → 配置请求头 → 默认语言及候选兜底。保留配置缺键／null语义、标准Request方法、App当前语言、Cookie／CSRF和缓存隔离规则。

新增资源可能扩大自动发现候选，这是本次有意的行为变化；显式app.supported_locales或setLocale保持优先。保留语言匹配机制，以18语实测结果修复实际缺口，不静默截断合法地区、文字和扩展标签。自动识别不得写成固定偏好。

缺词仍按app.fallback_locale运行。完整性检查必须禁止回退，逐语言按精确资源核对；缺词回退测试另设故意缺词夹具，不能用回退掩盖正式译文漏项。

### 欢迎页与文档

建议页面仍使用当前语言；**只为文档链接选择文档语言**：en／zh-Hans／zh-Hant用对应目录，其余15语用en。规则放在欢迎页视图的现有表达能力范围内，明确有限集合，不影响App::currentLocale、HTML lang、Content-Language或翻译回退；仓库仍取Application::REPOSITORY，URL／路径不进入语言词条，核心译器不感知文档目录。

这项建议需要在实施时同步修订现行“文档路径直接使用当前语言”的规范，记录是为18语运行时与三语文档分离作出的明确调整。未获本计划实施确认前不修改现有行为。语言控件继续遍历候选，菜单过长时提供可滚动区域、键盘焦点与手机布局；主题／自动语言模式保持现状。

阿拉伯语检查RTL布局、混合方向的版本号／URL／命令、图标和对齐。优先CSS逻辑属性及必要的bdi／dir，不机械镜像品牌或所有图标。泰文长句、印地语字形和各语长文案检查换行及溢出，不默认引入在线字体依赖。

## 执行阶段与退出条件

### A：锁定资源与消费者清单

- 确认18语名单和文档保持三语的建议，重新检查代码及相关指引。
- 按实际Lang／Blade／验证／认证／分页／邮件通知／Artisan／生成器调用建立键、替换参数、复数分支、加载来源清单；区分已有翻译、未接入翻译和第三方边界。
- 核对社区固定提交、许可和对应规则键；盘点生成器、安装器、独立部署、Docker和扩展的固定三语假定。
- 退出条件：资源范围与缺口明确，不能仅以搜索到18个目录结束。

### B：补齐18语资源与发布链

- 增加15语4组现有应用词条，并补齐18语的标准验证／认证／密码／分页及实际邮件通知词条。
- 最小修复未消费译文、固定三语分支、发布及生成应用遗漏；不重构无关服务。
- 自动校验JSON重复键、结构／叶子类型、键覆盖、占位符及大小写变体、复数格式、母语名称、方向值与BCP 47目录；正式包不得有占位译文或将英文复制当翻译完成。
- 普通文字、URL、Rust代码示例、schema类型名等不该翻译的内容分别检查；不对任意英文相同值一律判错。
- 退出条件：18份实际资源可精确加载，覆盖优先级、发布保护和缺词回退均有正反证据。

### C：页面、任务与分发消费者

- 欢迎页菜单、保存／自动模式、文档链接、RTL和长文案；保留零控制器冗余传参及已有Blade入口。
- 验证邮件与通知生成内容、队列任务语言传递及执行后恢复；用本地捕获传输，不声称真实供应商投递通过。
- 验证CLI帮助、错误、生成器说明和模型字段刷新使用真实译文；不改数据库已有字段描述原文。
- 核对Number／Faker的语言和地区支持，资源语言、消息复数、单词变形分别验收；未支持的具体能力给出准确边界。只修复本次实际导致错误的边界适配，不声称18语Faker全量本地数据已具备。
- 退出条件：真实HTTP、CLI、生成应用和独立部署能消费新增资源，文档链接没有不存在的目录。
