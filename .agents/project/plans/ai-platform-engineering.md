# AI 插件套件与平台应用工程实施计划

> 受众：AI Agent
> 更新：2026-10-26
> 状态：规划契约，未实施；当前不是可直接开工或上线的验收结论。
> 摘要：规定官方可选 AI 插件套件及完整平台应用的接入契约、依赖顺序、状态一致性、资源预算与验收；不减少完整平台范围，不以插件可用绕过上线门禁。

## 可行性结论与权威入口

- 技术路径具备可实现性，但目前尚不能判定资源、外部供给和全部行为已可行：框架 G0 未完成，套件与应用未立项，端点/页面细项、真实供应商条件与成本尚待 P0 验证。已有 `Plugin::build/finish` 和路由/服务注册仅证明装配入口存在，不构成 AI 实现或协议兼容的证据。
- [产品主计划](ai-platform-product.md) 管插件分层、宿主边界、启动、隔离与 G0–G3；[完整对标计划](ai-platform-openrouter-parity.md) 管最终功能范围与证据矩阵；本文件管工程方案、依赖和实施准入。三者必须同时满足。
- 23 个域不是 23 个开发任务，也不是已经闭合的全量规格。最终范围采用开发者确认、有日期的可观察基线，公开 Beta/实验功能仍需拆项；教程重复项只映射一次，已废弃功能记录当前兼容/拒绝行为，不能机械复活停止提供的服务。
- P0 保存适用官方 schema、页面观察和测试 fixture 的版本/日期/内容摘要，维护字段级差异；原文仅按许可与必要范围保存。每次依赖或上游升级重跑契约，不依赖实时网页作为唯一规格。
- 未公开算法、第三方独家模型权重、私有运营后台实现不能作为可取得的源码目标；应明确等效功能与效果指标。未知行为必须取证或由开发者确认目标契约，不能臆造“相同”或静默删除。

## 启动与依赖顺序

G0 框架 v1/v2 完整体成熟 → G1 开发者授权套件与应用 P0 调研/规格 → P0 退出评审 → P1–P7 内部实现/验证 → P8/G2 完整体证据 → G3 上线决策。G1 不以前置完成 P0 全部细项为条件；P0 退出前不展开全面功能实现；G1 已授权的 P0 有界验证原型除外。插件化不增加框架 v1/v2 任务，也不提前启动 AI 开发。

| 时点 | 必须先交付 | 后续依赖与限制 |
| --- | --- | --- |
| P0 | 当前官方 API/schema/页面证据及基线、上游/区域/支付可达性、插件分层/宿主接口/兼容矩阵、威胁模型、租户/账户/价格/账本 contract、资源预算和原型计划 | 任何关键模型/平台工具不可取得或预算不可承担时留在本阶段，不以无限挂起任务进入全面开发 |
| P1 | 只启用调用层与组合网关的独立宿主接入；租户/主体/账户 ID 和授权上下文、管理与调用凭据分离、能力目录、受控路由和协议原样响应路径 | 完整组织 UI 可在 P5，但隔离不能等到 P5；真实调用仅使用明确授权的测试凭据与有界费用 |
| P2 | 短事务账本、预占/尝试/结算状态、幂等/outbox、付款与回调去重、对账/补偿任务 | P1 测试流量不是客户收费；没有此契约不能进行可产生商业负债的运行 |
| P3 | 对 P1/P2 的并发、失联、崩溃、限额与恢复验证 | 新协议/工具引入后必须重新验证对应预算与恢复路径，P3 不是一次通过就永远完成 |
| P4 | 使用既有租户/账本/作业骨架扩展协议、多模态/文件/批处理及网站 | 不另建文件权限或异步任务账本，不先存公共附件再补授权 |
| P5/P6 | 在既有隔离基础补组织/BYOK/供应商、企业身份/政策与区域部署 | 公共与私有端点不混用；区域条件在 P0 验证资源，后期才实际验收完整部署 |
| P7 | 托管工具/Agent 先做专用沙箱原型，再接模型编排/SDK | 沙箱可行性在 P0 尽早验证；不能最后才发现宿主隔离、成本或网络控制不可行 |
| P8 | 汇总所有阶段和新增路径的完整回归、独立审查及演练 | 没有完成的范围、未知行为或外部阻塞均阻断 G2；没有上线授权不得进入生产 |

## 推荐产品架构

优先模块化单体与独立进程角色，不因领域多就默认微服务。完整平台应用按需依赖平台模块、网关与调用插件，各插件依赖所需的下层公开能力及 OpenRust；网关复用调用层，但不要求每个模块形成强制线性依赖。核心 OpenRust 不反向依赖任何 AI 层，完整平台装配全部必交付能力。项目独立工作区内按职责组织源码，实际 crate 数量在 P0 按依赖隔离与维护边界决定，不按下表逐项新建 crate。

| 模块/角色 | 职责与边界 |
| --- | --- |
| API 数据面 | 身份/权限、预算预占、路由、上游适配及流式转发；同步推理不通过后台队列排队再等待，客户端连接内保持取消/背压 |
| 管理控制面 | 模型/渠道/价格版本、租户/策略/Key、客户/运营/供应商接口；配置以验证后的不可变版本发布，失败可回滚，不在长流中途更换价格或策略快照 |
| 计量与账本模块 | 唯一资金权威与结算 API，管理上游成本、客户消费及供应商应付；禁止控制台绕过服务直接改余额 |
| 作业 worker | 真实 Batch/视频等异步作业、回调、usage 核实、对账、通知、删除清理；复用持久任务，不把同步模型调用伪装成异步成功 |
| 文件与资产模块 | 上传/引用/授权/生命周期及临时链接，限制文件大小/内容/处理资源；对账保留必要元数据，正文删除政策不破坏财务可追溯性 |
| 沙箱执行面 | 与 API/数据库/密钥宿主分离，执行 shell/Agent 等不可信负载；资源/网络/身份隔离失败时不可用，不能仅用同进程 async timeout 当隔离 |
| UI/SDK/集成 | 客户、组织、供应商与运营不同权限视图，共用公开业务服务；SDK 绑定版本化 schema 与协议事件，不复制后台私有接口 |

- 应用通过 OpenRust 公开能力组装；框架缺失稳定 escape hatch 时形成独立通用任务。产品不覆盖框架统一响应规则来强迫所有框架用户接受 AI 协议。
- AI 兼容路径必须保留正确 HTTP 状态、header、JSON 错误结构、SSE/二进制及 multipart 语义，不能套 `ApiResponse<T>`/always-200 包装。鉴权、解析、限流、超时、panic、404/405 等中间件错误也要在产品边界转换；逐路由验证与默认框架行为共存。
- 上游 adapter 按真实能力声明字段/事件/取消/usage/区域；采用有界的协议转换与原样转发组合，不建立丢失全部供应商特性的万能最小结构，也不静默忽略未知参数。
- 模型/价格/能力目录有版本、来源、刷新与人工审核，自动更新不能未经验证改变历史价格、私有可见性或能力路由。

## 插件版本配置与迁移契约

| 契约 | 必须明确与验证 |
| --- | --- |
| 源码接入与版本 | 首期使用本地 workspace/path 和公开 `Plugin::build/finish` 静态装配；套件与平台独立标识版本及来源 commit，公布支持的框架/Rust/feature/数据库/协议范围，不承诺任意版本兼容。可选源码分发不自动改变内部 package 的 `publish = false`，不要求 crates.io 发布或动态加载 |
| 默认隔离 | 不选 AI 时不引入其运行时服务、外部请求、数据库迁移或部署要求；只选调用层时不编入平台 UI/商业账本及无关 driver。用默认构建与最小 feature 的依赖图及启动检查证明，允许源码工作区拥有独立的可选成员与测试入口 |
| 宿主身份与政策 | 用公开类型和适配接口接收已认证的主体、租户/workspace、授权和预算，不从任意请求字段推断身份，不耦合宿主用户表。验证两个不同身份模型的宿主；禁止未启用计费就默认为免费且无限上游调用 |
| 配置与路由 | 配置段、环境变量、路由前缀及服务注册冲突均有确定规则；非法配置、缺少依赖、重复注册或未支持组合在启动时失败。凭据使用框架加密/脱敏；供应商 URL 策略与 SSRF 防护不能由用户参数绕过 |
| 数据所有权与迁移 | 插件迁移和宿主迁移显式编排，记录版本及前置依赖；启动不自动改库，不修改宿主用户表。普通调用不需要平台数据表；网关与账本仅为实际启用模块建表。验证新安装、重复执行、升级失败和历史数据保留 |
| 升级与回退 | 为配置键、持久数据、队列载荷、公开接口和协议适配器声明兼容窗口；验证目标旧新版本节点共存、排空和恢复。配置弃用有诊断与迁移说明，不能静默忽略；数据库回退用实际可行的备份/前向修复方案，不承诺删除业务数据即可回滚 |
| 关闭与资源归属 | 首期停用通过配置/源码组合变更后重启，不承诺热卸载。路由、连接、任务和流有明确所有者；运行中取消/排空/关闭后不遗留后台任务。禁用不自动删除表、账本或用户数据，待结算请求必须先排空或交接可恢复处理 |
| 可选交付 | 插件自身按声明范围验收，不要求单个调用插件独自实现 OR 全矩阵。通过独立接入、兼容与依赖验证后可纳入官方可选分发，实际合并/发布遵守既有授权边界；不能以局部交付代替完整平台 G2/G3 |

供应商扩展沿用框架公开 driver/trait 原则：调用、流事件、能力与错误契约必须可由外部源码包实现，未知能力应明确拒绝或按已声明透传规则处理。宿主预算服务由平台模块或应用适配器提供；商业收费要求持久化预占/结算及恢复契约，不用普通事件监听器冒充资金一致性保证。

## 独立宿主接入验收

至少维护下列三个组合的独立消费方测试；消费方只能使用公开 API，不依赖平台私有模块，不修改框架核心。它们是正式兼容证据，不以同仓库内部单测或示例可编译替代。

| 组合 | 必须通过 |
| --- | --- |
| 现有应用只接 AI 调用 | 不安装平台账户/账本/UI，不要求数据库或 Redis；同步/流式调用、工具与用量结果、超时/取消、错误及凭据脱敏可用。模拟故障与代表性真实上游均有验证；未声明的能力清楚拒绝 |
| 自有身份应用组合网关 | 自有用户/租户模型通过适配契约接入；路由前缀与宿主普通 HTTP 共存，身份/权限/Key 撤销/配额和多节点隔离有效；显式内部使用政策及可选外部预算服务分别验收，不能依赖完整平台用户表 |
| 完整平台应用 | 全部必交付插件/模块组合，完整网站与角色流程、计费资金不变量和 OR-01–OR-23 全量回归；各插件单独通过不能代替组合验收 |

在声明支持的框架/Rust/数据库矩阵上运行实际构建和测试，验证最小依赖、可选组合、配置迁移、版本升级与不兼容拒绝。将上游模拟器用于故障覆盖，真实供应商/协议兼容与完整平台上线仍依原门禁取证。

## 数据与状态不变量

| 对象 | 最少状态/约束 | 必须发现的缺陷 |
| --- | --- | --- |
| 逻辑请求与尝试 | 独立 ID；tenant/workspace、配置/价格快照、上游请求 ID；重复请求指纹明确 | Key 重试和上游尝试被混淆、失败回退成本丢失 |
| 预占与结算 | reserved → settled/released，未知结果进入 reconciling；状态转移使用版本或行锁/唯一约束，终态不可重复计入 | 同时结算/释放、超时后双扣或全部预占提前释放 |
| 上游作业 | created/submitted/running/terminal 与 outcome-unknown 分开；请求发出但任务 ID 未持久化有恢复规则 | 崩溃恢复重复创建收费视频/批处理任务 |
| 事件与回调 | 业务状态和 outbox 同事务；inbox/事件 ID 去重，乱序校验，worker 租约和 fencing/版本拒绝过期执行者 | 数据已提交但事件丢失、重复/迟到回调覆盖终态 |
| 资金流水 | 定点精度、币种/计价单位、平衡分录、原单与反向更正关联；余额可从流水和有效预占核对 | 浮点误差、覆盖历史、跨单位直接相加与余额漂移 |
| 租户资产 | tenant/workspace 从可信身份解析；Key/BYOK/文件/缓存/日志/任务/私有模型关联可校验 | 参数改 ID 越权、缓存跨租户命中、删除后资产仍可访问 |

推荐账本采用复式分录或可证明等价的平衡约束；P0 固定科目、单位、舍入与不变量，并用测试向量验证充值、手续费、预占、消费、退款、拒付、应收/应付。不由“Decimal 已用”推定账本正确。

- 不持有数据库事务/行锁跨越上游网络请求或整个 SSE。持久化预占后提交短事务，网络执行后另起短事务结算；通过状态机和补偿处理跨边界失败。
- 预占必须覆盖有上界的计费风险：输入/最大输出、推理/缓存、工具次数、媒体单位/时长与可能的回退尝试等。平台不接受无限输出、无限 Agent 递归或无限上游尝试。
- 无可靠费用上界的渠道，在 P0 定义追加预占或平台风险资金限额；不允许未经规则使用客户负余额。实际费用超出预占时分别记录应计成本和合同允许的客户收费，由已确定的规则处理差额与告警，不能伪称上游永不超额。
- outcome-unknown 不按 TTL 自动视为未执行。明确核实窗口、渠道查询能力、人工处理期限、争议资金状态与最大挂账风险；到期的处理规则在 P0 决定，不无限冻结也不盲目退款。
- 客户断开、Key 撤销、政策改变与节点排空的在途处理必须定义；取消已产生费用不能靠事务回滚撤销。流内容通常不可完整重放，幂等重复的状态查询/拒绝/重放行为按协议确定，不能重新调用上游冒充幂等。
- 上述预占/结算规则适用于商业计费组合。仅调用层由宿主承担上游费用，必须有最大输入/输出、并发、重试/工具循环、流缓冲与各阶段时限；超时和取消失败返回可区分的未知执行/用量状态，不能默认成本为零。插件不自动启用付费 provider 或后台真实探测，不在客户端已收到流内容后重试拼接另一结果。

## 区域、隐私与分布式预算

- 区分控制面元数据、财务数据与提示词/文件/工具输出。内容、缓存、临时文件、日志、追踪、工具网络和备份都必须符合所声明的数据范围，政策在创建上游尝试之前生效。
- P0 推荐先为每个财务账户设置唯一权威写入域；跨区域预算使用预先持久化且总额受约束的区域额度分配，或访问权威账本完成授权。选择一种并证明网络分区时无双花，不把异步复制余额当可立即消费余额。
- 权威账本不可达时，默认拒绝新付费授权；如采用已分配区域额度，只能消耗有效且不重叠的配额。不能在 Redis 故障或网络分区时无条件放行。
- 区域不满足时拒绝该请求，不回退其他区域；跨区域元数据、支付处理及 BYOK 端点的政策差异明确列出，不声称单区域数据库就自动满足全球驻留。
- ZDR 与故障排查冲突时优先履行已选策略：默认元数据脱敏；允许的内容日志需显式授权/留存/删除；以合成数据排查无法合法留存的正文。

## 实施前高风险原型

P0 在授权后的隔离环境进行最小技术 spike，结果只写进当前证据清单。以下任一不可行时不得展开全部功能实现：

1. 用框架公开接口同时跑普通后台与 AI 原生 JSON/SSE 路径，覆盖 middleware 错误、UTF-8/事件切片、慢客户端和上游取消失败。
2. 使用可控上游与数据库验证预占后断电、发出请求未获 ID、结算前崩溃、重复/乱序回调，以及恢复后账本不变量。
3. 验证代表性真实上游的工具/usage/媒体/批处理能力和 API 差异；无法取得的关键供给在预算投入前明确。
4. 验证独立沙箱逃逸边界、网络策略、资源销毁、进程树取消与费用上限；无可用执行基础设施时记录阻塞，不转为宿主执行。
5. 验证目标区域的流量/存储/日志路径与账本授权延迟；实际支付/企业身份条件不具备时只做 mock contract，标记外部条件不通过。
6. 用独立宿主只接调用层，再用不同身份模型组合网关；证明不依赖平台私有代码、用户表或账本，关闭插件不遗留路由/任务，默认框架构建与启动不受影响。

## 工作量、资源与成本

P0 退出前按细项和依赖编制 WBS：负责人/角色、实现与独立审查工作量、前置项、验收、真实外部条件、估算区间及依据。一个人可兼任多个职责，但必须明确任务容量，不能默认多个 Agent 等于无限工程能力。

- 分别估算网关/适配、前端/体验、计量账务、租户/企业、沙箱/Agent、SDK/生态和运维/安全测试的工作量；将未知接口、Beta 漂移与供应商审核列为风险项并给出备选路径。
- 预算包含持续开发期间的上游测试 Token/媒体费用、沙箱、各区域计算/数据库/Redis/对象存储、带宽与日志、支付手续费、评测及持续运营人员成本；不能只估服务器费用。
- 先定义单位成本与盈亏压力测试：按模型/媒体/工具计量区分上游费用、收费、失败重试与免费额度，限制测试/滥用损失；不能为了看似便宜而跳过错误路径计费。
- 未经真实测量不填承诺周期/预算/性能数字。P0 退出时这些关键数字必须有依据、有责任人和开发者决定；不允许以长期“待定”跨过实现准入。

## 量化验收与退出规则

| 类别 | P0 必须确定的参数 | 最终验证 |
| --- | --- | --- |
| 协议/网站覆盖 | 基线接口/页面/角色总数、支持版本、行为差异的处理 | 所有最终必交付细项均验证，未知/真实阻塞未关闭则 G2 失败；兼容模式的拒绝行为也有测试 |
| 账本正确性 | 金额单位/精度、费用上界、核实期限、并发与风险额度 | 平衡约束与余额可重建，重复/崩溃/乱序测试不得发生非授权透支、重复结算或不明调账 |
| 性能与容量 | 硬件/区域/依赖、并发连接/流、输入/输出大小、平台附加 p95/p99、吞吐、内存/FD/连接池预算 | 固定负载与长时压测；上游耗时与网关耗时分开，慢流/长文件和对账积压纳入资源上限 |
| 可靠性 | 服务目标、错误预算、RPO/RTO、排空时限、最大结算积压及恢复时间 | 杀节点、DB/Redis 故障、网络分区、上游失联、沙箱故障、备份恢复与迁移回滚演练 |
| 安全与隐私 | 威胁模型、角色矩阵、内容留存/删除、密钥轮换、允许网络 | 独立安全审查；越权/SSRF/注入/资源滥用、日志泄密、沙箱隔离及区域拒绝路径验证，无未关闭上线阻断项 |
| 升级与供应链 | 框架/依赖/SDK/迁移/构建版本、数据兼容窗口和产物校验 | 可复现构建与依赖检查、数据迁移/备份恢复、旧新节点共存、兼容回归；回滚不假设可逆删除已写业务数据 |
| 插件接入 | 各层公开 API、宿主适配、版本/feature 组合、配置迁移与资源归属 | 独立消费方覆盖调用层、网关和完整平台；最小依赖、默认隔离、启停排空、升级/不兼容拒绝及声明支持矩阵有实际证据 |

最终证据包含实际环境、版本、命令/负载、结果、失败修复与审查结论。修复重大问题后重跑受影响回归；P8 独立审查人或不同模型不能只重复实现方结论。待外部条件、无数值阈值或仅有 mock 的项不能记为验收通过。

## 官方行为核对

- [流式协议](https://openrouter.ai/docs/api_reference/streaming)：区分各协议 usage/终止事件；不能假定所有 Chat usage 帧均为空 choices，也不能假设所有供应商都可取消计费。以冻结基线的事件形状回归。
- [Responses](https://openrouter.ai/docs/api_reference/responses/overview)：对标无状态约束与拒绝字段，不泛化为 OpenAI 全接口等价。
- [区域路由](https://openrouter.ai/docs/guides/features/in-region-routing)：地域不匹配时失败，内容与运营记录的声明范围分开；真实部署验证不能被 metadata 配置替代。
- [托管工具](https://openrouter.ai/docs/guides/features/server-tools)：客户端 function calling、平台执行和插件分别设计，Beta 漂移由版本基线管理。
