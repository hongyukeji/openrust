# v1 通用能力补齐计划

> 受众：AI Agent
> 更新：2026-10-26
> 摘要：请求级国际化、受限出站目标策略、应用数据加密与本地 key rotation 已独立实现；审计按 ADR-035、用途隔离限时签名链接按 ADR-036 实现并通过双库验收，WebSocket、请求幂等及新增 gRPC/出站韧性整合仍待完成。

## 范围与决策规则

- 本计划补充 [v1 总计划](gen1-plan.md)、[性能与开箱即用补强](v1-performance-and-readiness.md) 及 ADR-009 的扩展原则。
- 剩余通用能力均纳入 v1；其余通用能力的补齐与唯一归属见 [覆盖计划](v1-capability-coverage.md)。具体公共 API、配置键、依赖、默认限制、feature 和模块布局仍需设计 Agent 形成 Spec/contract，不能把本计划中的建议直接当成已定接口。
- 优先扩展根 `framework/src/` 的既有能力模块与成熟库；不为每一项能力机械新增 Cargo package，不以自研密码算法、HTTP 协议栈或消息平台替代成熟实现。
- 实施按单功能簇闭环，先完成当前 WIP；新增依赖先记录 `stack.md`，公开名称按 ADR-006 登记。设计与实现职责遵循仓库契约。

国际化表达、邮件模板、查询授权/租户隔离、外部身份/TOTP 和 CSV/XLSX 等新增必交范围集中在 [底层补齐计划](v1-foundation-completion.md)，复用本文件定义的验证、调用作用域、出站和生命周期边界。

## 1. WebSocket

- 当前尚未实现。SSE 与其复用认证、资源限制、停机和跨节点 transport，范围见 [能力覆盖](v1-capability-coverage.md)；不能由 axum 支持升级推定框架已经交付。
- 交付：复用 HTTP 栈的握手/升级与路由接入，连接生命周期和身份授权入口，可运行收发示例、客户端示例及真实网络集成测试。
- 建议复用 axum 生态；接口采用类型化处理和明确注册方式，不建立独立平行服务器。
- 握手前复用认证/权限，明确 Cookie 或令牌的接入方式、Origin 校验、令牌过期/撤销及连接清理策略；不把 HTTP CORS 自动视为 WebSocket 的来源防护。
- 建议明确消息/帧大小、每连接发送队列、连接数、心跳/空闲超时、慢消费者处理与停机关闭的边界；不以无界队列吸收背压。
- HTTP 统一响应包装仅适用于可处理的握手前 HTTP 响应；升级后的消息协议单独约定，不能将帧强行按普通 HTTP JSON 响应包装。业务消息格式允许应用自定义。
- 集群部署为必须项：连接由所在节点维护，跨节点目标路由/广播必须通过至少一个真实 transport 实现，按 [集群计划](v1-cluster-deployment.md) 验收；业务频道授权可扩展。持久离线历史重放、完整聊天服务仍不自动纳入，不将重连说成自动恢复历史消息。
- 验收：认证拒绝、来源拒绝、消息收发、超限、慢消费者、异常断开、资源释放与优雅停机；记录连接/消息负载的延迟和内存行为。

## 2. 通用加密与密钥轮换

- 已按 [ADR-034](../decisions/adr-034-application-encryption-and-key-rotation.md) 完成：加解密在框架进程内完成，断网可运行；默认和 v1 验收不依赖云 KMS、Vault、第三方加密 API、账户或服务。复用成熟 Rust 密码库不等于依赖外部服务，不自研密码算法。实现审计状态与目标平台性能仍属 v1 发布前复核项。
- 普通开发者最小路径已提供 `openrust key generate`、现有配置机制、`EncryptionPlugin` 与 `Encryptor`；框架负责版本化密文、nonce、完整性校验、错误映射与配置验证。算法、nonce 和标签不要求业务逐次管理。
- 交付：认证加密、安全随机密钥生成方式、密文版本与密钥标识、篡改检测及本地密钥轮换。密码哈希继续由认证能力负责；用途隔离签名链接和撤销语义按 [ADR-036](../decisions/adr-036-signed-links.md) 实现。
- 已固定 AES-256-GCM-SIV/RFC 8452 与随机 nonce，不向普通用户暴露算法/模式/填充组合菜单；`aes-gcm-siv` crate 文档声明目前没有该 crate 实现的完整独立审计，需在发布前复核库审计和维护状态。
- 轮换采用一个当前加密密钥加少量只用于解密的历史密钥。新密文只使用当前密钥，旧密文依据非敏感密钥标识选择历史密钥；重复标识、非法长度与缺失配置应尽早报错。
- 建议密钥配置在启动时加载，轮换按配置更新和正常重启/滚动发布执行；不强制热更新、远程密钥中心或复杂 provider 管理。滚动发布时先让所有实例能解密新旧密钥，再切换写入密钥，验证后退休旧密钥。
- 移除历史密钥前须确认仍需访问的密文及备份可解密；轮换不会自动重加密数据库。提供清楚的迁移步骤和示例，不默认扫描改写用户数据，不自动删除旧密钥。
- 密钥通过现有显式配置和环境变量接入，不内置共享生产密钥，不写入日志或 `config show`。已实现的 `openrust key generate` 只向操作者明确输出结果，不擅自写全局配置或修改凭据；不重新命名已有命令。
- v1 不建设企业密钥管理平台。将来若确有外部密钥服务需求，再按公开边界扩展，不能使当前应用背负额外流程或必需服务。
- 验收：禁用网络/无第三方账户环境中的加解密、篡改/错误密钥拒绝、非法密文与配置、旧密文跨轮换解密、新密文使用当前密钥、缺失历史密钥的明确错误、日志遮蔽及独立应用最简示例。高风险代码需独立审查，按上层约束选择不同 Provider 或模型。

## 3. 请求幂等

- 当前尚未实现公共请求幂等服务。`Queue::dispatch_unique` 只在活动任务存在期间去重，`dispatch_in_transaction` 只解决同库提交边界，均不能代替请求指纹、响应重放和完成结果保留。
- 交付：供明确选中的变更接口启用的幂等机制，支持身份/接口/键隔离、请求指纹、并发竞争、结果状态与过期策略。
- 建议用数据库唯一约束与事务作为默认基础，无需 Redis；提供可扩展存储边界。不同内容复用同一键、请求处理中和过期后的行为须明确。
- 业务写入与幂等结果能否原子提交须由 contract 保证或说明限制；进程崩溃、超时和租约恢复不能被忽略。对外部副作用仍需供应商幂等或事务 outbox 协作。
- 建议只存有界且脱敏的可重放响应，考虑授权重新校验；不将用户之间的响应互相复用，不无界缓存大文件或流式响应。
- 与限流、防重复点击、数据库唯一性校验区分，不承诺跨所有外部系统的恰好一次执行。
- 验收：并发同键只执行业务一次、不同身份隔离、指纹冲突、失败与崩溃恢复、过期清理，双库验证事务边界。

## 4. gRPC

v1 正式交付可选 gRPC server/client，完整契约、组件方案、G1–G3 功能簇与验收以 [ADR-040](../decisions/adr-040-grpc-integration.md) 为唯一入口。四种调用、TLS/mTLS、认证/Status、deadline/流取消、资源限制、生成项目和真实集群均须完成，不能以底层 tonic 支持或 unary 示例替代。具体执行顺序见 `todo.md`。

## 5. 协议无关验证与调用作用域

- 现有 validator、Error 与 HTTP 字段路径继续使用；提炼必要的公开验证/错误转换入口，让 HTTP、gRPC、命令与 Job 可复用同一业务 DTO 规则。Protobuf/HTTP 只做各自适配，不新建校验 DSL；数据库唯一性预检不能替代唯一约束及竞争处理。
- AppState 保存应用级服务；身份、locale、trace/request ID、剩余 deadline 和取消是单次执行数据。优先显式传参和现有请求扩展/task-local，避免把可变请求状态存入共享单例，不为统一命名创建巨型 Context 或全局容器。
- 明确子调用的预算和取消传播；主动脱离请求的工作必须由命令/队列持有。队列只序列化白名单上下文，如 locale 和 trace 关联；不持久化访问令牌、Cookie、任意 header 或进程内句柄，不让原请求取消后永久取消已提交任务。
- HTTP → gRPC/HTTP → 队列/worker 验证追踪关联；不同执行次数使用可区分 span，重试/延迟任务的 parent/link 语义明示。授权在消费或执行边界重新校验，不把遥远请求里的身份快照当永久权限。
- 验收：相同 DTO 在不同入口的验证语义一致，协议错误形态分别正确；高并发不同用户/语言无串用，超时预算逐层缩减，取消资源释放，任务独立生命周期、敏感载荷排除和 trace 关联可观察。

## 6. 出站目标安全与调用韧性

这两项补既有 HTTP client 的公共整合边界，并供 gRPC 复用适用部分；分别成簇，先定最小 contract。当前客户端已有超时、取消、响应限额和显式幂等重试，不重复开发。

- **目标安全策略已按 [ADR-051](../decisions/adr-051-http-target-security.md) 实现**：`HttpClient::restricted` 可选约束 HTTP/HTTPS、主机/端口、凭据和公网/内网 IP；受限 resolver 检查全部 DNS 结果并将同一地址集合交给 connector。重定向保持关闭，受限模式拒绝代理和自定义 transport。仅约束框架 HTTP client，不拦截 SeaORM、存储驱动或任意第三方网络连接；边界见 `core/http.md`。
- **调用韧性已按 [ADR-052](../decisions/adr-052-named-dependency-resilience.md) 实现**：`HttpClient::dependency(name, policy)` 对同名配置共享有界并发/等待队列和可选熔断；等待、发送、重试共用客户端总时限，响应正文消费期间持有许可，取消释放队列和许可。熔断状态为进程内，按连续 transport/timeout 与 5xx 失败计数，4xx 清除连续失败。
- `RetryPolicy` 默认关闭；仅 `idempotent()` 明确声明的可重放请求可重试，最多五次。transport/timeout、429、502、503、504 使用指数全抖动；`Retry-After` 秒数/HTTP 日期受 `max_delay` 与 `retry_after_cap` 限制，重试仍受总预算约束。RPC stream 不默认重试，gRPC 需在实现后另行复验。
- 验收：目标安全已由 ADR-051 受控 resolver 与真实 TCP consumer 通过。韧性验收使用真实 loopback 服务覆盖双命名依赖隔离、容量与等待上限、取消释放、熔断打开/半开/恢复；单测覆盖重试上限、jitter 和 `Retry-After` 截断。安全校验不访问真实云元数据或无关第三方目标。
- 参考 [OWASP SSRF 防护说明](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html) 识别边界；该策略是应用可选能力，不替代部署侧网络访问控制，也不代表本轮已完成安全测试。

## 里程碑与交付证据

| 阶段 | 安排 |
| --- | --- |
| M3 基础复用 | 国际化、出站 HTTP、加密、验证码、审计和签名链接已有实现；相应本地验收见 `core/` 与 `memory/`。真实短信投递、完整集群和负载性能仍有独立门槛 |
| M4 | 复用 ADR-037 的同事务数据库队列，补请求幂等与业务流程扩展；审计和通信按需接入后台任务，不强制所有记录异步化 |
| M5 | 协议无关验证/调用作用域、出站策略、有界运行及 gRPC G1–G3，完成 WebSocket 和跨能力资源/可观测性集成；已有认证和配置复用 |
| M6 | 各项能力在源码 workspace 的生成应用与聚合宿主验证；文档、测试、feature 矩阵、扩展示例、性能与生产说明齐全 |

代表性应用按能力实现顺序逐步覆盖，只有实际执行验证并更新模块事实后才能标记完成。PostgreSQL/MySQL、真实共享服务、多节点与生成项目各自需要匹配范围的证据。正式发布、供应商实发、凭据写入等操作不因本计划获得额外授权。

## 通用能力补齐与后续边界

SSE、薄通知、任务编排及 Session/API/缓存/锁均为 V1 范围；F1–F10 也按 [底层补齐](v1-foundation-completion.md) 必交。业务通知中心、组织/租户管理与 UI 归 V2；持久离线重放、更多数据库、独立 OAuth 授权服务器等仍为后续评估。外部 OAuth2/OIDC/SSO 接入与 TOTP 已归 V1，不再笼统后置认证协议。
