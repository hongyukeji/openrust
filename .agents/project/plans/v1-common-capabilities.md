# v1 通用能力补齐计划

> 受众：AI Agent
> 更新：2026-10-25
> 摘要：国际化、WebSocket、出站 HTTP、加密与密钥管理、审计及请求幂等纳入 v1；记录最小范围、设计建议和验收要求，不代表已经实现。

## 范围与决策规则

- 本计划补充 [v1 总计划](gen1-plan.md)、[性能与开箱即用补强](v1-performance-and-readiness.md) 及 ADR-009 的扩展原则。
- 六项能力均纳入 v1。具体公共 API、配置键、依赖、默认限制、feature 和模块布局仍需设计 Agent 形成 Spec/contract，不能把本计划中的建议直接当成已定接口。
- 优先扩展既有能力 crate 与成熟库；不为每一项能力机械新增 crate，不以自研密码算法、HTTP 协议栈或消息平台替代成熟实现。
- 实施按单功能簇闭环，先完成当前 WIP；新增依赖先记录 `stack.md`，公开名称按 ADR-006 登记。设计与实现职责遵循仓库契约。

## 1. 国际化

- 交付：应用默认语言、按请求选择语言、回退语言、消息键与参数替换，覆盖框架错误、验证信息和邮件/短信模板的语言选择示例。
- 建议优先交付中文与英文的框架消息资源；应用可加载自己的资源，业务翻译内容由开发者提供。复用成熟资源格式与库，不强制新造翻译 DSL。
- 建议通过明确的请求上下文选择语言，不使用可被并发请求互相覆盖的全局可变语言。明确显式选择、用户偏好、请求头与默认值的优先级。
- 稳定错误 code 和字段路径不随语言改变；翻译面向可展示消息，不翻译配置键、协议字段、机器标识或生产内部异常细节。
- 验收：并发语言隔离、回退、缺失键/参数、验证消息及模板选择；补独立应用的资源扩展示例。复数、地区格式等高级能力先明确范围，不暗示完整支持。

## 2. WebSocket

- 交付：复用 HTTP 栈的握手/升级与路由接入，连接生命周期和身份授权入口，可运行收发示例、客户端示例及真实网络集成测试。
- 建议复用 axum 生态；接口采用类型化处理和明确注册方式，不建立独立平行服务器。
- 握手前复用认证/权限，明确 Cookie 或令牌的接入方式、Origin 校验、令牌过期/撤销及连接清理策略；不把 HTTP CORS 自动视为 WebSocket 的来源防护。
- 建议明确消息/帧大小、每连接发送队列、连接数、心跳/空闲超时、慢消费者处理与停机关闭的边界；不以无界队列吸收背压。
- HTTP 统一响应包装仅适用于可处理的握手前 HTTP 响应；升级后的消息协议单独约定，不能将帧强行按普通 HTTP JSON 响应包装。业务消息格式允许应用自定义。
- 最小范围为单实例连接管理与受控收发，业务频道授权入口可扩展；跨实例广播、离线消息、历史重放、可靠送达、完整聊天服务不自动纳入。断线重连示例不承诺消息自动恢复。
- 验收：认证拒绝、来源拒绝、消息收发、超限、慢消费者、异常断开、资源释放与优雅停机；记录连接/消息负载的延迟和内存行为。

## 3. 统一出站 HTTP 客户端

- 交付：连接复用、JSON 请求/响应、可配置超时、状态与传输错误、测试 fake/调用断言及第三方 API 示例，供供应商适配复用。
- 建议封装成熟客户端的公共最小能力，保留可控的底层访问；优先复用既有依赖，不自建第二套网络栈。
- 明确连接/读取/总超时、响应体上限、重定向和请求取消行为；非幂等请求不默认重试，幂等重试次数/退避须有界。
- URL 来自用户输入的场景需显式处理目标与重定向限制，不把客户端包装等同于自动解决 SSRF；日志不记录令牌、认证头和完整敏感正文。
- 验收：真实本地测试服务与 fake 各自覆盖超时、错误、JSON、重试与取消；fake 无意外真实网络请求。

## 4. 通用加密与密钥管理

- 交付：基于成熟密码库的认证加密入口、安全随机密钥生成方式、版本化密文、篡改检测、密钥标识与轮换约定；密码哈希继续由认证能力负责。
- 建议评估标准 AEAD 实现，使用库提供的安全随机 nonce 管理；算法与库选型需专项审查，不实现自有算法或把编码当加密。
- 建议新数据使用当前密钥、旧数据按标识选择可解密密钥；定义移除旧密钥前的数据迁移和备份要求，避免静默破坏既有数据。
- 密钥通过显式配置/外部提供者接入，不内置默认生产密钥，不写日志；示例命令不得自动修改用户全局配置或凭据。
- 验收：加解密、篡改/错误密钥拒绝、轮换兼容、非法密文及敏感日志检查；高风险代码需独立审查，按上层约束选择不同 Provider 或模型。

## 5. 审计事件与记录

- 交付：统一审计事件、显式记录入口、可扩展 sink，以及至少一个真实持久化实现与测试 fake；覆盖账号/权限变更示例，不强制后台 UI。
- 建议区分审计与请求追踪：主体、动作、对象、结果、时间、请求 ID 为核心字段，变更内容按白名单记录并脱敏，避免默认存储完整请求/响应。
- 优先评估数据库持久化与既有事务/事件机制；明确授权失败、事务回滚、写审计失败时的行为，关键审计是否随业务提交须形成 contract。
- 明确保留/清理、访问权限、可信代理后的来源信息及测试隔离；最小实现不承诺不可篡改、法律合规或自动记录所有业务动作。
- 验收：成功/失败/回滚事件、记录故障、脱敏和扩展 sink；数据实现需 PostgreSQL/MySQL 证据。

## 6. 请求幂等

- 交付：供明确选中的变更接口启用的幂等机制，支持身份/接口/键隔离、请求指纹、并发竞争、结果状态与过期策略。
- 建议用数据库唯一约束与事务作为默认基础，无需 Redis；提供可扩展存储边界。不同内容复用同一键、请求处理中和过期后的行为须明确。
- 业务写入与幂等结果能否原子提交须由 contract 保证或说明限制；进程崩溃、超时和租约恢复不能被忽略。对外部副作用仍需供应商幂等或事务 outbox 协作。
- 建议只存有界且脱敏的可重放响应，考虑授权重新校验；不将用户之间的响应互相复用，不无界缓存大文件或流式响应。
- 与限流、防重复点击、数据库唯一性校验区分，不承诺跨所有外部系统的恰好一次执行。
- 验收：并发同键只执行业务一次、不同身份隔离、指纹冲突、失败与崩溃恢复、过期清理，双库验证事务边界。

## 里程碑与交付证据

| 阶段 | 安排 |
| --- | --- |
| M2 收口后至 M3 | 国际化及出站 HTTP 先形成契约；M3 认证/通信接入，补加密、密钥、审计与验证码设计和实现 |
| M4 | 请求幂等与业务事务/队列派发边界落地，审计和通信接入后台任务；不强制所有记录异步化 |
| M5 | 完成 WebSocket 与有界资源/可观测性集成；前置认证与相关 HTTP 配置已有明确契约 |
| M6 | 六项能力在独立生成项目和聚合宿主验证；文档、测试、feature 矩阵、扩展示例、性能与生产说明齐全 |

代表性应用按能力实现顺序逐步覆盖，只有实际执行验证并更新 crate 事实后才能标记完成。正式发布、供应商实发、凭据写入等操作不因本计划获得额外授权。

## 保留的后续方向

SSE、跨实例实时广播、通知中心、后台 Starter/UI、复杂任务链/批处理、更多数据库、OAuth/SSO 等保持后续候选。现有 ORM、队列、Session、API 输出、缓存能力需细化最低契约与示例，不以“底层库支持”代替框架使用体验；其中具体高级功能仍需场景驱动决策。
