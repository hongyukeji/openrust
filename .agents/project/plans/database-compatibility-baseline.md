# 数据库兼容基线

真人明确要求与项目固定 Laravel 官方支持版本保持一致。本表是交付目标，不表示当前所有驱动、版本和行为均已实现或通过验收；实际状态和执行负责人在[唯一待办](../todo.md)维护。

| 数据库 | 最低兼容目标 |
| --- | --- |
| MariaDB | 10.3+ |
| MySQL | 5.7+ |
| PostgreSQL | 10.0+ |
| SQLite | 3.26.0+ |
| SQL Server | 2017+ |

固定来源为项目 Laravel 文档基线的 database 章节，公开参考见[Laravel 数据库支持](https://laravel.com/docs/13.x/database#introduction)。未来上游升级按既定版本跟进流程核对，不以浮动页面静默改变本批基线。

## 支持与验证边界

- 上述目标替代旧暂定 PostgreSQL 14+、MySQL 8.0+ 的最低支持口径。历史版本验收仍保留，但不代表更低版本已通过；仅降低版本检查阈值不能算完成兼容。
- 真人最终确认：日常开发只运行真实 MySQL 8.4 数据库验收，参考 [Laravel Sail 的 MySQL 8.4 模板](https://github.com/laravel/sail/blob/1.x/stubs/mysql.stub)。这不是 Laravel 所有安装方式的唯一数据库默认值，也不改变 MySQL 5.7 的最低兼容目标；其他既有非数据库质量门禁继续执行。
- PostgreSQL、SQLite、MariaDB、SQL Server 及各最低版本的运行矩阵归入发布前验收；未开始的非 MySQL 日常阶段转发布待验，已在途命令自然结束并清理自有资源。
- 发布新版本前完整验证全部承诺数据库、最低与选定当前版本的适用连接、查询、Schema／迁移、事务及框架业务链路。缺少驱动、未实现、未执行或失败项目明确保留缺口，不能宣称五库完整兼容或发布已通过。
- 驱动能力、SQL 方言、版本功能、认证／TLS 等真实约束按固定官方语义补齐并验证；不得以依赖默认限制、开发环境版本或维护方便擅自抬高最低基线。
- 数据库生命周期／厂商维护状态与框架兼容范围分开记录；本兼容目标不要求默认部署旧版本，不自动授权新建或替换共享数据库服务。

总控统一同步 stack、core/db、配置校验、生成器、文档、测试规范与发布矩阵中的现行口径，保留历史证据。当前主线仍先完成 Query 验收提交推送，再执行框架目录迁移；后端实现由并行负责人按依赖推进，运行多数据库验收不作为日常提交门槛。
