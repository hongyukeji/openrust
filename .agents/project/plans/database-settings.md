# 数据库动态设置开发记录

记录日期：2026-11-21。状态：框架设置扩展已实现并通过本阶段验收。S2 后台及 S3 具体服务接入属于应用层按需工作，不作为框架扩展完成条件。实际证据见[设置底座验收记录](../audits/settings/README.md)。

## 目标与范围

提供通用管理后台的系统设置能力，让管理员通过后台维护运行期业务配置。网站设置、短信设置和存储设置只是首批示例，不是能力边界。应用及业务模块应能按同一约定新增设置组，无需修改设置底座或为每个分组新增数据库表。

采用“通用设置底座＋应用声明的类型化设置组＋后台表单与服务接入”的结构。框架扩展负责读取、持久化、类型转换、加密和生命周期；后台负责表单、权限、校验、展示及操作记录；具体组件负责读取设置并落实生效行为。保存到数据库不等于已经完成组件动态接入。

框架交付范围为 S1 通用底座。管理后台产品、权限策略、操作记录及具体消费者适配由使用本扩展的应用按需实现，不列为框架待完成批次。现行固定 Laravel 基线及项目目录约定以[项目规范](../conventions.md)和[基线记录](laravel-rebuild-baseline.md)为准。

## 设置分类与接入边界

下表是常见设置的覆盖方向，不要求一次性实现全部页面和服务。新增业务设置沿用同样的分组、校验和读取流程。

| 类别／候选分组 | 常见内容 | 生效与职责边界 |
|---|---|---|
| 网站与 SEO：`site` | 网站名称、标题、描述、关键词、Logo、备案信息、版权、联系方式 | 新请求读取；公共输出只选择明确可公开的字段。 |
| 地区与显示：`localization` | 默认语言、展示时区、日期格式、货币展示 | 仅接入声明支持的显示行为，不改变数据库时间语义；翻译词条仍由翻译模块管理。 |
| 邮件：`mail` | 默认 mailer、命名 mailer、发件人、SMTP 凭据 | 保留既有组件命名；配置变更后新发送使用新实例，历史任务语义明确。 |
| 短信：`sms` | 默认服务、命名驱动、签名、模板映射、凭据 | 沿用现有 `default`、`drivers`；任务选定的服务名称与执行时凭据读取分别定义。 |
| 存储：`filesystems` | 默认磁盘、命名磁盘、对象存储凭据及访问域名 | 沿用 `default`、`disks`；重建受影响磁盘实例；旧文件保留磁盘标识。 |
| 上传：`uploads` | 文件大小、类型、图片尺寸、文件命名策略选项 | 由上传业务及 Validator 执行；不能突破服务器请求体限制等部署约束。 |
| 账号与安全策略：`registration`、`security` | 是否开放注册、邮箱／手机验证要求、验证码、登录策略参数 | 经认证与限流组件显式接入；密钥、路由装配和 Guard 结构不由通用设置任意改写。 |
| 通知：`notifications` | 默认业务通知渠道、事件通知开关、模板选择 | 区分系统默认值与用户个人偏好；服务执行及模板内容仍归对应模块。 |
| 第三方服务：`services` 或业务命名组 | OAuth、验证码服务、地图等启用状态及凭据 | 保留既有配置名称；需要路由或 Provider 装配的变化可能需要重启，页面明确提示。 |
| 业务策略：由模块命名 | 业务开关、展示规则、阈值等 | 模块声明字段、权限及接入点；支付／订单等已有记录保留发生时的关键业务参数。 |

组名在实现时按现有 `config/*.rs` 及所接入组件最终核对，后台栏目名称不要求与数据库分组一一对应。不要为这些例子预建全部设置类或空页面。

部署配置继续由环境变量和配置文件管理：数据库／Redis 连接、应用加密主密钥、监听地址、容器绑定及 Provider 清单等。系统设置也不承担定时任务执行器、权限模型、翻译词条库或任意脚本执行功能。

## 包、命名与存储

候选包为可选扩展 `openrust-settings`，目录 `vendor/openrust/settings/`。应用装配候选为 `config/settings.rs` 与 `app/settings/` 下的设置类型；模块自己的设置放在模块内并通过现有 Provider 机制显式登记。上述路径已在 S1 实现；不因包可编译将后台及服务接入标为完成。

主要名称参考 `Settings`、`SettingsRepository`、`DatabaseSettingsRepository`、`SettingsServiceProvider`、`group`、`save`、`refresh`。最终签名、异步边界、序列化及 Artisan 命令在锁定上游和核对容器生命周期后确定，不先发明另一套不兼容术语。

首期采用单表 `settings`：

| 字段 | 作用 |
|---|---|
| `id` | 主键。 |
| `group`、`name` | 设置组和属性名，联合唯一约束。 |
| `payload` | 属性的 JSON 表示，支持标量、数组和对象；加密属性保存密文表示。 |
| `locked` | 预留上游锁定语义，具体行为核对后实现；不是管理员权限的替代。 |
| `created_at`、`updated_at` | 创建与更新时间。 |

属性类型、默认值、敏感标记和校验规则由应用代码声明，不把数据库中任意键自动暴露为可写设置。默认按组事务保存，组内对象必须有明确的字段校验及合并规则。更新时拒绝未知组、未知属性和错误类型；读取旧数据时的兼容策略由设置迁移确定。

默认值与已有 `config/*.rs` 衔接；数据库存在有效值时使用设置值，未配置时回退现有默认值。区分缺失、`null`、空字符串、`false` 和 `0`，不能按真假值判断是否回退。新增属性、改名与默认值演进通过可追踪迁移处理，升级时保留管理员自定义值。

“恢复默认”移除指定数据库覆盖并重新使用代码／配置默认值；“清除”写入字段允许的空值；“保持不变”不写入该字段，三者分别表达。驱动配置采用字段白名单及明确的对象补丁规则，数组默认整体替换，不使用不加区分的递归合并；切换驱动时重新校验必填项并处理旧凭据。含多个供应商密钥的对象可首期整体加密，后台仍仅修改允许的字段，不能因嵌套结构而明文落库。

不修改原同步 `Config::get` 契约，不在每次同步读取中执行异步数据库查询。设置层显式异步加载，按需提供给消费者；需要覆盖现有配置的组件只接入声明的字段。禁止用数据库任意覆盖整个配置仓库、修改 `.env`，或将动态值固化进 `config:cache`。

## 生命周期与动态生效

1. HTTP 请求及 Worker 单个任务建立设置作用域，首次访问某组时加载一次，作用域内复用；下一请求／任务重新解析。具体作用域实现需核对当前容器和 Worker，不将此设计写成已有能力。
2. 首期默认数据库读取＋作用域内缓存，不增加永久进程单例；无需依赖共享 Redis 缓存才能正确生效。在途请求／任务允许继续使用已取得的设置。
3. 保存时以当前数据库值合并本次补丁并验证完整候选值，在事务内写入；刷新只发生在真实最外层事务提交之后。外层回滚不发布变更。提交后通知／审计出口失败不能冒充数据库回滚，也不要求全节点即时刷新；后续作用域仍从数据库取得新值。跨组修改不默认承诺全局原子切换。
4. `FilesystemManager` 缓存磁盘实例，单改配置值不足以生效。接入时核对现有 `forgetDisk` 与实例所有权，避免新作用域再次拿到旧实例，或清理仍被在途请求使用的资源。邮件、短信及第三方客户端按相同原则逐项核对。
5. 可选共享缓存后续按实际需求接入。必须先验证事务提交后的失效、旧读回填与并发保存、缓存故障及多进程可见性，不能仅靠删除缓存就宣称一致。缓存暂不作为首批交付前置。
6. 缺失设置按声明默认值回退；数据库故障、密文损坏和类型错误应可观察、可诊断。敏感服务配置不静默使用错误或陈旧凭据；如某组采用降级策略，须单独声明并验收。

后台区分“已保存”和“已生效”，明确新请求／新任务生效及需重启的项目。存储默认值变更只影响新上传，历史文件仍能定位；短信／邮件排队任务明确派发时确定哪些参数、执行时读取哪些凭据，不因默认服务变化悄然改投其他服务。

按组读取使用一次完整查询或一致事务快照，禁止逐属性查询导致同组混用提交前后的值。作用域内复用同一组快照；`save`／`refresh` 显式更新当前实例，其他已取得的实例保持原快照。跨组不承诺同一版本；需要共同校验及原子变更的字段应优先放在同一组。

后台多管理员编辑必须有冲突检测：读取取得不含明文秘密的不可解释版本标识，保存时在数据库原子保护下比较，冲突提示重新加载，不静默覆盖。不仅检查提交前的一次读取，也不能仅依靠低精度 `updated_at`；具体机制须在 S1 仓储实现前确定并覆盖三库，含首次创建时的竞争。不要求新增修订表。设置读取、补丁合并、校验及写入必须共同防止并发绕过跨字段约束。

作用域复用现有容器／Facade 生命周期，不新建平行作用域系统。除 HTTP 与 Worker 外，普通 Artisan 调用按命令作用域加载；长期运行命令、Scheduler 每轮／任务及流式连接须声明刷新边界，不能把整个常驻进程当成一次操作。异步并发首次加载、取消和失败重试不能共享半初始化对象，也不能泄漏到其他应用或请求。

服务实例从作用域设置快照创建或按其有效配置身份复用，避免并发请求原地修改全局配置仓库。远端进程不能依赖保存进程的 `forgetDisk`；其新操作必须自行解析最新设置。还须验证 `MailManager` 的 mailer 缓存；旧文件更改磁盘名、根目录或 bucket 会失去定位，迁移／删除仍被引用磁盘不作为普通设置更新开放。

## 后台与敏感信息

- 设置底座只提供类型化读写能力；管理 API、表单和菜单属于应用／可选后台模块，不向框架核心植入后台 UI。
- 按组检查读取与更新权限，复用 FormRequest／Validator、Gate／Policy。仅允许声明字段；局部更新不得用默认值覆盖未提交字段。
- 敏感属性在落库前使用现有加密能力加密。读取接口返回“已配置”等状态，不回传原密钥；空白保留、替换、显式清除分别表达。嵌套驱动对象的部分修改不能误删其他凭据。
- 公共网站设置提供明确的公开字段投影；禁止直接输出整组或整张表。凭据不写入普通日志、错误响应或明文共享缓存。
- 操作记录优先复用宿主应用审计机制，记录操作者、时间、设置组、变更字段与结果；敏感字段仅记录变更动作。当前没有据此确认可直接复用的统一审计模块，S2 须确认宿主出口；没有持久出口时明确标为缺口，不将普通日志计作可靠审计。设置写入与审计的事务／失败策略在接入时确定。首期不新建完整版本历史、审批或回滚平台。
- 测试连接、发送测试邮件／短信等操作属于显式动作，先校验权限和参数，不在保存时自动发送；限制可配置地址、磁盘路径及访问范围，避免将设置入口变成任意网络或文件访问入口。
- 后台 HTTP 沿用现有认证及 CSRF 等保护，读权限与改写权限分别校验；高风险认证设置按宿主机制执行密码确认或二次验证，防止管理员把自己的恢复入口关闭。Rust 内部设置对象的 `save` 供可信应用调用；不把每个内部仓储写入都等同于后台授权接口。
- 密钥轮换复用现有 `APP_PREVIOUS_KEYS` 解密能力，提供受控、可重试的重新加密流程后再移除旧密钥；备份恢复须同时具备适用解密密钥。缺失旧密钥明确报错，不以默认值覆盖坏密文。禁止通用 `Debug`／序列化、队列任务载荷和审计参数带出明文；脱敏占位字符串不能当作新密钥写回。

## 安装、升级与运维恢复

- 未启用扩展时不查询设置表。Provider 注册不强制访问数据库，首次安装、`migrate`、包发现及配置缓存命令不能因设置表尚未创建而无法执行；显式需要数据库设置的业务入口遇到缺表则给出可操作错误，不静默当作空表。
- 使用现有迁移体系登记建表和设置数据演进，不额外创建第二套迁移执行器；S1 明确扩展启用／配置发布／迁移／首次读写的正式顺序及 Artisan 入口，与现有初始化流程联通。重复安装和迁移不得重置已有设置。
- 同一仓储中重复组名或属性映射须在登记时拒绝；模块停用默认保留数据，再启用仍可读取。删除模块的数据须显式操作，不能顺带删除其他组。
- 固定数据库连接及逻辑表名配置；保留 Schema／Query Builder 的标识符引用，避免 `group` 在不同方言中的保留字问题。设置仓储优先读取写连接，避免保存后读取副本延迟；不与宿主其他数据库或应用共享不受隔离的缓存键。
- 备份以数据库持久值与部署密钥为准，不依赖缓存恢复。提供受控的指定组／属性重置或修复入口，复用 Artisan、现有服务及部署操作权限；公开后台仍执行应用授权。默认不提供明文密钥导出，不以完整版本回滚系统为前置。
- 新旧应用版本共存时采用先新增再迁移再移除的兼容流程；旧版读取未知属性与新版读取缺失属性的行为单独测试。默认值只填缺失属性，不在进程启动时反复全量写库。JSON 大小、属性数、查询超时和重试须有明确上限；设置不存文件内容或无界业务数据。

## 开发顺序与验收

| 批次 | 交付内容 | 关键验收 |
|---|---|---|
| S1 通用底座（已验收） | 按固定 Spatie 提交对账并检查旧版复用；确认目录、接口及生命周期；类型化设置、单表仓储、迁移／默认值、加密、按组事务及冲突检测；网站及自定义模块设置示例 | 类型往返、缺失／空值／恢复默认差异、锁定属性、安装及升级、组内快照与并发冲突、外层回滚、密钥轮换与恢复、请求／任务隔离、独立进程下次操作读取新值。 |
| S2 后台接入约定（应用层参考） | 选定已授权的后台载体，提供分组读取／保存、表单校验、权限、脱敏、公开投影及操作记录 | 未授权／未知字段拒绝、局部更新与显式清除、并发编辑、秘密不泄露；新增业务组无需改底座。没有后台开发授权时只完成契约及应用侧示例。 |
| S3 服务接入（应用层参考） | 优先短信、存储，再按需求邮件、上传、注册安全、通知和其他服务 | 常驻 HTTP 与 Worker 新值可见、旧实例处理、旧文件定位、队列参数语义；逐组记录真实服务验证范围。 |

框架扩展以 S1 独立验收闭合。S2／S3 保留为应用接入参考，未经独立应用开发任务授权不自动推进；不把所有常见设置一次性内置，也不以网站示例代替通用扩展能力验收。公开配置保持现有 Laravel 名称；新增组的指南需包含声明、登记、读写、权限、校验和生效边界。

实际实现按当前项目规范使用 Rust 1.94.0、隔离源码快照与独占 target；共享数据库行为分别使用隔离 PostgreSQL 18、MySQL 8 和 SQLite；若接入共享缓存，覆盖 Redis 8、database、file，database 缓存的 SQL 路径同时覆盖三库。不改开发数据，不能将缺变量跳过计为通过。运行对应测试、格式与严格 Clippy，并覆盖真实 HTTP／Worker／Artisan 入口、多个独立应用进程和同进程多应用隔离。交付后补齐三语用法文档；本次纯内部计划只校验链接、路径和差异。

首期不引入多租户／用户多级继承、通用表单生成器、独立配置中心、Pub/Sub 集群发布、全量修订回滚或审批系统。确有需求时再以当前设计扩展，避免影响简单的分组读写流程。

## 与现有待办的关系

数据库动态设置与 `openrust-translation-database` 分别跟踪：前者存储类型化运行期参数，后者提供翻译词条加载。语言选择可以是设置，词条内容继续由翻译模块承担。此记录不改变既有核心／扩展的排程，也不将旧版 ADR 的动态配置设计自动视为当前约定。

## 2026-11-21 计划审计

计划审计时结论：主体方向保留，补齐以下约束后可拆分开发。当前实现状态以文首及验收记录为准。

| 优先级 | 原计划缺口 | 本次处理 |
|---|---|---|
| P1 | 按组事务保存未保证按组一致读取，管理员并发修改可能覆盖或破坏联合校验 | 补充一次查询／一致快照、数据库保护下的冲突检查和首次插入竞争；机制在 S1 编码前收敛。 |
| P1 | 保存进程刷新不能让其他进程更新，原地改全局配置可能串请求 | 明确作用域快照、自行重解析、实例配置身份、邮件缓存及跨进程验收。 |
| P1 | 未定义初次安装、缺表、外层事务及提交后失败 | 补充启动免查询、安装顺序、真实提交后刷新和失败结果区分。 |
| P1 | 凭据加密未覆盖密钥轮换、恢复及对象序列化泄露 | 补充旧密钥、重加密、备份恢复和输出边界。 |
| P2 | 默认／清除／未提交、嵌套补丁及锁定语义未闭合 | 明确前述操作差异；锁定规则对照固定上游后定稿，后台不得假报更新成功。 |
| P2 | 未明确模块重名、停用保留、滚动升级及长命令刷新 | 补充登记、迁移兼容、保留数据和作用域边界。 |
| P2 | “复用审计”预设了未经核实的宿主能力 | 改为明确依赖／待接入项；记录事务与失败策略门禁。 |
| P2 | 验收环境落后于现行三库／三缓存规范 | 修正环境，增加独立进程、恢复、并发及初始化场景。 |
