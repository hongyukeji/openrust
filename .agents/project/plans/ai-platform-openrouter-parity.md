# AI 平台 OpenRouter 功能对标与最终验收计划

> 受众：AI Agent
> 基线日期：2026-10-25
> 状态：域级计划审计已完成，产品未启动；逐接口、登录后页面和真实供应商行为仍待 P0 取证。
> 摘要：最终目标是复刻 OpenRouter 公开产品的功能与关键使用流程；MVP 是交付阶段，不是终点。独立产品与 `projects/*` 约束保持有效。

## 审计结论与目标定义

原 [产品计划](ai-platform-product.md) 的 P0–P3 可构成网关和商业运营首版，但不足以支撑完整 OpenRouter 功能对标。主要缺口为：API/页面覆盖未建清单；多协议、多模态、BYOK 和团队能力只列按需扩展；缺失供应商侧、企业治理、工具执行、开发工具和最终逐项验收门槛。

- 本次需求将终点升级为“公开功能与主要业务流程对标”，包括公开列出的 Beta/实验能力；原 P4 的按需扩展措辞不再允许省略最终能力。
- 当前范围基于官方公开站点、文档索引、API 文档及专项正文。未登录客户/企业/供应商后台，也未调用付费 API；不能将本次域级审计称为逐页面、逐字段或全端点行为审计。
- 复刻以可观察契约、功能和用户流程为准，采用自己的品牌与资源。无法从公开资料得知的内部算法、合作条款、用户规模、私有模型、历史流量与运营数据不能靠代码复制，也不能伪造为已达到。
- 在 P0 固定一份有日期的功能/接口/页面基线；后续官方新增或废弃项目进入差异清单，由开发者确认更新目标，不因对方持续发布使交付终点无限移动。
- 尚不确定的功能保持“待取证”；外部资格或服务缺失保持“待外部条件”。Agent 不得静默改成不做，也不能用假数据、空页面、模拟器或仅连 OpenRouter 一个上游宣称整体复刻完成。

## 审计发现与修订

| 优先级 | 原计划不足 | 修订要求 |
| --- | --- | --- |
| 阻断最终验收 | 首版范围与最终目标混用 | 保留首版，增加 P4–P8 与全量对照门禁；首版完成不能关闭产品 |
| 阻断范围确认 | 缺少端点、角色、页面和计量维度清单 | P0 建立可追踪基线，每项关联来源、实现、测试、证据和状态 |
| 高 | 泛称 OpenAI 兼容 | 拆分 Chat/Responses/Messages/Embeddings 等协议、字段与错误/事件；不把 OpenRouter 行为当作 OpenAI 全部行为 |
| 高 | 仅余额扣减路径较明确 | 补自动充值、预算层级、BYOK 服务费、工具/文件/异步计量、供应商应付与对账等规则 |
| 高 | 缺少真实供应商平台 | 增加端点准入、模型/价格同步、质量/可用性观测、运营和结算流程 |
| 高 | 无企业隔离和隐私端到端证据 | 企业身份、workspace、私有端点、数据策略及区域路由必须有拒绝路径与真实部署验证 |
| 高 | 只覆盖 API 用户 | 补访客、个人、组织管理员/成员、供应商、平台运营的完整网站流程 |
| 中 | SDK/CLI/MCP/Agent 生态未排期 | 纳入后期强制阶段；具体兼容目标与工具能力在 P0 拆项 |

## P0 必建的追踪清单

产品启动后在产品分支保存权威细项清单，不能只沿用本次领域表。每条至少包含：

- 稳定 ID、官方来源 URL、观察日期、稳定/Beta/废弃标记及证据级别（文档、页面实测、真实 API 实测）。
- 用户角色、页面/动作、API method/path、请求/响应/流事件/错误/权限、计费与数据区域影响。
- 本平台目标行为、兼容偏差、负责模块、依赖能力/外部服务、阶段与验证用例。
- 状态只用待取证/已规格化/开发中/已实现/已验证/待外部条件等可区分字段；“有入口”“有 mock”“只通过编译”不等于已验证。
- 按接口、用户旅程、能力域分别统计覆盖；不能按文件数或粗略模块数宣称完成百分比。全部最终项和未知项未关闭前，不宣称全面复刻。

先从官方文档索引与 API schema 建立清单，结合访客/客户/组织/供应商/运营角色的真实浏览器流程补证。登录或企业权限不可用时只记录缺口，不推测后台行为或索取不必要凭据；后续在获得适用访问条件时补验。

## 关键 contract 风险

- Responses：官方当前文档为无状态，不支持 `store: true`/非空 `previous_response_id`；对标应验证相应拒绝行为。不能因为它叫 Responses 就承诺 OpenAI 的所有持久状态能力。
- SDK 兼容：必须覆盖响应字段、流式 delta/usage、工具与推理、错误码/header、取消和重试；只有 happy path 请求成功不算兼容。
- 身份隔离：组织/workspace、BYOK、文件、缓存、私有模型、日志、工具任务与预算统一授权，不能依赖 UI 隐藏或 Key 字符串猜测租户。
- 财务隔离：用户余额、平台上游成本、BYOK 服务费和供应商应付分别记账；缓存、失败尝试、工具子调用及批处理部分成功均需明确收费；无法确认的成本进入核实流程。
- 缓存与回退：response cache 不跨权限/数据策略复用；路由不能为了成功率跳过地区、隐私、能力与预算过滤；跨地区回退缺省禁止。
- 工具执行：shell/Agent 必须运行在产品专用隔离环境，网络/文件/时间/递归/费用有界，不能复用框架宿主机权限；不是简单增加一个 HTTP 路由。
- 路由质量：内部评分/训练数据不公开时，用可说明和可测的等效策略达成目标，不能声称重现相同内部算法；需要离线评测与在线指标，不能只做随机转发。

## 外部条件与可达性

| 目标 | 软件可交付 | 最终验证还需要 |

## 最终完成定义

1. 基线内所有公开功能/API 家族均有细项映射；未知、偏差和外部阻塞公开可查，不能标成完成来凑覆盖率。
2. 全部目标端点与页面具有实现、权限/错误/流式/计费/隔离测试，目标 SDK 和真实上游的证据；所有业务状态从前端到后台到 API 闭环。
3. 资金预占/结算/释放/充值/退款/应付具备并发、重复、乱序、崩溃、补偿与对账验证；多区域/多副本故障不导致越权或重复扣费。
4. 真实跨供应商回退、BYOK/私有模型、文件/批处理、多模态及托管工具完成最终公开矩阵验收，不依赖 OpenRouter 作为唯一实现来源。
5. 备份恢复、SLO/容量基准、灰度/回滚、依赖故障与数据驻留验证达标；文档、集成、运维与客户/供应商旅程可复验。
6. 通用框架主线仍保持独立：产品代码与依赖不进入默认构建，所有拟回馈框架的变更有独立理由与验证，不能因产品验收而降低框架标准。
7. 若某项受真实外部条件阻塞，可发布注明差异的阶段版本；在其完成前不得宣称“全面复刻”。确需减少最终范围只能由开发者明确决定，不能由 Agent 自行降级。
