# Artisan 非交互式完整初始化

2026-11-26 用户确认方案。本文记录交付契约和验收条件；实现范围、功能清单及实际运行结果见[完整初始化验收](../audits/00-03/init-full.md)。

## 已确认的命令契约

| 源码入口 | 行为 |
| --- | --- |
| `./artisan init` | 保留现有交互式向导及既有选项，供开发者自定义。 |
| `./artisan init:full` | 全程非交互。使用开发者提前准备好的 MySQL 和 Redis，完成完整功能安装、配置、构建、迁移和运行验证。 |
| `./artisan init:full --dry-run` | 只读列出目标服务、安装清单、文件变更、冲突和迁移计划。区分已核实和需要安装或构建后才能确认的迁移。输出脱敏。 |

Windows 使用 `artisan.bat init:full`。把 `init:full` 注册为可在 `artisan list` 发现的正式命令，同步帮助。两入口共用安装流程。沿用分项安装命令，旧 `install:full` 继续只作为历史文档锚点。完整预设无需选拓扑，实际部署由部署工具负责。命令执行和交付均无需 Docker Compose，由开发者提供可用 MySQL 与 Redis，首版无需 `--deploy`、容器管理或集群资源生成。

## 服务与完整功能预设

- MySQL 存业务数据，Redis 用于缓存、会话、队列和分布式锁。使用现有环境变量及配置入口，首版常规验收用 MySQL 8.4 和 Redis 8。应用读取运维提供的主机、端口、数据库名和认证参数。默认复用同一部署的 Redis 地址，使用现有应用及环境前缀隔离数据，区分各用途的键空间。
- 新项目缺少 `.env` 时，以项目环境模板为基础写入完整预设值，保留显式环境变量和所提供的连接。对应驱动采用 `DB_CONNECTION=mysql`、`CACHE_STORE=redis`、`SESSION_DRIVER=redis`、`QUEUE_CONNECTION=redis`。已有环境或应用配置与预设冲突时，逐项说明并停止，不自动切库、不转移存量数据。复用现有 `APP_KEY`、应用标识和凭据，必要时通过原命令生成缺失的本地应用密钥；敏感值不进入标准输出、日志或版本控制。
- 把完整功能清单随版本固定。实施前对照当前官方包、Cargo feature、包发现、安装器、依赖和已交付状态，对每项注明安装方式、启用条件和验收入口。现有 `--extensions=all` 仅展开标准清单，完整预设须显式纳入完整用户套件 `full`，并逐项核定其余官方扩展，包括 Webhook 收发的交付状态。内置能力沿用框架默认装配，组合安装使用所属包已提供的正式资源和安装器。
- 支付、短信、邮件和外部登录等需要第三方账号的能力，应安装已交付的代码和配置入口，并显示待配置项。缺少外部账号可以延后启用该驱动。缺失承诺的安装器、必要配置或可用模块属于交付缺口，不能静默跳过。默认本地开发可启动和完成核心流程，外部真实投递、支付及生产公信证书另行验收。

## 实现顺序

1. **入口和计划。** 从现有 `init_command.rs` 抽取两入口共用的选择结果和执行流程，交互命令继续走原向导，完整命令提供固定预设。预检工具链、可写源码、已有配置、安装器、迁移目标以及 MySQL 和 Redis 的可用性。对 Redis 检查相关用途所需权限，探测应短时隔离且有收尾。预检缺项时输出具体修复字段及阶段并非零退出，非交互路径不读取标准输入。`--dry-run` 不写文件、不生成密钥、不构建、不改变服务或数据库。
2. **安装并构建。** 复用 `ExtensionInstallers`、`SourceInstallation`、包发现、源码锁和各包原有发布规则，按依赖发布配置、迁移、路由和应用接线。构建前复查文件状态和冲突。已有安装器可直接调用，缺少编译接线时复用现有引导构建与隐藏的 `init:resources`，资源落地后做最终构建。保持正常 API 前缀及认证守卫语义。默认应用继续按需接入扩展。
3. **迁移并运行自检。** 在已核实的目标 MySQL 库运行正常迁移流程，使用 Redis 锁避免并发迁移，并区分锁竞争和执行完成。保留现有生产迁移授权要求。配置标为生产且需要显式授权时，非交互命令不得绕过保护或等待输入。只在安装与迁移全部完成并验证成功后报告就绪。自检经实际构建产物运行临时 HTTP、独立 Artisan 和 Redis Worker，退出后回收本次自检资源，不常驻托管进程。
4. **重跑与报告。** 从实际文件、Cargo 配置和迁移账本判定完成状态，不另建安装状态库。已完成项复用，缺项补齐。并发安装通过现有源码锁处理。失败按阶段报告并返回非零，保留已有配置、凭据、业务文件、数据库数据及迁移账本。不清数据库或 Redis、不重放已执行迁移、不自动回滚旧批次。输出就绪、待配置、失败和冲突项目，给出当前应用的正常启动入口。

源码接续位置为[现有初始化命令](../../../vendor/openrust-framework/src/foundation/console/init_command.rs)、[共享安装器](../../../vendor/openrust-framework/src/foundation/console/installation.rs)和[应用迁移锁](../../../docs/zh-Hans/database/migrations.md#isolating-migration-execution)。已有历史边界见[初始化验收](../audits/00-03/init.md)和[认证扩展安装验收](../audits/00-03/init-auth.md)。

## 单机和多副本

两种部署使用同一份应用产物、功能清单及配置契约，初始化不选择拓扑。同一部署内 Web、Worker、调度及其他相关进程连接同一套 MySQL 与 Redis。多副本使用相同应用密钥，跨节点文件使用共享存储。部署层控制进程角色、调度协调、迁移的单次执行、负载均衡、证书和外部服务凭据。普通 Redis 可用于应用多副本。Redis Cluster 和真实生产基础设施各按支持范围单独验收。

## 分批实施与完成标准

1. **先闭合命令契约和清单。** 覆盖公开命令、帮助、无终端输入、只读预览、缺配置、服务不可用、现有驱动冲突、生产迁移保护和并发锁。
2. **再闭合单机消费者。** 从干净源码和开发者预先提供的隔离 MySQL 8.4、Redis 8 开始，只执行一次 `./artisan init:full`。以现有入口启动应用，实测首页、注册登录、会话与 Redis 队列。执行前后核对数据和迁移账本。另测已有项目重跑、文件定制保留、构建失败后恢复、迁移失败后恢复及缺少第三方账号的行为。安装命令自身须在无法访问 Docker Compose 的环境也通过。验收基础设施可独立提供服务。
3. **完成多副本与文档。** 用同一应用产物和共享 MySQL、Redis 验证跨副本会话、Worker 消费与失败恢复、迁移并发和调度协调。核对各正式入口、生成产物和真实消费者，记录运行平台。同步三语初始化和部署指南，执行 Rust 1.94.0 格式检查、严格 Clippy、实际命令及文档验收。实际部署域名、外部供应商和发布批准沿用项目发布验收边界。

交付结束应让开发者只需预先提供 MySQL 与 Redis。命令成功后即可通过现有入口启动应用并开始写业务代码，无需手动启用扩展、注册 Provider、调整默认驱动、生成密钥或再跑迁移。
