# 本轮持续开发交接记录

本记录适用于当前 OpenRust 持续开发。通用项目约定见[项目规范](conventions.md)。

## 持续开发停止条件

- 开始新交付单元、大型构建前，以及持续开发过程中定期核对实际额度和项目磁盘空间。额度使用账户工具实际返回的剩余百分比，不以目标 token 计数代替。无法读取时向用户说明并请求当前额度，未知值不视为充足。
- 任一可用额度窗口剩余大于 10% 且小于或等于 25% 时，停止开启新任务和新模块。仅收尾当前交付单元，完成必要验收后按核定范围提交本地 Git，保留在途和未通过验收的改动。提交后停止开发，记录提交号、剩余改动和恢复步骤，等待用户确认恢复。提交前重新核对额度。
- 任一可用额度窗口剩余小于或等于 10% 时，优先执行强制停工。立即停止开发和启动任何新构建、验收或提交，即使当前交付单元尚未收尾。保留工作区和暂存区，记录实测值与停点，等待用户确认恢复。
- 项目磁盘可用空间小于或等于 50 GB 时，停止开启新任务、大型构建及新模块。保存工作、记录已完成内容、未完成项和恢复步骤，汇报实测值，等待用户确认恢复。额度收尾规则不放宽磁盘停线。
- 保留用户及其他代理的改动。暂存、提交和推送仍按用户当次授权。

## 阶段编译缓存清理

每阶段完成验收并记录后，确认没有编译或验收进程使用本阶段目录，再清理已不需要的 Cargo target、隔离副本构建缓存和临时构建目录。保留候选源码、未提交改动、验收记录及必要发布产物。保留其他代理使用中的目录和共享依赖下载缓存，不能确定归属的共享缓存不删除。清理后复查磁盘空间，并在阶段记录中列出范围和结果。

## 当前 Git 授权

2026-11-11 用户已授权：阶段实现、必要验收、三语文档和进度记录完成后，可自主核对并提交该阶段内容到本地 Git，汇报提交哈希和范围。只提交本阶段核定内容，保留其他模块及代理的工作区改动。推送仍需用户另行授权。
