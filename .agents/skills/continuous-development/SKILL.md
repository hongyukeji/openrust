# 持续开发守护

- 结合上下文理解意图，不匹配关键词。已有计划时“持续开发”足以授权；进度查询/补充要求不表示停止；引用该词写文档不启用。目标不明不猜测。仅用于当前项目，不全局安装。
- 首次启用核对约束、任务范围、Git/WIP及在途任务；沿用完整Goal，确获持续执行授权且无目标时才创建。以项目根为工作目录执行 `python3 -B <本skill目录>/scripts/guard.py start --label "简短任务名"`；身份从可信环境读取，不猜最新对话、不为子代理重复登记。当前支持Paseo＋Codex；缺少支持明确报告。
- 首次启动及恢复异常时用 `status` 核实；需看全部任务才用 `list`。不在每轮重复启动、查状态、加载本skill全文、脚本/测试或全部聊天。常规监测由本地脚本每120秒完成，不调用模型；只读最多512KiB日志尾部，无变化复用解析结果。
- AI仅在实际恢复后按当前证据续作：先收取在途结果，避免重复派发、构建、全仓扫描或重做已完成阶段。等待使用已有任务句柄/收件机制，不为定时汇报不断开启模型轮次。短恢复消息沿用原目标；限流/故障退避后转冷却，额度自然恢复后复核，不改模型、账户或付款设置。硬阻塞通知并保留证据，能独立推进的继续。
- 运行记录在 `.agents/project/guards/registry.json` 及任务子目录；目录内`.gitignore`排除状态/日志/PID/锁，不改根忽略规则。根据真实进程、锁与心跳判活，不能只信PID文件或“已派发”。发送结果不明时不重复发送。
- 完整计划及实际验收都满足后，标记原Goal complete，自动运行 `guard.py finish` 并核实守护进程已回收；未完成目标会被拒绝清理。漏调时周期检查仍会自动收尾。单簇完成或模型总结不算整体验收。
- 用户明确停止时运行 `guard.py stop --stop-task`，禁止唤醒、暂停Goal并中断主控；协调停止自己派发的子代理，不碰他人任务/服务。只关守护用`stop`。界面暂停/取消优先，后续新授权才重启。

仅Python标准库，不安装环境或系统服务。worker可自恢复；断电、监督进程被杀、认证/协议故障仍可能需要处理。正常监测不产生模型调用，但实际恢复及继续开发仍消耗原对话上下文/推理token，不承诺零成本或任何故障下永不中断。

修改守护时才读脚本并运行 `python3 -B <本skill目录>/scripts/test_guard.py -v`；测试隔离，不向真实开发对话制造故障。
