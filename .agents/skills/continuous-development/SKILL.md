# 持续开发守护

## 智能判断与自动启用

由 AI 结合当前目标、历史授权、任务范围和最新消息理解意图，而不是匹配固定句式。“持续开发”已可表示继续当前完整计划，无需用户补齐“直到完成”。查询进度、插入问题、补充要求通常是对现有任务的指导，不能误当停止或重复登记授权。真正无法确定目标范围时先推进可确定部分，再澄清关键缺项。

1. 核对当前项目约束、实际计划、Git/WIP与在途任务。检查原生Goal：已有未完成目标沿用；用户授权持续追求当前任务且无目标时创建完整目标，不缩小范围或擅改预算。普通问题和一次性任务不创建Goal。
2. 以当前项目根为工作目录运行 `python3 -B <本skill目录>/scripts/guard.py start --label "简短任务名"`。从可信环境读取实际Paseo/Codex身份；指定另一对话时使用已核实的 `--agent` / `--thread`，不能猜最新对话。已登记则复用，子代理不各自再启动守护。
3. 用 `status` 确认持锁、监督进程和任务身份；`list` 查看当前项目全部守护。智能判断由Agent按实际证据完成，不另开模型轮询对话。先收取在途结果，不因观察超时就重复派发写入者。

本skill仅用于当前项目，确定性运行适配器支持 macOS/Linux 的Paseo＋Codex；不做全局安装，不自动接管其他项目。脚本按当前工作目录核对任务身份。缺少受支持运行器或可信身份时明确报告，不能声称已经守护，也不擅自安装环境或改系统配置。

## 持续推进与可观察性

- 正常开发由原Goal接续；守护默认每120秒检查，仅读日志尾部最多512KiB，不全盘扫描或用模型反复问“完成了吗”。临时故障按退避/冷却恢复；额度自然重置后复核再继续，不买credits、不切账户、不兑换reset。
- 在项目 `.agents/project/guards/registry.json` 记录看板；目录内 `.gitignore` 仅允许忽略文件本身被追踪，不修改根忽略规则。每任务单独记录目标身份、状态、最近心跳、下次检查、进程和异常原因。读取时结合持锁与心跳判断是否真在守护，不能只凭旧PID文件或“已派发”判断正常。硬阻塞本机通知并保留待处理状态；发送结果不明时观察原线程，不盲目重复发送。
- Agent恢复后智能判断：定位实际中断点，核对当前文件、验证和子任务结果，继续未完成且可执行的部分；独立任务继续推进。已经完成的阶段不重复开发，外部缺口不虚报已验收。无进展的重复汇报不算完成，应重新分析实际阻塞。

## 完成、停止与清理

- 核对整个获准任务及验收证据后才把原Goal标为complete。随后自动运行 `guard.py finish`，核实所有本任务守护/协议/CLI进程已回收，PID记录已清理，看板为complete；脚本会拒绝清理尚未完成的目标。即使Agent漏调finish，周期检查也会在看到complete后自动退出清理。
- 用户明确停止时自动运行 `guard.py stop --stop-task`：禁止再唤醒、暂停Goal并中断主控；协调停止自己派发的子代理，核实结果。仅关闭守护而继续开发时使用 `stop`。界面暂停/取消同样优先，不能偷偷恢复。
- 不结束其他Agent、构建或基础服务。保留简短审计状态和空锁inode，释放实际锁；过期记录必须显示未运行/孤立，不能冒充活跃守护。新授权恢复时重新执行start。

只有Python标准库，无全局安装、环境搭建、常驻模型或系统服务。worker可由监督进程恢复；断电、监督进程自身被杀、认证失效及运行器协议变化仍可能需要恢复/修复，不承诺任何故障下永不中断。验收真实性由Agent的实际检查负责，不能拿“模型说完成”或“守护进程活着”替代。

回归入口：`python3 -B <本skill目录>/scripts/test_guard.py -v`。使用临时项目和隔离CLI，不向真实开发对话制造故障或发送测试消息。
