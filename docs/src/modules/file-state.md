# 显式文件状态与启停

需要跨进程保存模块启停时，在部署环境明确选择文件激活器：

```dotenv
MODULES_ACTIVATOR=file
MODULES_STATUSES_FILE=state/modules.json
```

相对状态路径锚定应用运行根，绝对路径保持原值。它独立于模块源码、元数据、已编译 Provider 和文件初始化绑定；切换状态来源不应丢弃这些贡献。不会自动搬迁旧状态文件，部署时应先准备正确路径和权限。

应用提供 `module:list`、`module:enable 名称…`、`module:disable 名称…`。这些命令沿应用完整 bootstrap 执行；坏配置、坏状态或必需服务不可用仍会使命令失败，不能据此绕过启动约束。

`file` 构造时读取状态并保留实例缓存，不跟随其他进程的后续写入。`file-live` 是显式实时读取扩展：

```dotenv
MODULES_ACTIVATOR=file-live
```

两者复用相同状态路径；`file-live` 不是上游默认行为。默认注册模式则不读取或创建状态文件。

文件模式的写入结果、内存启用视图与 `Module::is_loaded()` 是不同状态。自身写前可能先改变缓存；写失败不会伪装成持久化成功，也不保证回滚缓存。启停不会热挂卸当前 Provider、路由或资源，下一应用实例才按新状态加载。依赖状态不自动级联修改。

坏 JSON 不应被普通写操作覆盖，恢复须明确选择重置路径。文件锁和原子替换用于保护写入，但不据此承诺硬链接别名、所有平台或并发 shutdown 的完整原子屏障。
